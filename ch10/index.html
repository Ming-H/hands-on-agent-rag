    第 10 章 ReAct 工具环：白名单 / 步级观测 / 重复收手

    状态：v0.2 · 所属：第三部 Agent 化 · 前置：第 8 章

    10.1 失败先行：自主循环的三种死法

    让小模型在循环里自主决定「检索什么、何时收手」，实测三种死法 （每种都有白盒回放测试钉死）：复读机（同一调用原样重复 6 步）、 幻觉参数（问半年度传 FY）、不收手（证据够了继续烧预算）。

    结论：自主性不是给模型自由，是给模型装护栏。

    10.2 业界视角：从 ReAct 到 function calling

    背景速览

    Agent 工具调用的学术谱系：

    • ReAct（Yao et al. 2022, arXiv:2210.03629）： 推理（Reasoning）与行动（Acting）交织——thought → action → observation 循环，LLM 交替写思考与调用。Tally 的 agent_research 是它的工程化。
    • Toolformer（arXiv:2302.04761）： 模型自学习在哪些位置插 API 调用（训练路线）。
    • Function calling（2023 起各家 API 原生支持：OpenAI tools、 Anthropic tool use）：结构化 JSON 工具调用成为平台能力—— 开发者的战场从「让模型学会调用」移到「调用之后怎么防它闯祸」。

    实践侧，Anthropic 的 Building Effective Agents 给出关键区分：workflow（代码编排 LLM）适合可预测任务， agent（LLM 自己控制循环）留给需要弹性的场景，且必须配 工具与护栏。Tally 的立场是混合：metric/compare 单跳交给 workflow 承重的固定管线，多跳信号才进 agent 环——「自由规划、 强制对账」。

    10.3 工具白名单：封闭世界契约的 Agent 面

    # tally/graph.py（节选）
AGENT_TOOLS = [_SEARCH_TOOL, _METRICS_TOOL, _DERIVE_TOOL]   # 就这三个

def _run_tool(name: str, a: dict) -> str:
    if name == "search":        return run_search(a)
    if name == "metrics_table": return run_metrics_table(a)
    if name == "derive":        return run_derive(a)
    return "[]"      # 注册表白名单外：封闭世界契约第 2 条

    三个工具全是内部动作（检索/取表/算术）。白名单外返回空观测 ——模型看得见「此路不存在」，但走不出去。

    derive（单季差分算子）单独一提：

    # run_derive：Q2=H1−Q1、Q4=FY−Q3，原币精度；操作数行不可解析时返回
# error 对象（模型可见的保守失败），绝不打印错数。结果登记 derived_ops
# ——verify 出口按「操作数必须真在场于证据池」重算 ±0.01

    禁止模型心算——封闭世界里算术也是事实。出口处代码重算差分、 操作数必须在场，派生值才允许 pass。「LLM 组织语言、代码拥有事实」 在算术上的落点。

    10.4 护栏四件套

    # tally/graph.py: agent_research（节选）
seen: dict[str, str] = {}   # 幂等缓存：小模型会把同一调用原样重复 6 步（实测）
...
if key in seen:             # 重复调用：回缓存结果并提示换角度
    msgs.append({"role": "tool",
                 "content": seen[key] + "（重复检索：结果同上。请换检索角度或停止调用工具。）"})
    step.update(gate="dup"); continue
...
if not fresh and pool:      # 整批全是重复 = 模型没有新问题要问
    stopped = "重复收手"
    break
    1. 幂等缓存 + dup 标记：重复调用不烧检索、不进证据池，还提示 模型换角度；
    2. 整批重复即收手：比等步数封顶早止损；
    3. 步数硬上限 MAX_AGENT_STEPS = 6；
    4. 理解先验覆盖工具参数：understand 的期间/公司是「模型对原问题 的结构化决定」，工具参数只是检索战术——参数幻觉被先验拦下。

    10.5 步级观测：waste_rate 是 eₖ 的代理

    每步记录四元组 {thought, action, obs(条数+首doc), gate(new/dup/empty)} + 耗时；-v 逐行、--json 可重放；eval 聚合出 waste_rate = (dup+empty)/calls——可靠性公理里 eₖ（步错率）的 可测代理（第 13 章讲全）。观测先行的意义：没有这四个字段，「小模型 在循环里表现如何」只能靠感觉争论；有了它，「重复率 30%」是一个 可以盯着的数字。这也是业界 LLM observability（trace/span 体系）在 本项目的最小实现。

    10.6 案例：远端 function calling 的接通（v0.7.1）

    本书写作时远端通道曾没有 ReAct（显式 NotImplementedError → 兜底固定管线，DESIGN-v0.7 §8 记录了 8/8 agent:fallback 的实测）—— 这曾是留给读者的 v1.1 挑战题，作者自己先交了卷，过程值得复盘：

    1. 消息规范化是主要工作：agent 环喂的宽松格式（assistant 的 tool_calls 只有 function{name,arguments}、tool 消息无 id）要转成 OpenAI 协议要求的 id+type+tool_call_id——按会话位置确定性 编号（call_1..call_N），每个请求自洽即可，且不就地污染入参 （本地通道继续用宽松格式）；
    2. 归一化契约不变：远端返回同样归一为 {content, tool_calls:[{name, arguments:dict}]}，arguments 兼容 SDK 的 JSON 字符串形态——上层 agent 环零改动；
    3. Anthropic 通道仍显式失败（tool_use 块协议不同）——显式失败 优于半成品协议转换；
    4. 实测回报（智谱 glm-5.3，agent 集 8 题）：22 次工具调用、 dup=0（强档位不复读——0.8b 的幂等缓存护栏在此档位未触发）、 waste_rate 0.227（全来自 empty）、两道 compare 题 degraded （cov≈0.44）→ 降级抽取式仍全对——闸门在真实远端生成路径上的 实弹工作证明。全表见 DESIGN-v0.7 §8.3。

    你的 v1.1 挑战题换成了：接通 Anthropic 通道的 tool_use 块—— 协议差异（content 块数组 vs 字符串）比 OpenAI 兼容路更有嚼劲。
