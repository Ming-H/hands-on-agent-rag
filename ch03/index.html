    第 3 章 切分：表格感知分块——毁掉证据的 N 种方式

    状态：v0.2 · 所属：第一部 知识入库 · 前置：第 2 章

    3.1 失败先行：亲手毁掉一份财报

    全书最疼的实验（以下为 2026-10-22 实测数字）。把 tally/ingest.py 的 _is_table_line 改成第一行 return False，重建库跑评测：

    # 表格感知关闭（临时），重建 /tmp 库摄取 samples + 中际旭创双语料
TALLY_DB=/tmp/ch03.db python -m tally.cli ingest samples/
TALLY_DB=/tmp/ch03.db python -m tally.cli ingest data/中际旭创
TALLY_DB=/tmp/ch03.db python -m tally.cli eval --mode heuristic --dataset innolight
    语料 块数 answer_hit retrieval@3
    samples（叙述型预告）基线 → 关闭 310 → 76 1.0 → 1.0 1.0
    innolight（表格重）基线 → 关闭 7,873+ → 4,075 1.0 → 0.778 1.0 → 0.963

    两个结果都是课：①叙述型语料根本不靠表格感知——业绩预告的事实 住在句子里，关掉只少了块数不伤指标；②表格重语料（年报/季报的 「主要会计数据」表）31 题掉 7 题，--min-hit 1.0 门槛当场非零退出。 毁伤面取决于语料形态——这比「切分很重要」的空话诚实得多。 （实验后 git checkout tally/ingest.py 还原。）

    3.2 业界视角：切分方法全景

    背景速览

    切分（chunking）是 RAG 里被讨论最多的低层决策，业界谱系：

    方法 代表实现 思路 软肋
    固定长度 朴素 token 切分 简单、可并行 拦腰斩断语义单元
    递归分隔 LangChain RecursiveCharacterTextSplitter 段落→句子→字符逐级回退 仍不识表格结构
    句子/语义窗口 LlamaIndex SentenceSplitter、语义分块（Kamradt） 按句/按嵌入相似度断点 表格行≠句子
    版面感知 Unstructured chunk_by_title 按标题/布局聚块 依赖上游版面分析
    命题级 Dense X Retrieval 一句一命题 块数爆炸、丢上下文
    迟到切分 Late Chunking（arXiv:2409.04701） 先嵌入整文再切 需长上下文嵌入模型

    经验参数：主流实践落在 256–1024 token、overlap 10–20%——但这些 数字全部来自叙事文本的直觉。财报是表格型文档：42% 的 内容住在表格里，而表格行的语义单位是「行」（标签+数值+同比）， 不是 512 个字符。选切分方法的第一问永远是：这个语料的语义 单元是什么？

    3.3 为什么：毁证据的三种死法

    营业收入 520,053,589.94  345,593,109.95  50.48%

    固定 512 字符边界切这行的三种死法：指标名与数值分家（销毁证据）； 同行三数分进两块（本期与同比分离）；切在千分位逗号后（520, 和 053,589.94 各自不可读）。Tally 全库实测：42.1% 的块是完整表格 块——毁掉它们，检索层再好也答不对。

    3.4 决策：逐行分类聚簇（6 行启发式）

    三个备选的取舍：①固定长度（毁表格）；②语义模型切分（贵、慢、 不可控——切分是离线高频操作）；③逐行分类聚簇（本文）。核心是 表格行判定（数字密集 + 无句末标点 + 短行），连续表格行聚成 原子块永不跨切；配套 keep_block 过滤纯列头块（「项目 2026年 半年度」——无数字的列头是检索噪声）；正文按段落边界切 ~420 字。

    还有一个容易被忽略的细节：数字归一化注释：

    _NUM_RE = re.compile(r"([1-9]\d{0,2}(?:,\d{3})+(?:\.\d+)?)\s*(亿元|万元|元)")
# 41,914.72 万元 → ≈4.19亿（纯程序换算，零幻觉；每块至多 6 条防噪）

    用户问「多少亿」、原文写「41,914.72 万元」——词面零重叠。注释在 下游打分加权（answer.py 的 1.4×/0.2 权重）接上亿级问法。它是程序 换算的字符串，不是 embedding——各司其职。

    3.5 已知边界：这门课不装完美

    超长表格（>840 字）切块后后块丢表头——列头在第一块，后几块是 裸数字行，命中后模型读不懂「第三列是什么」。这个坑 Tally 知道、 没修、写进了边界账本（第 13 章）。教学点：工程教程最值钱的 部分是「知道哪里没修好」。

    3.6 动手实验（还原后）

    sqlite3 tally.db "SELECT chunk_id, is_table, substr(text,1,40)
  FROM chunks WHERE doc_id='海伦哲_2026Q1' AND is_table=1 LIMIT 5"
# chunk_id 连号（p3#4、p3#5…）= 同一表格的连续行聚簇

python -m tally.cli ask "海伦哲 2026 年第一季度营业收入多少"

    习题

    2. 把 keep_block 的「≥3 位数字」阈值改成「含 % 或小数」，跑 eval——两位数百分比表格会被救回吗？
