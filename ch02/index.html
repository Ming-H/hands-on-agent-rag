    第 2 章 PDF → 大模型可读的内容

    状态：v0.2 · 所属：第一部 知识入库 · 前置：第 1 章

    2.1 失败先行：一个垃圾文件名的通关之旅

    把 samples 里任一文件复制一份，改成 20261009_某公司三季预告分析.md 这种日期开头的名字，再摄取——收到 ⚠ 拒收。这不是 bug，是 P0.5 轮 实测换来的闸门：主干是纯数字的文件名，曾真的产出过 20261009_MD 这样的垃圾 doc_id，进了库就污染检索和引用。

    垃圾进、垃圾出。摄取层第一课：元数据必须有确定性来源，绝不靠 模型猜。

    2.2 业界视角：PDF 解析的工具谱系

    背景速览

    「PDF → 文本」这件事，业界的工具分三代：

    代 代表 原理 适用
    文本层抽取 pypdf、PyMuPDF 读 PDF 内嵌文本流 数字原生的 PDF（本教程语料）
    版面感知 Unstructured.io、pdfplumber 视觉布局分区（栏/表/题注） 混排文档
    模型驱动 Marker、MinerU、GROB 视觉模型/OCR 重建结构 扫描件、复杂表格

    经验法则：能用文本层就别上版面分析，能上版面分析就别上模型—— 每升一代，成本、延迟和不确定性各加一层。Tally 用 pypdf（文本层） + 表格感知分块（第 3 章）覆盖了数字原生财报；扫描件显式拒收 （2.5 节）而不是硬上 OCR——封闭世界里，不可靠的输入不如没有输入。

    延伸：LlamaIndex 的 readers 生态把 各类解析器统一成接口；中文财报场景可关注 MinerU 的开源实现。

    2.3 决策：文件名即元数据契约

    Tally 认三类文件名（tally/ingest.py: parse_filename）：

    # 研报：20260703-东吴证券-并行科技-920493-标题.pdf → (券商, 日期, 研报)
_REPORT_PAT = re.compile(r"^(\d{8})-([^-]+)-(.+)\.pdf$")

_PERIOD_PAT = [                                    # 文件名 → (period, kind)
    (re.compile(r"(\d{4})年年度报告"), "FY"),
    (re.compile(r"(\d{4})年半年度报告"), "H1"),
    (re.compile(r"(\d{4})年第一季度报告"), "Q1"),
    ...
]
    # 兜底：主干必须是可读公司名（含 CJK）——日期开头的外部分析
    # 静默入库会产出 20261009_MD 这类垃圾 doc_id（污染检索与引用）；
    # 拒收让 cli 以 ⚠ 跳过（P0.5 实测库内留过一具）
    company = re.split(r"[__－-]", name)[0]
    if not re.search(r"[一-鿿]", company):
        raise ValueError(f"文件名解析不出公司名（主干={company!r}），拒收")

    为什么不用 LLM 从正文猜公司名和期间？业界确实有人这么做（甚至 「让模型给每份文档打标签」），三个理由反对：①确定性——同一 文件永远解析出同一 doc_id，增量摄取的幂等性依赖它；②零成本零 延迟——摄取是高频操作；③猜错了你不知道——文件名错了至少 报错可见，模型猜错是静默的。这与业界 metadata 注入的最佳实践同向： 元数据来自可信信号（文件名/路径/数据库字段），LLM 只处理内容。

    2.4 页眉剥离：一行空格打败逐字比对

    PDF 抽取的正文页页带着「公司名 + 报告标题」。Tally 做文档级频率 统计：同一行（归一化后）在超过 30% 的页出现即判页眉。关键坑在 归一化——P2 事故实录：

    PDF 文本抽取的空格位置逐页漂移（2026年 vs 2026 年），逐字相同 的判定失效。修复：比对前 re.sub(r"\s+", "", ln) 剥尽空白，且把 数字也剥掉（页眉带着页码，「第 3 页」「第 4 页」不剥就页页不同）。

    通用教训：文本相等性判定，永远先定义归一化。

    2.5 空文档闸门：扫描版 PDF 的静默失败

    一份 232 页全扫描件（pypdf 抽不出文本）会怎样？每页因「长度 < 20」 被跳过，ingest_file 返回 0 个 chunk——修前：空文档「成功」入库， manifest 记下指纹，以后每次增量都跳过（指纹没变），库里永远躺着 一具问答永空手的空壳。修复是一行闸门：

        if not chunks:
        # 空文档闸门：0 块文档静默入库后 manifest 指纹锁死、永不重试
        raise ValueError(f"{path} 摄取出 0 块——疑似扫描版 PDF 或空文档，拒收")

    失败方式的选择也是设计：显式抛错走 ⚠ 报告链路，而不是入库一个 「空」标记——前者用户可见可修（去 OCR），后者是静默债务。

    2.6 增量指纹：从 mtime 到内容哈希

    # tally/source.py
def _fingerprint(p: Path) -> str:
    """内容哈希指纹（流式读，1MB 块）——只看内容，与 mtime/ctime 无关。"""
    h = hashlib.sha256()
    with open(p, "rb") as fh:
        for block in iter(lambda: fh.read(1 << 20), b""):
            h.update(block)
    return f"sha256:{h.hexdigest()[:24]}"

    初版 mtime_ns-size（轻量）有两个洞：cp -p/rsync -a 保 mtime 改内容漏更新（语料静默过期答旧数）；touch 假更新。内容 哈希双洞堵死，成本 36MB 语料约 0.1s。业界同构物：Airbyte/LlamaIndex 目录连接器的 path→fingerprint 账本——增量摄取的幂等性永远建立在 「文件身份」的可信判定上。

    2.7 动手实验

    # ① 拒收演示
cp samples/海伦哲_2026年第一季度报告.pdf samples/20261009_test.pdf
python -m tally.cli ingest samples/   # 观察 ⚠（PDF 主干是日期）
rm samples/20261009_test.pdf

# ② 空文档闸门：空白 PDF
python -c "from pypdf import PdfWriter; w=PdfWriter();
[w.add_blank_page(width=595,height=842) for _ in range(3)];
w.write('/tmp/空壳公司_2025年年度报告.pdf')"
cp /tmp/空壳公司_2025年年度报告.pdf samples/ && python -m tally.cli ingest samples/

# ③ 幂等：连跑两次，第二次 0 新增 0 更新
python -m tally.cli ingest samples/ && python -m tally.cli ingest samples/
