    第 11 章 Planner 与 Memory：只删不造 / 三层记忆

    状态：v0.2 · 所属：第三部 Agent 化 · 前置：第 10 章

    11.1 失败先行：规划器的两种输出事故

    多跳问题（「对比 A、B、C 三家 2025 与 2026 的营收和净利」）先让 LLM 出子目标清单，实测它自然产出两类东西：白名单外的动作 （browse、裸 calculate）和语料里不存在的公司。校验哲学由此 定调：只删不造（_validate_plan）——白名单外动作丢弃、期间 规约枚举、去重、封顶 MAX_SUBGOALS=5、单公司回填；校验失败整体 回退 agent 环（现路径，不冒险）。

    11.2 业界视角：规划与记忆的谱系

    背景速览

    规划：让 LLM 先拆解再执行的代表——Plan-and-Solve（ arXiv:2305.04091）把 「let's think step by step」升级为显式计划；LangGraph 的 Plan-and-Execute 模式（官方 how-to） 把 planner 与 executor 分离成节点。Tally 的差异化在校验： 计划不是拿到就用，过一遍确定性白名单——「LLM 出灵感、代码 裁合法性」。

    记忆：业界三家代表 + Tally 的取法——

    系统 核心思想 Tally 取什么
    MemGPT（→ Letta） OS 式内存分页，LLM 自管理上下文 分层思想（热/冷分层）
    Mem0 抽取-合并的事实记忆，冲突解析 事实级合并算子（noop/conflict/supersede）
    Zep 时序知识图谱，事件序列 时效性意识（语料指纹失效）
    Tally 三层 L0 会话 / L1 台账 / L2 资产 ——

    与通用记忆系统的根本分野：Tally 的记忆只存结构化、已过闸的 事实（下文），不存对话向量、不存自由文本——封闭世界契约的 记忆版。

    11.3 检查点与「未覆盖」红线

    每个子目标执行后过检查点（_ckpt_ok：财报级数字在场 ∧ 指标词 命中），不过有界重试 ×1，再不过显式弃——弃掉的进 plan_gaps， verify 出口追加声明：

    # tally/graph.py: verify_citations（节选）
gaps = [g for g in (state.get("plan_gaps") or []) if g]
if gaps:
    out["answer"] = (f"{out.get('answer', '').rstrip()}\n（未覆盖："
                     + "；".join(gaps) + "——检索不足，以上为已覆盖部分）")

    部分答案不硬凑——宁可明说「C 公司的净利没找到」。这是 verify 精神在多跳场景的延伸：不编事实，也不编完整性。

    11.4 Memory 三层：每层回答一个「凭什么信」

    层 是什么 凭什么信
    L0 会话 轮摘要继承（公司/期间/年份/指标词） 永不继承自由文本——只继承结构化理解字段，切断叙述传播边
    L1 台账 verified_facts 表（公司+期间+指标+口径 键） 写闸严于读闸；读不豁免
    L2 资产 alias 词典等检索导航知识 人工维护 + eval 全绿才晋升；非答案事实 
    # tally/graph.py: _memory_write（写闸节选）
tr = "→".join(state.get("trace") or [])
if any(bad in tr for bad in ("caliber-mismatch", "fallback(",
                             "no-evidence", "derived-mismatch")):
    return []          # 口径闸触发过的一律不写——D22 闸保「数字在场」，
                       # 写闸要的是「行也对」

    写闸 = verify:pass ∧ 口径闸未触发。读不豁免更关键： memory_probe 命中拼出的答案照样内联过 verify（缓存证据不缓存 结论）——投毒测试为证：往台账写假事实 （test_poisoned_fact_read_not_exempt），读路径的 verify 把它拦下。 记忆是加速器，不是后门。失效机制：语料指纹漂移 → 自动 supersede ——记忆的生命周期跟着证据走。

    11.5 eₖ·gₖ 视角（先埋个钩子）

    三层共享同一直觉：长链的失败不该按 pⁿ 复利。L0 不继承自由 文本 = 剪断「叙述错误」的传播边；L1 结构化键 + 读不豁免 = 错误事实 要么进不来（写闸）、要么出不去（verify）。结构化传递的本质是 「字段复制，不文本重释」。第 13 章把这写成公理。

    11.6 动手实验（2026-10-22 实测修正）

    # ① 常态 ask 看 L1 在工作（trace 出现 memory:hit）
python -m tally.cli ask "海伦哲2026年一季度营业收入多少" --mode heuristic -v

# ② eval 默认隔离台账 vs 放开（TALLY_EVAL_MEMORY=on）
python -m tally.cli eval --mode heuristic --dataset multiturn
TALLY_EVAL_MEMORY=on python -m tally.cli eval --mode heuristic --dataset multiturn
# 实测：answer_hit 两次都是 1.0（不变！），citation_coverage 0.941→0.736（部分题走台账命中）

# ③ Planner 检查点与「未覆盖」（llm 模式）
python -m tally.cli eval --mode llm --dataset multihop -v 2>&1 | grep -E "plan|未覆盖"

    ②的反直觉结果是本章最重要的一课（作者亲踩后才写对）：想用 「eval 外面设 TALLY_MEMORY=off 做对照」根本不生效——evalx 内部 默认强制隔离（除非 TALLY_EVAL_MEMORY=on）。而放开后台账命中 answer_hit 不变：命中的是同一个已过闸事实，读不豁免、照样 过 verify——指标不变正是「读不豁免」的设计结果。记忆的可见差异 在 trace（memory:hit）、coverage 分布与延迟，不在答案对错。 这也解释了 eval 默认隔离的动机：防止检索指标被记忆命中测虚高。

    习题

    1. 解读 test_poisoned_fact_read_not_exempt：若读路径豁免 verify， 一个 bug 怎样把假事实注入所有后续回答？
    2. 思考题：为什么 L0 只继承 understanding 字段而不继承「上一轮答案 的数字」？（答案数字的权威来源永远是谁？）
