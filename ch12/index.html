    第 12 章 评测即测试：真值集 / 陷阱题 / CI 门槛

    状态：v0.2 · 所属：第四部 诚实 · 前置：第 8、9 章

    12.1 失败先行：装饰性 CI 的解剖

    本项目自己踩过的坑：CI 里跑了三个真值集 eval，看起来很严格—— 直到有人问「指标跌到 0.3，CI 会红吗？」不会：cmd_eval 只打印， 永远 exit 0。CI 从「只防崩溃」到「防退化」，差一个非零退出码：

    # tally/cli.py: cmd_eval（修复后节选）
if any(v is not None for v in mins.values()):
    fails = gate_failures(summary, **mins)
    if fails:
        print(f"✗ eval 门槛未过（dataset={args.dataset}）：\n  " + "\n  ".join(fails),
              file=sys.stderr)
        sys.exit(1)

    .github/workflows/ci.yml 四处 eval 全挂 --min-retrieval 1.0 --min-hit 1.0。门槛通电当天就抓到一次真实回归（12.2 的 0.963）。

    12.2 业界视角：RAG 评测的三代方法

    背景速览

    代 方法 代表 取舍
    人工/规则 关键词、精确匹配 传统 IR 的 P/R 零成本、可解释；覆盖窄
    框架指标 检索/生成/忠实分项 RAGAS（faithfulness、context precision/recall）、TruLens 全面；依赖 LLM 裁判，有方差
    领域真值集 人工核对答案 + CI 门槛 Tally 84 题 / 业务团队的 golden set 最可信；搭建成本高

    Hamel Husain 的名文 Your AI Product Needs Evals （作者博客汇总见 hamel.dev）主张： 领域专属的评测集 + 错误分析驱动迭代，比通用基准重要得多—— Tally 的 84 题（真值核对到分位）就是这个主张的实践。通用框架 不是不用：RAGAS 的指标定义值得抄（Tally 的 citation_coverage 与其 faithfulness 同源不同实现）；LLM-as-judge 有方差，本项目 只在 trend 叙述层用且非对称信任（只能否决，不能解锁）。

    12.3 judge 的演进史：一学期踩完的坑

    v1：OR 子串。 any(k in answer)——"3.6" 能以子串命中任何 13.68。评测在说谎。

    v2：左右都禁数字粘连。 堵假命中——innolight 掉到 0.963， 门槛当场红。定位：关键词 51.7，答案 51.71 亿元——数据集 约定是前缀截断（38,239 对 38,239,935,640），右边界一禁误杀 过半真值题。

    v3（现状）：只守左边界。 假命中实测全在左侧粘连；右侧延续 恰是截断约定：

    # tally/evalx.py: _kw_in
if re.search(r"\d", kw):
    return re.search(rf"(?<!\d){re.escape(kw)}", answer) is not None
return kw in answer

    教学价值超过规则本身：没有门槛的评测，你连自己的量尺坏了都 不知道。

    12.4 评测集设计的四个要素

    1. 真值纪律：关键词是人工核对到分位的原文数字，不是「大概对」；
    2. 陷阱题（expect_refused）：期间外（2030）、域外（天气）、 语义陷阱（「预计…多少」非趋势）——拒答正确率是一等指标；
    3. 反向断言（forbid_keywords）：第 9 章的口径负向断言；
    4. N/A 的诚实：无陷阱集的 refusal 记 None 不记 0——「不适用」 和「零分」是两回事。

    指标口径名实相符：faithfulness → citation_coverage（它测引用对账， 不是语义忠实——名字吹的牛会被 RAGAS 用户一眼拆穿）。

    12.5 动手实验：门槛通电（实测）

    亲手触发一次 CI 红灯。注意一个坑（本节作者亲踩）：第一题的 expect_keywords 是 OR 语义的四 个备选（36,000 / 42,000 / 4.19亿 / 3.6）——只改坏其中一个，其余三个照样命中，门槛纹丝不动。要触发 必须报废整组关键词：

    python - <<'EOF'
import json
from pathlib import Path
p = Path("evals/dataset.json")
data = json.loads(p.read_text())
data[0]["expect_keywords"] = ["__被改坏的真值__"]   # 第一题整组报废
p.write_text(json.dumps(data, ensure_ascii=False, indent=2) + "\n")
EOF
python -m tally.cli eval --mode heuristic --dataset default --min-hit 1.0
echo "exit=$?"     # 实测：1

    实测输出（2026-10-22）：

    ✗ eval 门槛未过（dataset=default）：
  answer_hit=0.875 < 1.0
  ✗ 欧科亿 2026 年半年度预计净利润多少   top1=欧科亿_2026H1E  kw=N doc=Y refused=N
exit=1

    改坏一道题 → 指标掉到 0.875 → 非零退出 + 指名道姓列出失败题。 git checkout evals/dataset.json 还原后 exit=0。这个「单毁一个 备选关键词无效」的坑本身就是 12.3 judge OR 语义的现场复习。

    习题

    1. 给你业务里的一个问题写 expect_keywords + forbid_keywords 对， 验证 forbid 的必要性（删掉防线后 forbid 的数真会出现吗）。
    2. 设计一道新陷阱题（提示：业绩预告是区间值——能当单值答案吗？ 查 metric_rows 对 E 后缀期间的处理）。
