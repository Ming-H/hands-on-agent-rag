## 14.1 知识：错误传播——错的不是链长，是传播结构

长链任务的可靠性不取决于单步多聪明。朴素模型假设错误**独立
传播**：单步出错率 5%，20 步成功率 0.95²⁰ ≈ 64%——三分之一强的
任务失败。治理思路不是把每步做到 99.99%（模型档位买不起），
而是改**传播结构**：

```
P(错误答案) ≤ Σₖ eₖ·gₖ
  eₖ = 第 k 步出错率（模型决定）
  gₖ = 错误穿过第 k 步闸门的存活率（代码决定）

e=5%、g=2%、20 步 → ≤2%；且失败形态 = 降级/拒答（安全失败）
```

直觉：错误要**穿过闸门才算数**——每步错误率乘以它穿过该步
闸门的存活率。四个杠杆，全书各兑现一个：

| 杠杆 | 一句话 | 兑现处 |
|---|---|---|
| ① 能确定化的环节不给模型 | 模型做不了的确定性收走 | 确定性遍历（第 9 章）、算术出口重算（第 7/11 章）|
| ② verify-as-you-go | 拦截推进到步级 | 子目标检查点（第 10 章）、唯一出口闸（第 7 章）|
| ③ 结构化传递 | 字段复制，不文本重释 | 会话继承/台账键值（第 12 章）|
| ④ 并行分支不乘法 | 分解后各自过闸再合并 | 按公司分解（第 9–10 章）|

**失效条件（相关性警告）**：闸门与模型犯**同一类系统性错误**时，
gₖ 不再独立于 eₖ，界失效——这就是双路径回归（规则模式 vs LLM
模式）+ 双档验收的深层理由：不是冗余，是**相关性探测**。

学界两份同构作业：**MAST**（[*Why Do Multi-Agent LLM Systems
Fail?*](https://arxiv.org/abs/2503.13657)，UC Berkeley 2025）挖掘
真实失败轨迹归纳出 14 类失败模式三大类（规格缺陷/单 agent 行为
失当/agent 间失配）——拿它当自查表，四杠杆就是对清单的逐类
釜底抽薪；**SAUP**（[ACL 2025](https://arxiv.org/abs/2412.01033)）
证明不确定度必须沿轨迹**逐级传播**观测、不能等终点裁决——
verify-as-you-go 与步级浪费率的理论背书。工程界的同构思想更老：
微服务的 fallback/circuit-breaker（降级产物仍满足不变量）、
Google SRE 的 postmortem 制度（[SRE Book](
https://sre.google/sre-book/postmortem-culture/)——不指责个人、
写清根因、行动项进跟踪）。

**安全失败通则**：拒答/降级/显式缺口，都好过沉默错——失败形态
本身是接口的一部分。**度量先行**：没有数字的可靠性是玄学——
浪费率是 eₖ 的可测代理，verdict 分布是 gₖ 的出口读数。

## 14.2 知识：组装次序论与生产 harness 的下一层

**为什么 RAG 先行、自主最后**——组装次序本身是设计决策：

```text
检索/存储地基 → 固定管线全绿（闸门/确定性遍历/评测）
→ 叙述层引入 LLM（骨架先硬，叙述才敢交给模型）
→ 四支柱（规划/记忆/工具/循环）
```

反过来装（先 agent 后闸门）会发生什么：自主循环的每种死法没有
浪费率可观测、没有出口闸兜底、没有确定性基线可对照——在没有
地基的地上盖楼，每个「智能」都不可复现。Anthropic 的建议
（从最简单能工作的结构开始、按评估增量放权）的另一种说法：
**自主性是买来的，付的货币是闸门和评测**。

**从教程系统到公司 harness**。LangChain 的生产实践（
[company harness 五组件](
https://www.langchain.com/blog/components-building-company-harness)）
是本书之上的下一层，逐条对照：

| 生产组件 | 本书已造 | 差距（附录 G 清单）|
|---|---|---|
| 驻留现场（Slack 等）| CLI | 服务化 + 接入 IM |
| 身份代行（OBO）| —— | 权限模型、工具级身份 |
| 分层记忆（global/user）| 三层记忆（单作用域）| 作用域隔离与权限 |
| 沙箱执行 | 封闭世界（无代码执行）| 需要执行时的沙箱 |
| 定时运行 | `--watch` 轮询 | 调度器 + ambient 触发 |

地基（检索/验证/记忆治理/评测）在五组件之下全部复用——这正是
harness 立论的验证：**模型会换，挽具沉淀**。

## 14.3 案例研究：Tally 的总装走读与边界账本

!!! note "案例研究：Tally（graph.py 全链）"

    **一条真实多跳 query 的 trace**（llm 模式，远端 glm-5.3，
    v0.7.1 实测）：

    ```text
    trace: start(3140ms) → mode:llm → understand:llm(5352ms)
         → memory_probe:miss → route:compare(4ms) → decompose:海伦哲|欧科亿
         → agent:2步/2次tool/10块证据/self(8686ms)
         → generate:llm → verify:pass(0.658)   总耗时 24.2s
    ```

    逐行对账 14 个模块各出现一次（第 1 章结构图的运行时版）：
    离线层（指纹/契约/切分/索引）的红利在线上兑现——文件名契约
    是期间守卫的根据，表格保全决定工具检索有没有真值可捞。版本
    史印证 14.2：v0.4–0.5 检索地基 → v0.6 固定管线全绿 → v0.6.5
    叙述层 → v0.7 四支柱 → v0.7.1 远端接通。

    **边界账本**（DESIGN-v0.6 §9，主动写下的「管不住」）：口径
    镜像（问扣非答归母仍可能 pass——两个数都在池里）、compare
    撞上限（结论句覆盖率虚高仍 pass）、每股收益断词（标签被 PDF
    抽碎）。三道题今天仍会错，写下来、配了越界样本实验——
    **边界账本比全绿可信**。

    **公理的一张实测快照**（远端 8 题）：22 次工具调用 5 次 empty
    （eₖ 可见）、2 例被 0.45 阈值拦成 degraded 仍全对（gₖ 可见）
    ——公理的每个字母对应一笔可观测的账。

## 14.4 毕业设计：换语料，造你自己的挽具

（法律判决书/医疗指南/内部 wiki/药品说明书）：

1. **画布走完 14 格**（附录 F）：每格是一章的迁移版决策——

3. **跑出三态出口**：至少一次诚实的 degraded 与一次诚实的

**画布就是全书的目录反转**。

## 14.5 结业：harness 是产品

三条带走的东西：①**对账思想**——LLM 组织语言，确定性代码拥有
事实；②**实测文化**——每个决策一张表、每次失败一条测试、每条
护栏一个事故存档；③**边界诚实**——主动写下管不住什么，它比
全绿可信。

最后一条论点送给毕业后的你：**harness 是产品——模型会换，挽具
沉淀。**你造的 14 个模块里，没有一个的寿命短于当前最强的模型
档位；换三次脑，闸门一行不改。行业每季度重写「怎么调用模型」
的教程，而「怎么让答案可靠地出门」的这套结构正在成为下一代
系统的地基——你手里已经有了。

## 常见误区

**误区一：「可靠性 = 多写测试」。**测试锁已知失败模式；可靠性
设计改变**未知失败的传播结构**。第 13 章的门槛是测试的事，
本章的公理是结构的事，互补不互替。

**误区二：「边界账本是示弱」。**能精确说出管不住什么，证明你
度量过、思考过失败面。全绿的演示随时可以被一道题戳穿；边界
账本的每一条都是已管理着的风险。

**误区三：「教程系统离生产很远」。**差的是五组件那一层（服务
化/身份/调度），不是地基——检索、验证、记忆治理、评测全部
复用。附录 G 是逐条清单。
