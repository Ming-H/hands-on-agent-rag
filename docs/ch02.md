## 2.1 知识：解析为什么难——三代工具与选型法则

**PDF 是页面描述格式，不是文档格式。**PDF 内部是「把字符画在某个
坐标上」的指令流——没有段落、没有表格、没有阅读顺序这些语义单位。
所以「解析 PDF」的实质是**从视觉布局重建文档结构**，日常翻车形态：
同一行被拆成两个 text run、双栏文档被抽成交错行、表格被拍平成
数字流。解析质量是全链路的天花板——后面切分、检索、生成再好，
解析丢了的信息回不来。

业界工具分三代：

| 代 | 代表 | 原理 | 适用 | 代价 |
|---|---|---|---|---|
| 文本层抽取 | pypdf、PyMuPDF、pdfplumber | 读内嵌文本流+坐标 | 数字原生的 PDF | 表格结构丢失 |
| 版面感知 | [Docling](https://github.com/DS4SD/docling)、[Unstructured](https://unstructured.io) | 视觉布局分区（栏/表/题注）| 混排文档 | 慢一个量级 |
| 模型驱动 | [LlamaParse](https://cloud.llamaindex.ai/parse)、[MinerU](https://github.com/opendatalab/MinerU)、Marker | 视觉模型/OCR 重建结构 | 扫描件、复杂表格 | 最贵、有幻觉面 |

两个代表系统的取舍值得对照：**Unstructured** 走「分区-分类-重组」
的确定性管线，输出统一的 element 模型，代价是版面规则要覆盖各种
排版；**LlamaParse/MinerU** 用视觉模型直接预测结构，对复杂表格更
强，代价是引入模型自身的错误面——识别错的数字比没有数字更危险。

选型法则：**能用文本层就别上版面分析，能上版面分析就别上模型**。
每升一代，成本、延迟和不确定性各加一层；而摄取是离线高频操作，
不确定性会被索引放大。配套决策：解析不了输入（扫描件无文本层）
时，在数字敏感场景**显式拒收**优于硬上 OCR——OCR 的错误面（8/O、
千分位逗号）正好打在最痛的地方。

## 2.2 知识：元数据两筐——谁产出，错了会怎样

摄取层最重要的产出不是正文，是**元数据**。分两筐治理：

| 筐 | 例子 | 该由谁产 | 错了会怎样 |
|---|---|---|---|
| 身份字段（主键类）| 主体、期间、doc_id、来源路径 | **确定性来源**（文件名/路径/数据库字段的契约解析）| 系统性错位——增量幂等、过滤、记忆失效全崩 |
| 富语义字段（加速类）| 摘要、标签、别名、类别 | 可用 LLM（低频、容错高）| 降级——检索少一条路而已 |

判断口诀：**这条元数据错了，是降级还是系统性错位？后者永远别给
模型。**「同一文件永远得到同一身份」是增量幂等的前提——LLM 对
同一文件两次抽取可能不同，身份就漂了。业界同构：数据管道工具
（Airbyte、LlamaIndex 目录连接器）都用 path→fingerprint 的确定性
账本管理文件身份，从不让模型参与。

## 2.3 知识：幂等摄取与显式失败

**增量摄取的正确性问题**：语料会变（新增/修改/删除），摄取怎么
知道哪些文件要重处理？两种指纹方案：

| 方案 | 原理 | 失败形态 |
|---|---|---|
| mtime+size | 文件元信息比对，零 IO | `cp -p`/`rsync -a` 保时间戳改内容 → **漏更新**（语料静默过期）；`touch` → 假更新 |
| 内容哈希（SHA-256）| 读全文件算指纹 | 略慢（流式读可控）；唯一能同时堵两个洞的方案 |

**幂等**（同一状态摄取 N 次结果一致）是底线要求；增量 = 幂等 +
三向 diff（add/update/delete）+ **删除的作用域限定**（多来源共存
一库时，一次扫描只对本次扫描根负责，否则 A 目录的同步会误删 B
目录的文档）。

**失败方式的选择也是设计**。摄取层最危险的失败不是崩溃（崩溃会
被发现），是**静默成功**：空内容文档「成功入库」、垃圾元数据
「成功关联」——没有报错、占据语料、永不重试。原则：**失败要贵、
要可见**——显式抛错（用户可见可修）优于入库「空」标记（静默
债务）。这与第 1 章三态出口同构：摄取层的 refused。

## 2.4 案例研究：Tally 的摄取层

!!! note "案例研究：Tally（ingest.py / source.py）"

    **元数据契约 = 文件名。**巨潮资讯网的财报命名天然带结构
    （`公司名_2026年半年度报告.pdf`，券商研报 `日期-券商-公司.pdf`），
    Tally 把这个约定升格为契约（`parse_filename`）：正则组解析
    身份三件套（公司/期间/类型），**兜底分支要求 CJK 公司名主干，
    否则 `raise ValueError` 拒收**。实测事故（P0.5）：日期开头的
    外部分析 md 静默入库后产出 `20261009_MD` 这类垃圾 doc_id，
    检索会命中它、引用会指向它、没有任何机制淘汰它——「库内留过
    一具」的注释就是那时写下的。

    **页眉剥离 = 文档级频率统计。**同一行（归一化后）在 >30% 的页
    出现即判页眉。关键坑（P2 事故）：PDF 抽取的空格逐页漂移
    （`2026年` vs `2026 年`），逐字比对把同一页眉算成两个「不同
    的行」——修复是比对前剥尽空白**且剥数字**（页眉带页码）：
    `norm = re.sub(r"[\s\d]+", "", ln)`。

    **空文档闸门**：`ingest_file` 尾部一行——摄取出 0 块（扫描版
    PDF）直接拒收，不让 manifest 指纹锁死一具「检索不可见、问答
    永空手」的空壳。

    **指纹**：`_fingerprint` 流式 SHA-256（1MB 块），双语料 36MB
    全量哈希约 0.1 秒；配套三向 diff，删除只对本次扫描根负责
    （v0.4 多根摄取实测教训）。

## 2.6 小结

- 解析的实质是从视觉布局重建文档结构；三代工具各加一层不确定性，
  选型从最低代开始；
- 元数据两筐：身份字段确定性产出（错了是系统性错位），富语义字段
  才可交给模型；
- 增量摄取建在内容指纹上；幂等是底线，删除要限定作用域；
- 最危险的失败是静默成功——失败要贵、要可见（摄取层的 refused）。

## 常见误区

**误区一：「PDF 解析是已解决的问题」。**一行 pypdf 抽出文本的
假象，掩盖了「段落/表格/阅读顺序全部需要重建」的实质。先做语料
形态分析（表格占比、扫描件占比），再选解析器。

**误区二：「元数据用 LLM 提取更智能」。**富语义字段可以；身份
字段不行——身份要求同一输入永远同一输出，而 LLM 的抽取是分布
采样。

**误区三：「扫描版加个 OCR 就好」。**在数字敏感域，一个识别错的
数字比没有数字更危险。显式拒收（fail loudly）优于静默错（fail
silently wrong）。
