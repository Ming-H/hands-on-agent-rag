## 2.1 知识：解析为什么难——格式本质与三代工具

**PDF 的本质决定了它难啃**。PDF 是**页面描述格式**：内部是一串
「把字符画在坐标 (x, y)」的绘图指令，外加字体与图像资源——它
描述的是**打印效果**，不是**文档结构**。「段落」「表格」「阅读
顺序」「列表」这些语义单位在 PDF 里根本不存在，全是渲染的副
产品。所以「解析 PDF」的实质是**从视觉布局反向重建文档结构**
——一个逆向工程问题。三类日常翻车形态：

1. **同一行被拆成多个 text run**：字体/字号/加粗变化就把一行
   切成多段指令流——「归属于上市公司股东的净利润」抽出来中间
   可能夹着空格；
2. **双栏交错**：按指令流顺序读，左右栏内容交叉成乱码——必须
   按坐标做版面分析重排阅读顺序；
3. **表格拍平**：表格变成一堆坐标相近的散文本——「标签在上一
   行、数值在下一行」已经是最好的情况，跨页表格更是灾难。

解析质量是全链路的天花板：第 3 章的表格保全、第 6 章的证据
组装，都建立在「解析把结构交出来了」的前提上。

**三代工具谱系**，原理与代价各不同：

| 代 | 代表 | 原理 | 适用 | 代价 |
|---|---|---|---|---|
| 文本层抽取 | pypdf、PyMuPDF、pdfplumber | 读内嵌文本流+坐标（pdfplumber 另做曲线检测猜表格线）| 数字原生的 PDF | 表格结构大量丢失 |
| 版面感知 | [Docling](https://github.com/DS4SD/docling)、[Unstructured](https://unstructured.io) | 版面分析模型/规则做区域分割（栏/表/题注），再按类型分别抽取，输出统一 element 模型 | 混排文档 | 慢一个量级；版面规则要覆盖各种排版 |
| 模型驱动 | [LlamaParse](https://cloud.llamaindex.ai/parse)、[MinerU](https://github.com/opendatalab/MinerU)、Marker | 视觉模型（布局检测 + OCR）直接预测结构，甚至端到端 markdown 化 | 扫描件、复杂表格 | 最贵；**模型自身有幻觉面** |

两个代表系统的取舍值得对照细看：**Unstructured** 走确定性管线
（partition → 分类 element → 重组），可预测、可调试，代价是每种
新排版都可能出现分区错误；**MinerU/LlamaParse** 用视觉模型直接
预测结构，对复杂表格强得多，代价是**引入模型错误面**——识别错
的数字比没有数字更危险（数字敏感域的致命点）。这与第 1 章信任
分级同构：解析层加模型，就是给离线高频路径加不确定性。

**选型法则**：能用文本层就别上版面分析，能上版面分析就别上
模型——每升一代，成本/延迟/不确定性各加一层，而摄取是离线高频
操作，不确定性会被索引放大到每次查询。

**OCR 决策**：扫描件（无文本层）在数字敏感场景**显式拒收**
优于硬上 OCR——OCR 的错误面（8↔O、1↔l、千分位逗号丢失、
小数点漂移）正好打在最痛的地方。拒收文案要指明出路（「请提供
文字版或先经人工 OCR 校对」）——失败要贵、要可见，且可修复。

## 2.2 知识：元数据两筐——治理从摄取开始

检索系统的过滤、排序、权限全部挂在元数据上。治理分两筐：

| 筐 | 例子 | 该由谁产 | 错了会怎样 |
|---|---|---|---|
| **身份字段**（主键类）| 主体、期间/日期、doc_id、来源路径、密级 | **确定性来源**（文件名/路径/上游数据库字段的契约解析）| **系统性错位**——增量幂等、过滤、权限、记忆失效全崩 |
| **富语义字段**（加速类）| 摘要、标签、类别、别名 | 可用 LLM（低频、容错高、错了只是降级）| 检索少一条路而已 |

判断口诀：**这条元数据错了，是降级还是系统性错位？后者永远别给
模型。**身份字段的铁律是「同一文件永远得到同一身份」——LLM 对
同一文件两次抽取可能不同（分布采样，第 9 章），身份就漂了；漂了
的身份让增量摄取漏更新、让权限过滤形同虚设。

业界同构：数据工程界的老智慧「schema on write 的身份列必须来自
确定性源」；Airbyte / LlamaIndex 目录连接器都用 path→fingerprint
确定性账本管理文件身份。**元数据契约**是常见落地形态——把命名
约定（`公司_期间_类型.pdf`）升格为解析契约，正则解析身份三件套。

**身份之外的清洗**：页眉页脚是文档级重复噪声——naive 逐页硬编码
删前 N 行对不同版式立刻失效；正解是**文档级频率统计**（同一行
归一化后在超过阈值比例的页出现即判页眉）。频率统计的关键坑在
**归一化**：抽取的空格位置逐页漂移、页码数字页页不同——比对前
要剥空白**且剥数字**。通用教训（全书第一次出现）：**文本相等性
判定，永远先定义归一化**。

### 解析质量怎么量（没有度量就没有选型）

三档「够不够用」的判定法，从便宜到贵：

1. **抽检对齐率**（半小时）：随机抽 10 页，人工比对段落边界与表格
   单元格——表格单元格对齐率是最硬的指标（错一格 = 数字配错行 =
   口径事故）；
2. **下游代理指标**（一次 eval）：解析质量最终体现在检索与问答
   指标上——同一切分与检索配置下换解析器跑真值集，ret@3 / hit 的
   差距就是解析质量的代理读数（本书案例的选型就用这招）；
3. **专项基准**：文档解析已有专门评测集（中文场景可关注 MinerU
   团队随仓库发布的评测说明；英文侧 OmniDocBench 一类）——基准
   数字看量级，自家语料的抽检才是签字依据。

配套一张**解析质量退化警报清单**：双栏交错率（版式换了）、表格
拍平率（新模板）、字符乱码率（字体嵌入异常）——三个比率随摄取
批次记录，漂移即报警（解析是全链路天花板，天花板塌了最先知道）。

## 2.3 知识：幂等摄取与显式失败

**增量摄取的正确性问题**：语料在变（增/改/删），怎么知道哪些
文件要重处理？指纹方案对比：

| 方案 | 原理 | 失败形态 |
|---|---|---|
| mtime+size | 文件元信息，零 IO | `cp -p`/`rsync -a` 保时间戳改内容 → **漏更新**（语料静默过期，检索答旧数——最危险，无任何症状）；`touch` → 假更新（无谓重算）|
| 内容哈希（SHA-256）| 流式读全文件算指纹 | 多一次文件读（1MB 块流式可控）；**唯一同时堵两个洞的方案** |

三个术语的准确含义：**幂等**（同一语料状态摄取 N 次，库内状态
不变）是底线；**增量** = 幂等 + 三向 diff（add / update / delete）；
**删除的作用域限定**——多来源共存一库时（业务文档 + 研报 + wiki
同库），一次扫描只对**本次扫描根**负责，否则同步 A 目录会把 B
目录的文档当「磁盘上消失」误删。

**最危险的失败是静默成功**。摄取层两类典型：空内容文档「成功
入库」（0 块，指纹已记，永不重试——库里躺一具检索不可见、问答
永空手的空壳）；垃圾身份「成功关联」（doc_id 是 `20261009_MD`
这类日期拼接，引用指向它、用户无法核对）。原则：**失败要贵、
要可见**——显式抛错走 ⚠ 链路（用户看得见、改得了：改文件名/
去 OCR），优于入库空标记的静默债务。这是第 1 章三态出口在摄取
层的投影：摄取也需要 refused。

## 2.4 案例研究：Tally 的摄取层

!!! abstract "案例研究：Tally（ingest.py / source.py）"

    **文件名契约**（`parse_filename`，代码走读）——巨潮财报命名
    `公司名_2026年半年度报告.pdf` 天然带结构，券商研报
    `日期-券商-公司-代码.pdf` 也是：

    ```python
    # tally/ingest.py: parse_filename（节选）
    _REPORT_PAT = re.compile(r"^(\d{8})-([^-]+)-(.+)\.pdf$")   # 研报
    _PERIOD_PAT = [                    # 文件名 → (period, kind)，穷举
        (re.compile(r"(\d{4})年年度报告"), "FY"),
        (re.compile(r"(\d{4})年半年度报告"), "H1"),
        (re.compile(r"(\d{4})年半年度业绩预告"), "H1E"),
        # …Q1/Q3/Q3E 同构
    ]
    company = re.split(r"[__－-]", name)[0]     # 兜底：主干当公司名
    if not re.search(r"[一-鿿]", company):      # 但必须含 CJK——
        raise ValueError(f"文件名解析不出公司名（主干={company!r}），拒收")
    ```

    设计三读：**兜底最严**（宁可错杀不可放过——日期开头的外部分析
    md 静默入库的实测事故：垃圾 doc_id `20261009_MD` 进了库，检索
    会命中、引用会指向、没有机制淘汰，P0.5 复盘原话「库内留过一
    具」）；**失败要贵**（ValueError 走 ⚠ 报告，用户改文件名即可
    修复）；**为什么不 LLM 猜**——同一文件要永远同一 doc_id（增量
    幂等依赖它），且猜错是静默的（2.2 的口诀）。

    **页眉剥离**（文档级频率统计 + 归一化）：

    ```python
    # P2 事故修复：空格逐页漂移 + 页码页页不同 → 剥空白且剥数字再比对
    norm = re.sub(r"[\s\d]+", "", ln)
    # 同一 norm 在 >30% 的页出现 → 判页眉删除
    ```

    P2 复盘三行：现象（剥离对部分页失效，答案被页眉噪声污染）→
    根因（`2026年` vs `2026 年` 被当成两个「不同的行」，频率各自
    过不了阈值）→ 修复（归一化先行，且剥数字防页码）。

    **空文档闸门**一行：

    ```python
    if not chunks:
        raise ValueError(f"{path} 摄取出 0 块——疑似扫描版 PDF 或空文档，拒收")
    ```

    **指纹与三向 diff**：`_fingerprint` 流式 SHA-256（双语料 36MB
    全量哈希约 0.1 秒）；`cmd_ingest` 三向 diff，删除只在
    `under_root(本次扫描根)` 内生效（多根共存一库的实测教训）。

## 2.6 小结

- PDF 是页面描述格式，解析 = 从视觉布局重建结构；三类翻车
  （text run 拆行/双栏交错/表格拍平）是结构性而非 bug；
- 三代工具各加一层不确定性；选型从最低代开始；数字敏感域扫描件
  显式拒收优于硬上 OCR；
- 元数据两筐：身份字段确定性产出（错了是系统性错位），富语义
  字段才可交给模型；文本相等判定先定义归一化；
- 幂等是底线，增量 = 幂等 + 三向 diff + 删除限定作用域；最危险
  的失败是静默成功——失败要贵、要可见。

## 常见误区

**误区一：「PDF 解析是已解决的问题」。**一行 pypdf 抽出文本的
假象掩盖了结构重建的实质。先做语料形态分析（表格占比/扫描件
占比/双栏占比），再选解析器。

**误区二：「元数据用 LLM 提取更智能」。**身份字段不行——身份
要求同一输入永远同一输出，LLM 抽取是分布采样。摘要/标签可以。

**误区三：「mtime 够用了」。**`cp -p`/`rsync -a` 保 mtime 改内容
的场景一出现，语料静默过期——检索答旧数且无任何症状。内容哈希
是唯一同时堵两个洞的方案。

**误区四：「摄取失败就跳过，别打断流程」。**静默跳过制造的是
「空壳文档 + 永不重试」的静默债务。显式拒收 + ⚠ 报告才是对用户
负责的失败形态。
