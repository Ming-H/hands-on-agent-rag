> 状态：初稿 v0.1 · 所属：第一部 知识入库 · 前置：第 1 章

## 2.1 失败先行：一个垃圾文件名的通关之旅

把 samples 里任一文件复制一份，改成 `20261009_某公司三季预告分析.md`
这种日期开头的名字，再摄取：

```bash
cp samples/欧科亿_2026年半年度业绩预告.pdf /tmp/x.pdf   # 举例
python -m tally.cli ingest samples/
```

日期开头的 md 会收到 ⚠ 拒收。这不是 bug——是 P0.5 轮实测换来的
闸门：**主干是纯数字的文件名，曾经真的产出过 `20261009_MD` 这样的
垃圾 doc_id**，进了库就污染检索和引用，还永远留在那里。

垃圾进、垃圾出。摄取层的第一课：**元数据必须有确定性的来源，
绝不靠模型猜。**

## 2.2 决策：文件名即元数据契约

Tally 认三类文件名（`tally/ingest.py: parse_filename`）：

```python
# 研报：20260703-东吴证券-并行科技-920493-标题.pdf → (券商, 日期, 研报)
_REPORT_PAT = re.compile(r"^(\d{8})-([^-]+)-(.+)\.pdf$")

_PERIOD_PAT = [                                    # 文件名 → (period, kind)
    (re.compile(r"(\d{4})年年度报告"), "FY"),
    (re.compile(r"(\d{4})年半年度报告"), "H1"),
    (re.compile(r"(\d{4})年第一季度报告"), "Q1"),
    ...
]
    # 兜底：主干必须是可读公司名（含 CJK）——日期开头的外部分析
    # 静默入库会产出 20261009_MD 这类垃圾 doc_id（污染检索与引用）；
    # 拒收让 cli 以 ⚠ 跳过（P0.5 实测库内留过一具）
    company = re.split(r"[__－-]", name)[0]
    if not re.search(r"[一-鿿]", company):
        raise ValueError(f"文件名解析不出公司名（主干={company!r}），拒收")
```

为什么不用 LLM 从正文猜公司名和期间？三个理由：①确定性——同一
文件永远解析出同一 doc_id，增量摄取的幂等性依赖它；②零成本零延迟；
③**猜错了你不知道**——文件名错了至少报错可见，模型猜错是静默的。

## 2.3 页眉剥离：一行空格打败逐字比对

PDF 抽取的正文页页带着「公司名 + 报告标题」的页眉。Tally 的做法是
**文档级频率统计**：同一行（归一化后）在超过 30% 的页出现即判页眉。
关键坑在归一化——P2 事故实录：

> PDF 文本抽取的空格位置逐页漂移（`2026年` vs `2026 年`），逐字相同
> 的判定失效——出现频率被分散，过不了 30% 阈值。修复：比对前
> `re.sub(r"\s+", "", ln)` 剥尽空白，且把数字也剥掉（页眉带着页码，
> 「第 3 页」「第 4 页」不剥就页页不同）。

**通用教训：文本相等性判定，永远先定义归一化。** PDF 的「视觉相同」
和「字节相同」是两回事。

## 2.4 空文档闸门：扫描版 PDF 的静默失败

一份 232 页的全扫描件 PDF（pypdf 抽不出任何文本）会发生什么？
每一页都因「长度 < 20」被跳过，最后 `ingest_file` 返回 0 个 chunk
——修前的行为是：**空文档「成功」入库**，manifest 记下指纹，
以后每次增量都跳过它（指纹没变），库里永远躺着一具检索不可见、
问答永空手的空壳。

修复是一行闸门（`ingest.py: ingest_file` 尾部）：

```python
    if not chunks:
        # 空文档闸门：0 块文档静默入库后 manifest 指纹锁死、永不重试，
        # 库里留一具问答永空手的空壳——显式失败让 cli 的 ⚠ 链路报告
        raise ValueError(f"{path} 摄取出 0 块——疑似扫描版 PDF 或空文档，拒收")
```

注意失败方式的选择：**显式抛错走 cli 的 ⚠ 报告链路**，而不是入库
一个标记为「空」的文档——前者用户可见、可修（去 OCR），后者是
静默债务。

## 2.5 增量指纹：从 mtime 到内容哈希

摄取怎么知道哪些文件变了？`tally/source.py` 的答案演进了一轮：

```python
def _fingerprint(p: Path) -> str:
    """内容哈希指纹（流式读，1MB 块）——只看内容，与 mtime/ctime 无关。"""
    h = hashlib.sha256()
    with open(p, "rb") as fh:
        for block in iter(lambda: fh.read(1 << 20), b""):
            h.update(block)
    return f"sha256:{h.hexdigest()[:24]}"
```

初版用 `mtime_ns-size`（轻量），直到被指出两个洞：`cp -p`/`rsync -a`
保留旧 mtime 改内容会**漏更新**（语料静默过期，检索答旧数）；`touch`
会**假更新**。换成 SHA-256 后两者都堵死——成本是双语料 36MB 全量
哈希约 0.1 秒，可接受。配套的 three-way diff（增/改/删自适应、
多根共存一库、删除只对本根负责）在 `cli.py: cmd_ingest`。

## 2.6 动手实验

```bash
# ① 拒收演示：日期开头的文件名
cp samples/海伦哲_2026年第一季度报告.pdf samples/20261009_test.md  # (内容无所谓)
python -m tally.cli ingest samples/   # 观察 ⚠ 拒收信息

# ② 空文档闸门：造一份空白 PDF
python -c "from pypdf import PdfWriter; w=PdfWriter();
[w.add_blank_page(width=595,height=842) for _ in range(3)];
w.write('/tmp/空壳公司_2025年年度报告.pdf')"
cp /tmp/空壳公司_2025年年度报告.pdf samples/ && python -m tally.cli ingest samples/
# 观察 ⚠「摄取出 0 块——疑似扫描版」；然后删掉这个文件再 ingest（清指纹）

# ③ 幂等性：连续跑两次 ingest，第二次应为 0 新增 0 更新
python -m tally.cli ingest samples/ && python -m tally.cli ingest samples/
```
