    自托管）；②解释 OpenAI 兼容协议为什么是事实标准、例外有哪些；

## 8.1 知识：选型五维与三种接入形态

模型选型不是「哪个最强」，是五个维度的联立求解：

| 维度 | 问什么 | 典型权衡 |
|---|---|---|
| 任务 | 理解、生成还是工具调用？ | 结构化抽取对小模型更友好；叙述对大模型敏感 |
| 能力 | 档位够不够过你的闸门？ | 有闸门兜底时，档位只影响「讲得好不好」 |
| 成本 | 单价 × 调用次数 × token | agent 循环一次问答 = 5–10 次调用，成本放大系数先算 |
| 延迟 | p50/p95/p99 与长尾 | 远端长尾 20s+ 真实存在——超时与重试是必需品 |
| 数据边界 | 语料/问题能出域吗？ | 内部文档场景，云端选项直接出局 |

落到接入形态是一棵三叉树：数据不能出域 → **公司级自托管**
（vLLM + 开源权重，吞吐与数据都不妥协，代价是运维推理服务）；
要零成本/离线/数据不出机 → **本地**（Ollama，档位受本机算力
限制）；都不受限 → **云端 API**（最强能力，代价是成本、长尾、
出域）。vLLM（[arXiv:2309.06180](https://arxiv.org/abs/2309.06180)）
的 PagedAttention 让自托管的吞吐逼近商用服务，是「公司级」选项
成立的技术原因。

**OpenAI 兼容协议是事实标准**：2024–2025 年几乎所有服务商
（DeepSeek/智谱/vLLM/Ollama/云厂商）都提供兼容的
`/v1/chat/completions`。工程含义：**接入层写一次，换服务商改一个
`base_url`**。例外只有两类（行为差异大到必须特殊对待）：本地
Ollama 的兼容层会静默丢参数（原生 `/api/chat` 才有完整控制）、
Anthropic 的 Messages 协议（thinking 预算语义不同）。

**结构化输出三路线**——agent 应用要模型可靠输出 JSON 的三条路：

| 路线 | 机制 | 可靠性 | 代价 |
|---|---|---|---|
| prompt 约束 | 「只输出 JSON」+ few-shot | 最低（围栏/夹带/漂移）| 零依赖 |
| JSON mode / function calling | 服务端保证合法 JSON / 参数 schema | 高（协议层）| 依赖服务商 |
| 受限解码 | 解码器层面约束语法（[outlines](https://arxiv.org/abs/2307.09702)）| 最高（非法格式生不成）| 要控制解码器，云 API 给不了 |

分层选择：**协议层保证 + 防御性解析 + 调用点兜底**三层叠，不追求
受限解码——因为每个结构化调用点都该有规则兜底，解析失败的代价
是降级而非崩溃。「可靠性靠结构不靠解码」。

**工具调用协议要点**（第 11 章展开设计原则）：严格协议要求
`tool_calls` 项带 `id+type`、`arguments` 是 JSON 字符串、`tool`
消息回指 `tool_call_id`——内部用宽松格式、边界做归一化是常见
解法。

## 8.2 知识：推理工程面与成本模型

接入层不只是「能调通」，是一组生产参数的工程：

- **超时与重试**：尾延迟 20s+ 的真实存在意味着无超时的调用会把
  单次请求拖到半分钟。经验起点：SDK 层 60s 超时 + 重试 1 次——
  **重试是止血不是治病**，超过 1 次说明该降级了；
- **批处理**：离线评测/批量处理用 Batch API（半价量级、小时级
  返回）——评测集跑批与在线单问走不同通道是免费的省钱；
- **流式（streaming）**：首 token 延迟决定体感——长答案流式输出
  把「等 15 秒」变成「立刻开始读」；注意流式下做输出校验要把
  流拼完再验；
- **提示缓存（prompt caching）**：系统提示词 + 检索上下文的前缀
  相同部分命中缓存，成本与延迟双降——把「稳定的放前面、变化的
  放后面」从排版习惯变成省钱纪律；
- **成本模型**：每问成本 = Σ（各调用 token_in × 单价_in + token_out
  × 单价_out）。没有调用账本（每问几次调用、各多少 token）的
  系统不知道自己多贵；agent 循环的成本放大系数（5–10×）要在
  选型时就算进去。

**thinking/温度纪律**：思考预算（reasoning tokens）普遍计入输出
预算——开思考可能把生成预算吃光、正文为空；温度上，凡是要确定
性的地方（结构化抽取、评分）`temperature=0`，叙述生成小温度。
**通道间的行为差异必须实测**：「兼容协议」不代表参数语义一致，
每个通道的关键参数都要验证生效，不能信文档信到裸奔。

**显式失败优于半成品**：接入层的第一美德不是全覆盖，是失败得
明明白白。一个抛异常的通道是可诊断的；一个「能调通但参数被静默
吞掉」的通道是定时炸弹。没有能力的组合就显式 `NotImplementedError`
+ 走兜底路径，答案质量同闸。

## 8.3 案例研究：Tally 的 llm.py

!!! note "案例研究：Tally（llm.py，约 290 行）"

    **通道判定 = 两个纯函数**，没有配置项没有 if 用户选——host
    与路径即协议：`localhost/127.0.0.1` → 原生 `/api/chat`；
    base_url 含 `/api/anthropic` → Messages 协议；其余 → OpenAI
    兼容 SDK。全部配置就五个环境变量（`TALLY_LLM_API_KEY/
    BASE_URL/MODEL/MAX_TOKENS/THINKING`），密钥只进 `.env`。

    **D7 三实测**（改 llm.py 前先读，DESIGN-v0.5）：①Ollama 的
    `/v1` 兼容层**静默吞 `think` 参数**——本地通道绕过 SDK 直连
    原生端点的原因；②Qwen3.5 的 `/no_think` 软开关已死；③thinking
    计入 max_tokens——Anthropic 通道 512 预算被思考吃光正文为空，
    该通道预算自动 ×8。由此沉淀分层纪律：**结构化调用永远关思考、
    本地默认关**（0.8b 开思考延迟 ×5：14s vs 3s 实测；生成垮了由
    verify 降级兜底）；温度同构（结构化 0、生成 0.2）。

    **防御性解析**：`_parse_json` 剥围栏、取首个花括号平衡块，
    失败抛 ValueError 由调用节点降级规则——解析失败是预期事件。
    **消息归一化**：`_normalize_tool_messages` 把内部宽松格式转
    严格协议（按位置确定性生成 call_N id，不就地污染入参）——
    v0.7.1 靠它接通远端 function calling，上层 agent 环零改动。

    **显式失败**：Anthropic 通道 tools 未接 → 显式
    NotImplementedError → agent 环走固定管线兜底，答案同闸。
    远端实测（glm-5.3，agent 集 8 题）：22 次调用 dup=0、
    waste_rate 0.227、两道 compare 被 0.45 阈值降级抽取式仍全对。

## 8.5 小结

- 选型五维 × 三形态；OpenAI 兼容是事实标准，例外两类（本地原生、
  Anthropic Messages）——判据是实测的 host 与路径；
- 结构化输出三层叠：协议层保证 + 防御性解析 + 调用点兜底；
- 推理工程面：超时/重试/批处理/流式/缓存各管一段；成本模型先算
  agent 循环的放大系数；稳定前缀放前面吃缓存；
- thinking 与温度按确定性需求分层；通道行为差异必须实测；
- 显式失败优于半成品——接入层的美德是失败得明明白白。

## 常见误区

**误区一：「接最强模型再说」。**接入层设计决定换模型的成本。
通道/密钥/参数硬编码进业务代码，每次换档都是一次回归测试；五个
环境变量 + 自动判定，换档是运维动作。

**误区二：「兼容协议 = 行为一致」。**「能调通」不代表参数生效——
think 被静默吞就是实例。每个通道的关键参数都要实测验证。

**误区三：「解析失败用更长的 prompt 修」。**更长 prompt 降频率、
不改变失败形态。正解是三层叠（协议/防御解析/兜底），prompt 只是
第一层便宜的门帘。
