## 8.1 失败先行：两种灾难形态

把 `tally/answer.py` 的 `COVERAGE_THRESHOLD = 0.45` 调成两个极端，
各跑一遍真值集：

```bash
# 极端 A：阈值 0.0——什么都放行
#   观察：citation_coverage 虚高，但问口径的题开始答错数字仍 pass
#   ——闸门死了，第 9 章的口径灾难全部回来

# 极端 B：阈值 1.0——近乎全降级
#   观察：大量答案被降级成抽取式（答案变丑但仍然全对）、部分被拒
#   ——正确性保住了，可用性掉一半
```

0.45 不是玄学，是实测分布：真值题的覆盖率分布里，合格答案聚在
0.5–0.95，编造答案聚在 0.2 以下——0.45 是两峰之间的谷。
**阈值是工程：它该由数据的分布决定，由回归测试锁定。**

## 8.2 三态出口：pass / degraded / refused

verify_citations 是全图唯一出口（`tally/graph.py`），任何路径——
heuristic 检索、Agent 自主检索、记忆命中、差分派生——都必须过它：

```python
# tally/graph.py: verify_citations（骨架节选）
    verdict, cov = ans.verify(a, pool)          # 引用覆盖率对账
    if verdict == "pass" and not _derived_ok(state.get("derived"), pool):
        verdict = "degraded"                     # 派生值出口重算 ±0.01
    ...
    else:  # degraded：LLM 答案对不上账 → 降级为抽取式（永远有真凭实据）
        body, cited = ans.extractive_answer(state, state["hits"])
```

三种出口的语义：

| 出口 | 含义 | 用户看到 |
|---|---|---|
| pass | 覆盖率 ≥ 阈值 | LLM 组织的完整回答 |
| degraded | 对不上账 | **从证据池抽的原句**（丑但真）|
| refused | 无证据可用 | 拒答 + 现有期间提示 |

注意 degraded 的设计：**降级不是重试**——不把答案打回模型改写
（小模型会把同一件事编得更圆），直接换成交取式。抽取式答案每句
都带引用、每个数字都来自原文——**可靠性由结构保证，不靠模型
自觉。**

## 8.3 覆盖率怎么算（以及它不算什么）

`citation_coverage` 的口径（`tally/answer.py`，注释值得全文读）：

- 证据池 = 答案里实际被引用的块 + hits（页窗口自动扩展到整页）；
- **只考核数字句**——框架句（「根据提供的证据…」）不要求与证据重叠，
  否则 LLM 的行文结构会被误杀；
- 两侧 token 都剔除元词（公司名/年份/期间）——「欧科亿 2026 年」
  不构成证据相关性，数字与指标词才是；
- 数字归一化注释计入证据（LLM 常答「6.44亿」而非原文
  「644,051,473.82」）。

**它不算什么**（诚实的边界，第 13 章展开）：它保证「答案说的每句话
有出处」，不保证「答案说的是问的那件事」——问扣非答归母，只要
归母的句子真的在证据池里，verify 照样 pass。这道缝隙由第 9 章的
口径守卫补，补不完的部分写进边界账本。指标名也由此改过一次：
`faithfulness → citation_coverage`——名实相符，别让指标名替你吹牛。
