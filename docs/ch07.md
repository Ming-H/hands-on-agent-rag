## 7.1 知识：groundedness 三路线与裁判的脾气

「怎么保证生成不编」的三条代表路线：

| 路线 | 代表 | 机制 | 代价 |
|---|---|---|---|
| 自反思 | [Self-RAG](https://arxiv.org/abs/2310.11511) | 模型生成反思 token 自评 | 要微调；**自己批自己的卷子** |
| 纠错环 | [CRAG](https://arxiv.org/abs/2401.15884) | 检索评估器打分，差则重检/补源 | 开放世界假设（「补」的来源是谁？）|
| **事后归因闸** | AIS 工程化 | 生成后逐句对账证据池，不过则降级/拒答 | 需要独立验证器 |

选第三条的深层理由：**验证器不能和生成器是同一个大脑**。Self-RAG
让模型自评，等价于让学生批自己的卷子——模型犯错的相关性会让自评
跟着错。事后闸用与模型能力无关的判定（规则/独立模型）算对账，
换厂商、换档位，**闸门同一把尺子**。

用 LLM 当裁判（NLI 蕴含判定、RAGAS 的 faithfulness）是折中路线：
语义级、能抓「改写后仍忠实」的细粒度问题，但**裁判模型自带方差
与偏差**——[MT-Bench](https://arxiv.org/abs/2306.05685) 的画像：
强 judge 与人一致率可超 80%，但有位置偏（先看的答案占优）、冗长
偏（长的赢）、自增强偏（偏爱自己风格的输出）三类系统性偏差。
工程结论不是「别用 judge」，是**别给 judge 油门**：judge 只能
否决不能解锁（veto-only），且永远跑在确定性闸门之后。另一个邻居
是 **guardrails 中间件**（NeMo Guardrails、
[Llama Guard](https://arxiv.org/abs/2312.06674)）——它们管安全和
话题边界（「不能说的话」），出口闸门管事实对账（「说错的话」），
互补不互替。

**三态出口与阈值工程**。三态契约（pass/degraded/refused，第 1 章）
的落地是阈值：判定分数低于阈值 → 降级（换确定性产物，不是重试
——重试是给模型二次编造的机会，且错在证据层时重写治不了根）。
阈值怎么定？**两极端法**：先把阈值调到 0.0（什么都放行）和 1.0
（近乎全拦）各跑一遍真值集——0.0 证明闸门防的那条路径存在，1.0
证明降级产物的质量下限——再看合格答案与坏答案在**你的**语料与
生成器下的分数分布，阈值取两峰之间的谷。**阈值是工程：由分布
决定，由回归测试锁定**；抄别人的阈值等于抄别人的分布。

## 7.2 知识：闸门的盲区——实体粒度混淆

规则闸门的典型判定是「答案句里的内容能否在证据池找到」。它有一
个结构性盲区：**答案完全有据，但答非所问**——

```text
问：A 公司的扣非净利润是多少
答：A 公司的净利润是 X 元 [引用真实、页码正确]
验证：数字真在证据池 → pass ✓
真值：扣非 ≠ 净利润 —— 差了一个口径
```

这类错误的学名是**实体粒度混淆**（同族实体的属性分支互相冒充），
每个领域都有自己的版本：

| 领域 | 混淆对（语义近、语义价值不同）|
|---|---|
| 财经 | 归母净利润 ↔ 扣非净利润；营业收入 ↔ 营业总收入；总资产 ↔ 净资产 |
| 医疗 | 常规剂量 ↔ 最大日剂量；血清肌酐 ↔ 尿素氮；成人 ↔ 肾功能不全人群 |
| 法务 | 原告 ↔ 上诉人；合同生效日 ↔ 签署日 |
| 电商 | GMV ↔ 净销售额 |

**为什么语义检索救不了它**：混淆对在向量空间里几乎贴着（都是
「净利润」！）——语义越近，冒充越容易、检索越分不开（第 5 章
BEIR 结论的口径版）。业界没有现成轮子：实体消歧解决「茅台=贵州
茅台」，不解决「归母 vs 扣非」；元数据过滤在文档级，不滤句级
口径；prompt 提醒降频不建边界。**领域守卫是自建空白区**——通用
框架是分层防御：打分层抑制冒充句（问 X 时同族 Y 降权）、校验层
要求答案大数出现在**该口径的标签行**（不只「在场」，还要「在
正确的行里」）、评测层做反向断言（问 X 的答案不得出现 Y 的数值）。
识别方法放之四海：找你的语料里「语义相近而语义价值相反」的词对
家族——那就是你的口径清单。

**gate ≠ correctness**：把上面的盲区说全——闸门管「有出处」，
不管「对题」（结论是否回应问句）、不管「完整」（该比的两家比了
吗）。管不到的部分要么显式声明（「未覆盖」），要么写进边界账本
（第 14 章）。**主动写下管不住什么，比全绿可信。**

## 7.3 案例研究：Tally 的对账闸门与五层口径防线

!!! note "案例研究：Tally（graph.py / answer.py / evalx）"

    **唯一出口闸**：verify_citations 是全图唯一出口——规则检索、
    Agent 自主检索、记忆命中、差分派生，任何路径都过它。判定 =
    引用覆盖率（数字句 token 与证据池的重叠，剔除公司名/年份等
    元词；换算注释计入证据；证据池 = 被引块 ∪ hits——**验证器和
    被验物必须看同一个世界**）。派生值另有出口重算：Q2=H1−Q1 的
    答案，操作数必须真在场且 |a−b−value| ≤ 0.01——**禁止模型
    心算**（封闭世界里算术也是事实）。

    **阈值两极端实测**（innolight 31 题，2026-10-22）：

    | 阈值 | coverage | answer_hit | 课 |
    |---|---|---|---|
    | 0.0（放行）| 1.000 | 1.0 | heuristic 下无症状——**危险潜伏**：LLM 路径上编造但挂引用的答案会畅通（v0.7.1 远端实测两例 compare 正是被 0.45 拦下）|
    | 0.45（基线）| 1.000 | 1.0 | 合格答案分布 0.5–0.95、编造 <0.2，谷底取 0.45 |
    | 1.0（全拦）| 0.074 | **1.0** | 93% 降级抽取式仍全对——**降级=安全失败**，惩罚形态不惩罚正确性 |

    **五层口径防线**（全表与六对降权注释见附录 D）：拼块（标签/
    数值重接）→ 行级抽取（指标词后首大数 + 前邻 20 字口径检查）→
    配对降权（问扣非时归母句 ×0.3，降权不跳过——双口径问句仍要
    看到对方）→ 数值闸（问具名口径，大数必须在该口径标签行，D22）
    → 评测反断言（forbid_keywords）。泛化证据：**第二家公司（贵州
    茅台）十份文档入语料，9 题零调参全对**——防线按标签行工作，
    公司无关；新口径家族的成本 = 一条降权 + 一道 forbid 题。

    **LLM 裁判（`_self_check`）**：trend 叙述存活后的非对称裁判，
    只能否决（sensitive 剥句不重写；不忠实有界修复 1 次再退骨架）
    ——永远在确定性闸门之后。

!!! example "迁移盒：医疗指南的「口径」是什么"

    - **语料差异**：「口径」= 干预层级与人群分支——推荐剂量 vs
      最大日剂量、成人 vs 肾功能不全者。

      第一道交付物。

## 7.5 小结

- 三路线取舍：事后归因闸与生成器解耦（验证器不能和生成器同一个
  大脑）；LLM 裁判有偏差清单，只配坐刹车位；
- 阈值工程两极端法：0.0 验证防御路径存在、1.0 验证降级下限，
  阈值取你自己分布的谷底；
- 闸门的结构性盲区是实体粒度混淆——语义越近越难分，领域守卫
  （打分抑制/行级校验/评测反断言）是自建空白区；
- gate ≠ correctness：管不到的显式声明或入边界账本。

## 常见误区

**误区一：「verify 是可选的锦上添花」。**没有出口验证的系统把
正确性全部押在生成层自觉上——自觉是 prompt，换模型就变天。verify
是把正确性从概率问题变成结构问题的那道门。

**误区二：「闸门没拦住 = 闸门没用」。**7.2 的盲区是所有「证据
在场」型闸门的共同边界——正确的反应不是拆闸门，是加领域守卫
层 + 诚实记录管不住什么。

**误区三：「口径问题在 prompt 里提醒一句就行」。**prompt 约束
降低频率、不建立边界——要修在打分层（降权）、校验层（行级验证）、
评测层（forbid），prompt 只是第一道便宜的门帘。
