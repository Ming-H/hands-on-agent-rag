## 7.1 知识：groundedness 三路线与裁判的脾气

「怎么保证生成不编」的三条路线，机制与代价各自不同：

| 路线 | 代表 | 机制 | 代价 |
|---|---|---|---|
| 自反思 | [Self-RAG](https://arxiv.org/abs/2310.11511) | 模型生成反思 token 自评「要不要检索/证据够不够」 | 要微调；**自己批自己的卷子** |
| 纠错环 | [CRAG](https://arxiv.org/abs/2401.15884) | 检索评估器打分（correct/incorrect/ambiguous），差则触发纠正（重查/改写/补源）| 开放世界假设（「补」的来源是谁？）|
| **事后归因闸** | AIS 工程化 | 生成后逐句对账证据池，不过则降级/拒答 | 需要独立验证器（本章） |

选第三条的深层理由：**验证器不能和生成器是同一个大脑**。Self-RAG
的自评与生成共享同一个模型的错误相关性——模型系统性弄错的地方，
自评也系统性放行。事后闸用与模型能力无关的判定（规则/独立 NLI），
换厂商换档位，**闸门同一把尺子**。

**NLI 路线**（RAGAS faithfulness 的底座）：把答案拆成 claims，
逐条用 NLI 模型判「证据是否蕴含」。语义级、能抓「改写后仍忠实」
的细粒度问题——但有裁判方差（同一答案两次打分不同）与领域盲区
（见 7.2 的口径缝隙 NLI 看不出）。**LLM-as-judge 的脾气清单**
（[MT-Bench](https://arxiv.org/abs/2306.05685)）：强 judge 与人
一致率可超 80%，但三类**系统性偏差**——**位置偏**（先看的答案
占优）、**冗长偏**（长的赢）、**自增强偏**（偏爱自己风格的输出）。
工程结论不是「别用 judge」，是**只给刹车不给油门**（veto-only：
只能否决不能解锁），且永远跑在确定性闸门之后。邻居**guardrails
中间件**（NeMo Guardrails、[Llama Guard](https://arxiv.org/abs/2312.06674)）
管安全和话题边界（「不能说的话」），出口闸门管事实对账（「说错
的话」）——互补不互替。

**judge 偏差的一眼演练**：拿两个候选答案让 LLM 裁判——A：准确但
 3 行；B：同样准确但 8 行且开头复述问题。多数裁判给 B 更高分
（冗长偏 +「显得专业」的自增强偏）；把 A/B 交换顺序再问一次，
同一裁判可能反转（位置偏）。三个对策按成本排：**交换顺序问两次
取平均**（成本 ×2）、**盲评**（不给「哪个是自家系统」的标记）、
**只允许否决**（veto-only——把裁判从法官降为安检员）。这就是
MT-Bench 偏差清单落到工位的形态。

**NLI 判定例**（RAGAS faithfulness 的最小单元）：claim =「净利润
  同比增长 58.39%」，证据 = 同表格块 → 判蕴含（entail）→ 该 claim
  忠实；claim =「增长主要系需求回暖」而证据只有数字 → 判中性
  （neutral）→ 该 claim 无据。注意 NLI 在这里的**粒度是 claim 不是
  句子**——答案先被拆成原子断言再逐条判，这是 RAGAS 与 token
  重叠（案例做法）的本质差异：一个语义级带方差，一个确定性但粗。

**三态出口与降级设计**
**三态出口与降级设计**。三态契约（第 1 章）的落地是阈值判定：
分数低于阈值 → degraded。**降级不是重试**——重试给模型二次编造
机会（小模型会把同一件事编得更圆），且错在证据层时重写治不了
根；降级产物（抽取式原句直出）**结构上不可能编造**——每句有
出处、数字来自原文，「丑但真」。失败形态本身是设计对象。

**阈值工程（两极端法）**：

```text
第一步：阈值调到 0.0（全放行）跑真值集
   → 看哪些「编造但挂引用」的答案混进来（证明闸门防的路径存在）
第二步：阈值调到 1.0（全拦）跑真值集
   → 看降级产物的质量下限（安全失败的验证）
第三步：画合格答案与坏答案的分数分布，阈值取两峰之间的谷
   → 用回归测试锁定（阈值进 CI）
```

**阈值是工程：由你的分布决定，由回归锁定**。抄别人的阈值 = 抄
别人的分布。

## 7.2 知识：闸门的结构性盲区——实体粒度混淆

「证据在场」型闸门有一个绕不开的盲区：**答案完全有据，但答非
所问**：

```text
问：A 公司的扣非净利润是多少
答：A 公司的净利润是 X 元 [引用真实、页码正确、数字在场]
验证：X 真在证据池 → pass ✓
真值：扣非 ≠ 净利润 —— 差了一个口径
```

学名**实体粒度混淆**（同族实体的属性分支互相冒充），每个领域
都有自己的版本：

| 领域 | 混淆对（语义近、语义价值不同）|
|---|---|
| 财经 | 归母净利润 ↔ 扣非净利润；营业收入 ↔ 营业总收入；总资产 ↔ 净资产 |
| 医疗 | 常规剂量 ↔ 最大日剂量；血清肌酐 ↔ 尿素氮；成人 ↔ 肾功能不全人群 |
| 法务 | 原告 ↔ 上诉人；合同生效日 ↔ 签署日 |
| 电商 | GMV ↔ 净销售额 |

**为什么语义检索救不了它**（第 5 章硬币的出口面）：混淆对在
向量空间几乎贴着——**语义越近，冒充越容易**；NLI 裁判也看不出
（两个数都在上下文里，蕴含判定通过）；元数据过滤在文档级，不滤
句级口径；prompt 提醒降频不建边界。**领域守卫是自建空白区**——
没有 canonical 轮子的三个近邻：实体消歧（解「茅台=贵州茅台」，
不解「归母 vs 扣非」）、Table QA（假设问题直指表格行，兜不住
叙述句）、prompt 约束（生成层自觉，第 6 章已立论不当边界）。

**三层通用防御框架**（打分/校验/评测各一层）：

1. **打分层抑制**：问 X 时，同族 Y 的句子降权（×0.3 而非删除
   ——双口径问句「扣非和归母差多少」仍要看到对方）；
2. **校验层行级验证**：问具名口径时，答案大数必须出现在**该口径
   的标签行**（不只「在场」，还要「在正确的行里」）——把证据
   在场升级为证据对位；
3. **评测层反向断言**（forbid）：问 X 的答案不得出现 Y 的数值
   ——防守知识共享给评测，每次 CI 都跑。

识别方法放之四海：找你的语料里「语义相近而语义价值相反」的词对
家族——那就是你的口径清单（迁移练习见 7.4）。

**gate ≠ correctness**：盲区说全——闸门管「有出处」，不管
「对题」（结论是否回应问句）、不管「完整」（该比的两家比了
吗）。管不到的：显式声明（「未覆盖」，第 10 章）或写进边界账本
（第 14 章）。**主动写下管不住什么，比全绿可信。**

## 7.3 案例研究：Tally 的对账闸门与五层防线

!!! abstract "案例研究：Tally（graph.py / answer.py / evalx.py）"

    **唯一出口闸**——verify_citations 是全图唯一出口，规则检索、
    agent 自主检索、记忆命中、差分派生全部过它（骨架走读）：

    ```python
    # tally/graph.py: verify_citations（骨架）
    pool = list(state.get("evidence") or []) + list(state.get("hits", []))
    verdict, cov = ans.verify(a, pool)        # 引用覆盖率对账
    if verdict == "pass" and not _derived_ok(state.get("derived"), pool):
        verdict = "degraded"                   # 派生值出口重算
    if verdict == "pass":
        ...
    elif verdict == "refused":
        return refuse(...)                     # 无据 → 拒
    else:
        body, cited = ans.extractive_answer(state, state["hits"])
        # degraded：降级抽取式（永远有真凭实据），不是打回重写
    ```

    **覆盖率口径四规则**（citation_coverage 的名实相符）：只考核
    **数字句**（框架句不要求重叠——否则 LLM 行文被误杀）；两侧
    剔**元词**（公司名/年份/期间——数字与指标词才是证据相关性）；
    **换算注释计入证据**（LLM 答「6.44亿」而非原文全数字，第 3
    章的注释在这接上）；**证据池 = 被引块 ∪ hits**（抽取式从
    hits[:8] 抽句，第 5–8 名块支撑的句子若不计入池，自家答案被
    自家 verify 误判——**验证器和被验物必须看同一个世界**）。

    **派生值出口重算**（`_derived_ok`）：单季差分 Q2=H1−Q1 的答案，
    操作数必须**真在场**于证据池且 |a−b−value| ≤ 0.01——禁止模型
    心算的落点（封闭世界里算术也是事实；原币精度算，亿值四舍
    五入差分会到百万级误差）。

    **阈值两极端实测**（innolight 31 题，2026-10-22，两极端法的
    完整现场）：

    | 阈值 | coverage | answer_hit | 课 |
    |---|---|---|---|
    | 0.0（放行）| 1.000 | 1.0 | heuristic 下无症状——**危险潜伏**：LLM 路径上编造但挂引用的答案会畅通（v0.7.1 远端实测：glm-5.3 两道 compare 正是被 0.45 拦下）|
    | 0.45（基线）| 1.000 | 1.0 | 合格分布 0.5–0.95、编造 <0.2，谷底取 0.45 |
    | 1.0（全拦）| 0.074 | **1.0** | 93% 降级抽取式仍全对——**降级=安全失败**：惩罚形态不惩罚正确性 |

    **五层口径防线**（7.2 三层框架的实例化；全表与六对注释见
    附录 D）：①stitch 拼块（标签/数值重接）→ ②行级抽取（指标词
    后首大数+前邻 20 字口径检查）→ ③配对降权 ×6 对（问扣非时
    归母句 ×0.3，降权不跳过）→ ④caliber_mismatch 数值闸（问具名
    口径，大数必须在该口径标签行，D22——gate≠correctness 的第一
    处收口）→ ⑤forbid_keywords（评测反断言，第 13 章）。
    **泛化证据**：第二家公司（贵州茅台）十份文档入语料，9 题
    **零调参**全对——防线按标签行工作，公司无关；新口径家族的
    成本 = 一条降权 + 一道 forbid 题（修一台新电梯，不是重盖楼）。

    **LLM 裁判**（`_self_check`）只在 trend 叙述层且非对称信任：
    只能否决（sensitive 剥句不重写；不忠实有界修复 1 次再退
    骨架），永远在确定性闸门之后——judge 省的是叙述层的坏句子，
    碰不到事实层的错数字。

### 演练：画你自己的阈值分布图

两极端法的第三步需要一张真实的分布图（数据 = 你的真值集跑一次
带判分的 eval）：

```text
把每题的对账分数（0~1）按答案质量分两色画数轴：
  合格答案（人工确认对）：● ●●  ●●●●     ●●●     ●●
  编造/降级候选：   ○○  ○
  0.0    0.2        0.5      0.7    0.95   1.0
                ↑ 两峰之间的谷 = 阈值候选（案例取 0.45）
```

三条判读规则：两峰重叠区大 → 你的判分器区分力不够（先改判分
口径再谈阈值）；合格峰左尾拖太长 → 抽查左尾样本，通常是「正确
但表述特殊」的题——要么改归一化，要么认赔（记进边界账本）；
分布随模型换档整体平移 → **阈值跟着换档重标**（它属于「模型×
语料」的乘积，不是系统常数）。

## 7.5 小结

- 三路线取舍：事后归因闸与生成器解耦（验证器≠生成器的同一个
  大脑）；NLI 语义细但带方差与领域盲区；
- judge 三类系统偏差（位置/冗长/自增强）→ veto-only + 永远在
  确定性闸之后；guardrails 管话题、闸门管事实，互补不互替；
- 降级不是重试——降级产物结构上不可能编造；阈值两极端法：
  0.0 验证防御路径、1.0 验证降级下限、分布取谷、回归锁定；
- 盲区是实体粒度混淆（语义越近越难分）：打分抑制/行级校验/
  评测反断言三层自建；gate ≠ correctness——管不到的显式声明
  或入账本。

## 常见误区

**误区一：「verify 是锦上添花」。**没有出口验证的系统把正确性全
押在生成层自觉上——自觉是 prompt，换模型就变天。verify 把正确性
从概率问题变成结构问题。

**误区二：「闸门没拦住 = 闸门没用」。**粒度混淆是所有「证据在场」
型闸门的共同边界——正确反应是加领域守卫层 + 诚实记录管不住什么，
不是拆闸门。

**误区三：「阈值抄同行的」。**阈值是分布的函数，分布是你的语料
×你的生成器的乘积。两极端法三步，一个下午就能跑出自己的谷底。

**误区四：「judge 能修答案」。**judge 有偏差清单，只配坐刹车位。
能修答案的是降级（确定性产物），不是再生成一次。
