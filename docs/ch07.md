## 7.1 失败先行：两个极端，两堂课

把 `tally/answer.py` 的 `COVERAGE_THRESHOLD` 调成两个极端，各跑一遍
innolight 31 题（2026-10-22 实测，heuristic 模式）：

| 阈值 | citation_coverage | answer_hit | 解读 |
|---|---|---|---|
| 0.45（基线）| 1.000 | 1.0 | 正常 |
| **0.0**（什么都放行）| 1.000 | 1.0 | **与基线完全相同！** |
| **1.0**（近乎全拒）| **0.074** | **1.0** | 93% 答案降级，但答案仍然全对 |

- **阈值 0.0 在 heuristic 下毫无症状**——抽取式答案本来就 grounded，
  闸门形同虚设也不出事。危险是**潜伏的**：LLM 生成路径上，一个编造
  但挂了引用的答案会畅通无阻（7.4 的口径灾难全回来）。**启示：闸门
  的价值要在它防的那条路径上测**——这句线在 v0.7.1 的远端实测里
  得到了实弹证明：glm-5.3 生成的两道 compare 题正是被 0.45 阈值打成
  degraded 降级抽取式、答案仍然全对（DESIGN-v0.7 §8.3）。
- **阈值 1.0 时 coverage 崩到 0.074 但 answer_hit 仍是 1.0**——93%
  的答案被降级成抽取式，而抽取式每句带引用、数字全来自原文，所以
  「丑但全对」。**降级 = 安全失败**的活教材：闸门收紧惩罚的是形态
  （pass 率），不是正确性。

0.45 本身不是玄学，是实测分布：合格答案的覆盖率聚在 0.5–0.95，
编造答案聚在 0.2 以下——0.45 在两峰之间的谷。**阈值是工程：由数据
分布决定，由回归测试锁定**（两极端法：先调 0.0 和 1.0 看指标怎么
崩，再从分布里找谷底）。

## 7.2 知识点：groundedness 三路线与三态出口

「怎么保证生成不编」的三条代表路线：

| 路线 | 代表 | 机制 | 代价 |
|---|---|---|---|
| 自反思 | [Self-RAG](https://arxiv.org/abs/2310.11511) | 模型生成反思 token 自评检索/生成质量 | 要微调；**自己批自己的卷子** |
| 纠错环 | [CRAG](https://arxiv.org/abs/2401.15884) | 检索评估器打分，差则重检/上网补 | 开放世界假设 |
| **事后归因闸** | Tally / AIS 工程化 | 生成后逐句对账证据池，不过则降级/拒答 | 需要独立验证器（本章）|

Tally 选第三条的深层理由：**验证器不能和生成器是同一个大脑**。
Self-RAG 让模型自评，等价于让学生批自己的卷子——模型犯错的相关性
会让自评跟着错。事后闸用确定性代码算覆盖率，与模型能力无关：
0.8b 也好、100b 也好、换了厂商也好，**闸门同一把尺子**。CRAG 的
「上网补」则违反封闭世界契约（第 1 章）——检索不到正确口径时，
降级到原文比补一个语义相近的网页安全。

三条路线之外还有一层**框架生态**：NeMo Guardrails、Llama Guard
（[arXiv:2312.06674](https://arxiv.org/abs/2312.06674)）把「规则
拦截 + 模型审查」做成对话/输出中间件——它们管**安全和话题边界**，
与出口闸门（管**事实对账**）互补不互替：guardrails 拦「不能说的话」，
verify 拦「说错的话」。

**三态出口**是事后闸的输出契约。一个可信系统的每个回答只能是三种
状态之一：

| 出口 | 含义 | 用户看到 | 什么时候发生 |
|---|---|---|---|
| pass | 覆盖率 ≥ 0.45 | LLM 组织的完整回答 | 生成对得上账 |
| degraded | 对不上账 | **证据池原句**（丑但真）| 引用漂移/编造/派生值对不上 |
| refused | 无证据可用 | 拒答 + 现有期间提示 | 检索空手/期间外/域外 |

拒答在这套语义里是**一等能力**（SQuAD 2.0 的学统，第 1 章已引）：
指名缺什么、列出现有什么、拒绝的代价为零。

![verify_citations 对账闸门](img/verify-gate.png)

*对账闸门全景（[▶ 动画版](anim/verify-gate.html)）：generate 的答案逐句拆分 → 对账证据池（被引 ∪ hits）→ 覆盖率裁决 → pass / degraded / refused 三态出口。*

## 7.3 本项目：verify_citations 与覆盖率口径

verify_citations 是**全图唯一出口**——heuristic 检索、Agent 自主
检索、记忆命中、差分派生，任何路径都必须过它：

```python
# tally/graph.py: verify_citations（骨架）
    pool = list(state.get("evidence") or []) + list(state.get("hits", []))
    verdict, cov = ans.verify(a, pool)          # 引用覆盖率对账
    # 派生值出口对账：登记的派生数按证据池重算，操作数必须真在场
    if verdict == "pass" and not _derived_ok(state.get("derived"), pool):
        verdict = "degraded"
    if verdict == "pass":
        ...
    elif verdict == "refused":
        return refuse(...)                       # 无据 → 拒
    else:
        body, cited = ans.extractive_answer(state, state["hits"])
        # degraded：降级为抽取式（永远有真凭实据），不是打回重写
```

**degraded 的关键设计：降级不是重试。**为什么不把答案打回模型改写？
①小模型会把同一件事编得更圆（重试=二次编造机会）；②错在检索/证据
层时，重写生成治不了根；③抽取式答案结构上不可能编造——每句带引用、
每个数字来自原文。**可靠性由结构保证，不靠模型自觉。**

`citation_coverage` 的口径（`tally/answer.py`）四条规则：

1. **只考核数字句**——框架句（「根据提供的证据…」）不要求重叠，
   否则 LLM 的行文结构会被误杀；
2. **两侧剔除元词**（公司名/年份/期间）——数字与指标词才是证据
   相关性（与 extractive 打分同口径）；
3. **数字归一化注释计入证据**——LLM 常答「6.44亿」而非原文全数字
   （第 3 章的注释在这里接上）；
4. **证据池 = 被引块 ∪ hits**（页窗口扩展到整页）——extractive 从
   hits[:8] 抽句，第 5–8 名块支撑的句子若不计入池，自家答案会被
   自家 verify 误判（实测教训）。**验证器和被验物必须看同一个世界。**

派生值另有出口重算（`_derived_ok`）：单季差分 Q2=H1−Q1 的答案，
操作数必须**真在场**于证据池且 |a−b−value| ≤ 0.01——「禁止模型
心算」的落点（算术也是事实，第 11 章 derive 工具再展开）。

## 7.4 口径防线（一）：verify 管不住的那道缝

第 7.3 节的闸门有一道缝，具体长这样：

```
问：中际旭创 2025Q1 扣除非经常性损益后的净利润
答：归属于上市公司股东的净利润 1,582,876,128.67 元
    [中际旭创_2025Q1 第3页]          ← 引用真实、页码正确
verify：覆盖率 0.529 → pass ✓        ← 闸门说没问题
真值：1,568,385,287.19               ← 差了整整一个口径
```

数字真在证据池、真有出处——闸门管「有出处」，不管「对题」。这类
错误有个统一的名字：**口径混淆（caliber confusion）**。更扎心的是：
**语义检索越好，这种错越严重**——归母和扣非在向量空间里几乎贴着
（都是净利润！）。第 5 章 D19 消融的被害题恰好全是口径题，不是巧合
：语义相近恰恰是口径任务的风险源（BEIR 的账：BM25 在精确匹配任务
上稳健，[arXiv:2104.08663](https://arxiv.org/abs/2104.08663)——
同一个现象的学界版本）。

口径问题为什么没有现成轮子：

| 近邻问题 | 业界常规解法 | 为什么不够用 |
|---|---|---|
| 实体消歧 | NER + entity linking | 消歧「贵州茅台（公司）」≠ 区分「归母/扣非（指标）」|
| 属性对齐 | Table QA | 假设问题直指表格行，兜不住叙述句 |
| 元数据过滤 | 向量库 filter | 过滤文档级，不滤句级口径 |
| Prompt 约束 | few-shot 提醒 | 生成层自觉，不被信任为边界 |

**口径守卫是领域自建的空白区**——这既是本章的存在理由，也是你
迁移到其他领域的机会清单。

## 7.5 口径防线（二）：五层防线全表

![口径五层防线](img/caliber.png)

*五层防线与冒充者（[▶ 动画版](anim/caliber.html)）：问扣非时归母来冒充——拼块/行级/配对降权/数值闸/评测 forbid 逐层拦截（✕ 处）。*

Tally 的答案是五层防线，每层对应一类实测越界：

| 层 | 位置 | 防什么 | 代价 |
|---|---|---|---|
| ① stitch_adjacent 拼块 | 检索后 | 标签与数值分家——拼不回去连「选哪行」都无从谈起 | 块变长 |
| ② 行级抽取+标签上下文 | trend pick | 「指标词后第一个大数」+前邻 20 字口径检查 | —— |
| ③ 配对口径降权 ×6 对 | answer.py | 问 X 时同胞指标 Y 的句子 ×0.3 | 规则维护 |
| ④ caliber_mismatch 数值闸 | graph.py（D22）| 问具名口径→答案大数必须在该口径标签行里，否则降级 | 误杀风险 |
| ⑤ forbid_keywords | evals/*.json | 评测层反向断言：问扣非的答案不得出现归母的数 | —— |

第③层的六对「家族降权」，注释本身就是案例库（节选两对）：

```python
# tally/answer.py（节选——注释即实测档案）
# ① 问扣非：无「扣除/扣非」的净利润句是归母口径（茅台 2026H1 实测
#    445.17 亿散文句顶掉 44,464,207,646.01）
if (("扣非" in q_raw or "扣除非" in q_raw)
        and "净利润" in s and "扣除" not in s and "扣非" not in s):
    score *= 0.3
# ③ 问总收入：营业收入句是子口径不是总口径（真值 92,278,072,083.21
#    被营业收入行冒充，2026H1 p30）
if "总收入" in q_raw and "营业收入" in s and "总收入" not in s:
    score *= 0.3
```

两个设计取舍值得抄：**降权不跳过**（×0.3 而非 continue）——双口径
问句（「扣非和归母差多少」）仍要看到对方；**注释里带实测数字**——
每对降权都能溯源到一次真值集失败。第④层（D22 数值闸）是「gate ≠
correctness 的第一处收口」：把「数字在场」升级成「数字在正确的行
里」。第⑤层把防守知识共享给评测：

```json
{
  "q": "中际旭创 2025 一季度扣除非经常性损益后的净利润多少",
  "expect_keywords": ["1,568,385,287"],
  "forbid_keywords": ["1,582,876,128"]
}
```

答案出现 forbid 的数（归母姊妹值）→ 一票否决。**防守和评测共用同一
套口径知识**——单测层的负向断言上移到 eval 层，成为每次 CI 都跑的
防线（「评测即测试」的微观样本，第 13 章宏观展开）。

## 7.6 口径防线（三）：泛化的诚实

六对降权是两家公司语料（中际旭创+贵州茅台）喂出来的。第三家会带来
新家族吗？会。但有两层兜底：

1. ④层口径闸按「标签行验证」工作，**不依赖具体公司**——它对第 N
   家公司同样生效；
2. 每对新家族的成本 = 一条降权 + 一道 forbid 题——**修一台新电梯，
   不是重盖楼**。

**最好的证据是茅台零调参 9/9**：新公司十份文档进语料，九道真值题
全对，没改一行检索代码——D20–D22「多公司泛化」批在第二家公司上
一次性验收。这也是面试里回答「你这套换家公司还行不行」的王牌。

!!! example "迁移盒：医疗指南的「口径」是什么"

    - **语料差异**：临床指南/药品说明书里，「口径」= 同一指标的
      干预层级与人群分支——「推荐剂量」vs「最大日剂量」、「成人」
      vs「肾功能不全者」、「肌酐」vs「尿素氮」（语义近、语义价值
      不同）。
    - **哪个决策因此改变**：③层降权家族要重定义（剂量 vs 极量、
      人群限定词）；④层数值闸的「标签行」变成「剂量表行 + 人群列」；
      ⑤层 forbid 换成「问最大剂量不得出现常规剂量数值」。
    - **Tally 哪个机制对应**：五层骨架原样——换的是词对家族与标签
      行定义，不是结构。医疗域错误代价更高，⑤层评测反断言应该是
      监管审计的第一道交付物。

## 7.8 前沿拓展：faithfulness 的度量谱系与 judge 的脾气

本章的闸门给了「有出处」的硬保证；这一节把它放回业界度量谱系。

**RAGAS 四指标 vs Tally 七指标**（[RAGAS, arXiv:2309.15217](
https://arxiv.org/abs/2309.15217)——无参考评估的代表）：

| 问题 | RAGAS | Tally |
|---|---|---|
| 答案被证据支撑吗 | faithfulness：答案拆 claims，逐条 NLI 蕴含判定（裁判模型） | `citation_coverage`：数字句 token 重叠（确定性代码） |
| 检索捞到对的了吗 | context precision / recall | `chunk P/R@8`（真值承载块） |
| 答案回应问题了吗 | answer relevancy（反向生成） | `answer_hit` + `forbid` 一票否决 |
| 该拒的拒了吗 | ——（不测） | `refusal`（陷阱题一等指标） |

取舍：无参考便宜、可大规模跑，但**裁判模型自带方差**；领域真值贵
（人工对库核对），但能抓住「扣非句真在池里、问的却是归母」——NLI
裁判看不出这个缝隙（7.4 的缝在 RAGAS 同样存在）。Tally 的选择不是
「更原始」，是**换掉了裁判**：确定性代码替代 NLI 模型——方差归零，
代价是量尺更粗。指标名也由此改过一次：`faithfulness →
citation_coverage`——它测引用对账，不测语义忠实。

**LLM-as-judge 的脾气清单**（[MT-Bench, arXiv:2306.05685](
https://arxiv.org/abs/2306.05685)）：强 judge 与人一致率可超 80%，
但有三类**系统性偏差**——位置偏（先看的答案占优）、冗长偏（长的赢）、
自增强偏（偏爱自己风格的输出）。工程结论不是「别用 judge」，是
**别给 judge 油门**。`_self_check` 的非对称信任是这个结论的闸门版：
只能否决不能解锁（sensitive → 剥句不重写；不忠实 → 有界修复 1 次 →
退骨架）；judge 跑在确定性闸门**之后**——它省的是叙述层的坏句子，
永远碰不到事实层的错数字。

**若在 Tally 上继续做**：把 RAGAS 式语义 faithfulness 当**离线诊断**
而不是在线闸门——对边界账本（第 14 章）的 verify:pass 但语义可疑
样本批量跑 NLI 蕴含，看能捞出多少闸门缝隙。度量的下游是「边界账本
再收口」，不是「换掉闸门」：语义判据有方差，进 CI 会抖。

## 7.9 小结

- 三态出口：pass / degraded（抽取式兜底）/ refused（明说没有）——
  全路径唯一闸；降级不重试；
- 覆盖率四口径：数字句/剔元词/含注释/池=被引∪hits；阈值由分布定、
  回归锁；两极端实测：0.0 潜伏无感、1.0 全降级仍全对；
- verify 管「有出处」，不管「对题」——口径是那道缝；
- 五层口径防线：拼块/行级/降权/数值闸/评测 forbid；降权不跳过、
  注释带案例；茅台零调参 9/9 是泛化证据。

## 常见误区

**误区一：「verify 是可选的锦上添花」。**没有 verify 的 RAG 把
「答案对不对」全部押在生成层自觉上——而自觉是 prompt，换模型就
变天。verify 是把正确性从概率问题变成结构问题的那道门。

**误区二：「阈值可以抄别人的」。**覆盖率阈值取决于**你的**分布——
合格答案和编造答案在你的语料、你的生成器下聚在哪里，只有实测能
回答。Tally 的 0.45 是两峰之间的谷；你的谷可能在 0.3 或 0.6。抄
阈值的本质是抄别人的分布。

**误区三：「口径问题在 prompt 里提醒一句就行」。**「注意区分归母
和扣非」能降低频率，不能建立边界。口径要修在**检索打分层**（降权）、
**数值校验层**（标签行验证）、**评测层**（forbid），prompt 只是第一道
便宜的门帘。

**误区四：「这是财报域的特殊问题」。**口径的学名是「同族实体/属性
的粒度混淆」，每个领域都有自己的版本（医疗：肌酐 vs 尿素氮；法务：
原告 vs 上诉人；电商：GMV vs 净销售额）。识别方法相同：找「语义
相近而语义价值相反」的词对家族。
