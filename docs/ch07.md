## 7.1 失败先行：一个空格毁掉的合格答案

小模型生成答案时会手写引用，格式会漂：`[中际旭创_2025FY 第8页]`
（粘连）、`[中际旭创_2025FY 第 8 页]`（多空格）。verify 用精确子串
匹配引用——**有据答案被判 degraded**，对比结论句被抽取式顶掉
（2026-10-19 llm 实测 cov=0.8 仍 degraded）。修复是空白归一：

```python
# tally/answer.py
def _cite_norm(s: str) -> str:
    """引用匹配的空白归一（D13）：小模型手写引用的空格会漂移……
    剥尽空白再比，引用语义（doc+页）不变。"""
    return re.sub(r"\s+", "", s)
```

第 2 章的教训在此复现：**文本相等性判定，永远先定义归一化。**
PDF 抽取和 LLM 手写是同一个问题的两副面孔。

## 7.2 grounded 生成的契约

generate 的 prompt 只有三条硬规矩：

1. 每个事实句**必须**带 `[公司_报告期 第N页]` 引用；
2. 证据池里没有的，答「原文中没有找到依据」——不许推理补全；
3. 数字原样引用，不许换算（换算由摄取层的归一化注释负责，第 3 章）。

注意职责切分：模型负责**语言组织**（把证据句组织成通顺回答），
不负责**事实裁决**——那是下一章 verify 的工作。生成层的自觉
（prompt 约束）从来不被信任为安全边界，它只是降低 verify 的工作量。

## 7.3 证据组装：页级窗口与表块拼接

送进生成的证据池怎么组（`tally/graph.py`）：

- **page_evidence**：small-to-big——检索命中 chunk 所在页的 ±2 兄弟
  块一起进池（表格行常被切在相邻块，只给单行模型读不懂列结构）；
  首命中页分层取窗（union-window 实测净负：上下文稀释）；
- **stitch_adjacent**（D16）：同页「标签块 + 数值块」拼接——PDF 抽取
  常把 `归属于上市公司股东的扣除非经常性损益的净利润（元）` 和
  `1,568,385,287.19` 切成两块，不拼回去抽取式永远选不出完整证据；
- **front_key_table**：metric 意图把「主要会计数据」表页前置——
  真值行词面打不过「页眉块」（页眉含公司名+期间，词面完美匹配），
  实测被挤出 top-8。

三个组件都是**实测教训的沉淀**，不是先验设计——这也是全书反复
出现的模式：先跑真值集，让失败告诉你下一行代码写什么。
