## 7.1 失败先行：一个空格毁掉的合格答案

小模型生成时会手写引用，格式会漂：`[中际旭创_2025FY 第8页]`（粘连）、
`[中际旭创_2025FY 第 8 页]`（多空格）。verify 精确子串匹配——
**有据答案被判 degraded**（llm 实测 cov=0.8 仍 degraded）。修复：

```python
# tally/answer.py
def _cite_norm(s: str) -> str:
    """引用匹配的空白归一（D13）……剥尽空白再比，引用语义（doc+页）不变。"""
    return re.sub(r"\s+", "", s)
```

第 2 章的教训在此复现：**文本相等性判定，永远先定义归一化。**

## 7.2 业界视角：引用与归因的形态

!!! note "背景速览"

    「生成时带出处」在业界有三种形态：

    | 形态 | 代表 | 出处粒度 |
    |---|---|---|
    | 文档级 | 早期 RAG 应用 | 「参考了这 3 篇」 |
    | 句/段级内联引用 | Tally、Bing/Copilot 类产品 | 每个事实句挂来源 |
    | 引用评测基准 | [ALCE](https://arxiv.org/abs/2305.14627)（citation F1 等）| 评测层 |

    学术标准是 AIS 框架（[arXiv:2112.12870](https://arxiv.org/abs/2112.12870)）：
    归因的判定单元是「陈述—来源」对，一个知情读者能否同意
    「根据 s，z 成立」。Tally 的工程化选择：**句级内联引用
    `[公司_报告期 第N页]`**——粒度细到页，verify 才有可计算的
    对账面（下一章）；页码来自抽取时的元数据，不靠模型回忆。

## 7.3 grounded 生成的契约

generate 的 prompt 只有三条硬规矩：

1. 每个事实句**必须**带 `[公司_报告期 第N页]` 引用；
2. 证据池里没有的，答「原文中没有找到依据」——不许推理补全；
3. 数字原样引用，不许换算（换算由摄取层归一化注释负责，第 3 章）。

职责切分：模型负责**语言组织**，不负责**事实裁决**——生成层的
自觉（prompt 约束）从不被信任为安全边界，它只降低 verify 的工作量。

## 7.4 证据组装：页级窗口与表块拼接

- **page_evidence**：small-to-big——命中 chunk 所在页 ±2 兄弟块进池
  （表格行常切在相邻块，单行读不懂列结构）；首命中页分层取窗
  （union-window 实测净负：上下文稀释）；
- **stitch_adjacent**（D16）：同页「标签块 + 数值块」拼接——PDF 抽取
  常把 `归属于上市公司股东的扣除非经常性损益的净利润（元）` 和
  `1,568,385,287.19` 切成两块，不拼回去抽取式永远选不出完整证据；
- **front_key_table**：metric 意图把「主要会计数据」表页前置——
  真值行词面打不过页眉块（页眉含公司名+期间，词面完美匹配），
  实测被挤出 top-8。

三个组件都是**实测教训的沉淀**——全书反复出现的模式：先跑真值集，
让失败告诉你下一行代码写什么。这组技术业界常被归入
context engineering（上下文工程）：检索到 ≠ 送进去，**送什么、
按什么顺序送**同样是检索质量的一部分。
