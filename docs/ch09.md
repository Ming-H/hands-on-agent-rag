# 第 9 章 口径守卫：问扣非为什么不能答归母

> 状态：v0.2 · 所属：第二部 求证闸门 · 前置：第 8 章

## 9.1 失败先行：verify:pass(0.529) 的错答案

第 8 章的缝隙具体长这样：问「扣除非经常性损益后的净利润」，系统答
了归母净利润 `1,582,876,128.67`——数字真在证据池、真有出处，覆盖率
0.529，verify 判 pass。闸门管「有出处」，不管「对题」。

这类错误有个统一的名字：**口径混淆**。而且语义检索越好，这种错越
严重——归母和扣非在向量空间里几乎贴着（都是净利润！）。回想第 5 章：
D19 消融的被害题恰好全是口径题，这不是巧合。

## 9.2 业界视角：口径问题为什么没有现成轮子

!!! note "背景速览"

    口径（caliber）是财经领域的土话，学界近邻是这几个问题：

    | 近邻问题 | 业界常规解法 | 为什么不够用 |
    |---|---|---|
    | 实体消歧 | NER + entity linking | 消歧「贵州茅台」≠ 区分「归母/扣非/总额」|
    | 属性对齐 | Table QA（TAPoS 类）/ 表格骨架 | 假设问题直指表格行，兜不住叙述句 |
    | 元数据过滤 | 向量库 filter（Weaviate/LangChain filters）| 过滤文档级，不滤句级口径 |
    | Prompt 约束 | few-shot「注意区分口径」 | 生成层自觉，不被信任为边界（第 7 章）|

    结论：**口径守卫是领域自建的空白区**——这既是本章的存在理由，
    也是你把这套方法论搬到自己领域时的机会：找到你的语料里
    「语义相近而语义价值相反」的词对家族，就是你的口径清单。

## 9.3 五层防线：从拼块到评测

| 层 | 位置 | 防什么 |
|---|---|---|
| ① stitch_adjacent 拼块 | 检索后 | 标签与数值分家——拼不回去连「选哪行」都无从谈起 |
| ② 行级抽取 + 标签上下文 | trend pick | 「指标词后第一个大数」+ 前邻 20 字口径检查 |
| ③ 配对口径降权 ×6 对 | answer.py | 问 X 时同胞指标 Y 的句子降权 0.3× |
| ④ caliber_mismatch 数值闸 | graph.py（D22） | 问具名口径→答案大数必须在该口径标签行里，否则降级 |
| ⑤ forbid_keywords | evals/*.json | 评测层反向断言：问扣非的答案不得出现归母的数 |

第③层的六对「家族降权」，注释本身就是案例库：

```python
# tally/answer.py（节选——注释即实测档案）
# ① 问扣非：无「扣除/扣非」的净利润句是归母口径（茅台 2026H1 实测
#    445.17 亿散文句顶掉 44,464,207,646.01）
if (("扣非" in q_raw or "扣除非" in q_raw)
        and "净利润" in s and "扣除" not in s and "扣非" not in s):
    score *= 0.3
# ③ 问总收入：营业收入句是子口径不是总口径（真值 92,278,072,083.21
#    被营业收入行冒充，2026H1 p30）
if "总收入" in q_raw and "营业收入" in s and "总收入" not in s:
    score *= 0.3
```

设计取舍：**降权不跳过**——双口径问句（「扣非和归母差多少」）仍要
看到对方。规则惩罚「冒名顶替」，不惩罚「同场出现」。

## 9.4 第⑤层：评测层的负向断言

```json
{
  "q": "中际旭创 2025 一季度扣除非经常性损益后的净利润多少",
  "expect_keywords": ["1,568,385,287"],
  "forbid_keywords": ["1,582,876,128"]
}
```

答案出现 forbid 的数（归母姊妹值）→ 一票否决。防守和评测共用同一
套口径知识——「评测即测试」的微观样本（第 12 章宏观展开）。

## 9.5 泛化的诚实：第三家公司要修多少规则？

六对降权是两家公司语料喂出来的。第三家会带来新家族吗？会。但两层
兜底：④层口径闸按「标签行验证」工作，不依赖具体公司；每对新家族
只需一条降权 + 一道 forbid 题——**修一台新电梯，不是重盖楼**。茅台
零调参 9/9 是这个论断最好的证据（新公司进语料，九道真值题全对，
没改一行检索代码）。
