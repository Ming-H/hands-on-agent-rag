## 13.1 知识：评测三代与「评测什么会骗你」

| 代 | 方法 | 代表 | 取舍 |
|---|---|---|---|
| 人工/规则 | 关键词、精确匹配 | 传统 IR 的 P/R | 零成本可解释；覆盖窄 |
| 框架指标 | 检索/生成/忠实分项 | [RAGAS](https://docs.ragas.io)、[TruLens](https://www.trulens.org) | 全面、无需人工真值；**裁判模型自带方差** |
| 领域真值集 | 人工核对答案 + CI 门槛 | 业务 golden set | 最可信；搭建贵 |

框架指标属于「无参考评估」（reference-free）：RAGAS 的
faithfulness 把答案拆成 claims 逐条判蕴含、context precision/recall
量检索质量；TruLens 用类似思路做反馈函数。它们便宜、可大规模跑，
但有两条边界：裁判模型有方差（同一答案两次打分不同）；语义级
判定看不出**领域性错误**——「问扣非答归母」在通用 faithfulness
下可能满分（两个数都在上下文里）。领域真值集贵（人工对库核对），
但它是唯一能抓住领域错误的尺子。业界方法论的代表是 Hamel
Husain 的 [*Your AI Product Needs Evals*](https://hamel.dev)：
**领域专属评测集 + 错误分析驱动迭代**，比通用基准重要——你的
用户不问 MMLU，问你领域的问题。

**评测自己会骗人。三种假绿**（指标全绿但系统有病）：

| 假绿 | 形态 | 现形 |
|---|---|---|
| 模式方差 | 评测悄悄走了带方差的路径（如 auto 选到 LLM），回归对不上基线 | 锁定确定性模式（规则模式）跑对照 |
| 记忆虚高 | 反复跑同批题，记忆把上轮答案记住了——检索指标测的是命中不是检索（第 12 章）| 评测默认隔离记忆，对照显式开闸 |
| 门槛缺位 | 指标掉了 CI 依然全绿——评测恒成功退出，是仪表盘不是防线 | 门槛通电实验（13.3）|

**评测统计学一句级**（展开见 agent-book ch.7）：20 题的评测集上
一题之差就是 5 个点——小评测集的波动先问样本量（二项置信区间
多宽），再问系统变化；「A 比 B 高 5 个点」在 n=20 上可能毫无
意义。真值集要么做大，要么对结论保持谦逊。

**eval 驱动开发**：每个设计决策先有失败样本，再写修复——没有
失败样本的优化是盲调；失败样本入库，优化才有靶子。

## 13.2 知识：评测 harness 四件套与线上漂移

把任何评测系统拆开，骨架都是四件：

| harness | 领域 | 四件套实例 |
|---|---|---|
| [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness) | 基础模型基准 | 数百 task 注册表 / 模型后端统一接口 / per-task 指标 / 版本钉死可复跑 |
| [HELM](https://crfm.stanford.edu/helm/) | 全维评测 | 场景（任务×分布）/ 适配器 / 多维指标 / 排行榜可复现 |
| [SWE-bench](https://arxiv.org/abs/2310.06770) | 真实仓库修复 | 真实 issue+PR / agent 输出→测试 / 通过率 / docker 锁环境 |
| 你的评测 | 领域 RAG | 真值集 / 图后端可切换 / 指标+门槛 / CI 同口径复跑 |

**任务集 + 适配器 + 指标 + 可复跑**——先有任务集（你的领域
问题），被测系统通过适配器接入，指标必须名实相符，一切为了
可复跑（CI 同口径 = 评测自己的评测）。你的毕业设计（第 14 章）
交的就是这四件。

**线上漂移**：语料在长、问句分布在变、模型服务商悄悄换版——
离线真值集测不到线上分布。最低配监控三件：问句日志抽样回放进
评测；verdict 分布看趋势（degraded 占比升高 = 生成/检索在退化）；
浪费率看趋势（agent 环在变懒或变笨）。附录 G 回到生产侧。

**真值集设计四要素**：

1. **真值纪律**：期望值人工核对到精确位（多源交叉验证），不是
   「大概对」——真值错一题，整条防线错位；
2. **陷阱题**：应拒答的问题（期间外/域外/语义陷阱）——**拒答
   正确率是一等指标**（SQuAD 2.0 学统，第 1 章）；
3. **反向断言**（forbid）：答案不得出现已知错误值——问扣非的
   答案不得出现归母的数（第 7 章口径防线的评测面）；
4. **N/A 的诚实**：无陷阱题的数据集拒答指标记「不适用」不记
   0——「不适用」和「零分」是两回事。

## 13.3 案例研究：Tally 的 evalx 与门槛通电

!!! note "案例研究：Tally（evalx.py / cli.py）"

    **七数据集 84 题**（default 10 / innolight 31 / maotai 9 /
    agent 8 / multihop 8 / quarters 8 / multiturn 10 轮），全部
    人工对库核对。七指标：retrieval@3 / answer_hit / refusal /
    citation_coverage / chunk P/R@8 / steps（waste_rate）。指标
    名实相符改过名：faithfulness → citation_coverage（它测引用
    对账，不测语义忠实——名字吹的牛会被 RAGAS 用户拆穿）。

    **judge 演进史（量尺也会说谎的三轮）**：v1 OR 子串——关键词
    「3.6」子串命中 13.68，分数虚高；v2 左右禁数字粘连——innolight
    掉到 0.963 **门槛当场红**，定位出「前缀截断约定」（真值
    51.7 对答案 51.71——右边界一禁误杀真值）；v3 只守左边界
    （假命中全在左侧粘连，右侧延续恰是截断约定）。教学价值：
    **没有门槛，你连自己的量尺坏了都不知道**——量尺 bug 和系统
    bug 只有门槛能区分。

    **门槛通电**：`gate_failures` 纯函数 + `--min-*` 低于即
    `sys.exit(1)`，CI 四处 eval 全挂 1.0 门槛。实测记录：门槛
    通电当天就抓到一次真实回归（0.963）。坑一枚：期望关键词是
    OR 语义的备选组——只改坏其中一个，其余照样命中，门槛纹丝
    不动；要触发必须报废整组。

    **LLM 裁判**只在 trend 叙述层、且非对称信任（只能否决，
    MT-Bench 偏差清单的工程落地，第 7 章）。

## 13.5 小结

- 三代评测：无参考评估便宜但看不住领域错误；领域真值集贵但
  是唯一能抓住口径混淆这类错的尺子；
- 三种假绿（模式方差/记忆虚高/门槛缺位）各有现形实验——评测
  工程的大半就是让这三种绿消失；
- 量尺会自己说谎（judge 演进史）：量尺 bug 和系统 bug 只有门槛
  能区分；评测集要懂统计（n=20 上一题=5 个点）；
- 评测 harness 四件套：任务集+适配器+指标+可复跑；线上漂移靠
  抽样回放 + verdict/浪费率趋势；
- eval 驱动开发：先有失败样本，再写修复。

## 常见误区

**误区一：「有了 RAGAS 就不需要自建评测」。**通用 faithfulness
看不出「扣非答归母」（两个数都在上下文里）。框架是补充不是
替代。

**误区二：「LLM-as-judge 更先进」。**judge 是另一个 LLM，有自己
的分布、盲区与三类系统偏差——评测层的可复现性比先进性重要。
judge 只配坐刹车位。

**误区三：「评测集建完就完了」。**真值集是活资产：每次事故入
一题，语料扩容抽验旧题；线上另有漂移监控——离线满分 ≠ 线上
正确。
