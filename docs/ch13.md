## 13.1 先立靶子：三种假绿

评测自己会骗人。本章先点名三种**指标全绿但系统有病**的形态——
每一种 Tally 都踩过，每一种都有现形实验：

| 假绿 | 形态 | 现形实验 |
|---|---|---|
| ① 模式方差 | plain `eval` 默认 auto——本地 Ollama 在线时静默走 llm，小模型方差混进指标，回归对不上基线 | 一律加 `--mode heuristic` 对照（heuristic 全集 1.00/1.00/1.00 是回归基线）|
| ② 记忆虚高 | eval 反复跑同批题，L1 台账记住了答案——retrieval 满分测的是记忆命中不是检索 | `TALLY_EVAL_MEMORY` 默认隔离；对照要显式 `on`（第 12 章 12.4）|
| ③ 门槛缺位 | 指标掉了 CI 依然全绿——eval 恒 exit 0，评测是仪表盘不是防线 | 13.2 的门槛通电实验 |

记住这三种形态再往下读：评测工程的大半内容，就是让这三种绿
消失。

## 13.2 失败先行：装饰性 CI 的解剖

本项目自己踩过的坑：CI 里跑了三个真值集 eval，看起来很严格——
直到有人问「指标跌到 0.3，CI 会红吗？」**不会**：`cmd_eval` 只打印，
永远 exit 0。CI 从「只防崩溃」到「防退化」，差一个非零退出码：

```python
# tally/cli.py: cmd_eval（修复后节选）
if any(v is not None for v in mins.values()):
    fails = gate_failures(summary, **mins)     # 纯函数，可单测
    if fails:
        print(f"✗ eval 门槛未过（dataset={args.dataset}）：\n  "
              + "\n  ".join(fails), file=sys.stderr)
        sys.exit(1)
```

`.github/workflows/ci.yml` 四处 eval 全挂 `--min-retrieval 1.0
--min-hit 1.0`。**门槛通电当天就抓到一次真实回归**（13.4 的 0.963）。
教训：没有门槛的评测是仪表盘，不是防线——仪表盘不会在深夜叫醒
任何人。



## 13.3 知识点：评测三代与 eval 驱动开发

| 代 | 方法 | 代表 | 取舍 |
|---|---|---|---|
| 人工/规则 | 关键词、精确匹配 | 传统 IR 的 P/R | 零成本可解释；覆盖窄 |
| 框架指标 | 检索/生成/忠实分项 | [RAGAS](https://docs.ragas.io)、TruLens | 全面；依赖 LLM 裁判，有方差 |
| 领域真值集 | 人工核对答案 + CI 门槛 | Tally 84 题 / 业务 golden set | 最可信；搭建成本高 |

Hamel Husain 的名文 [*Your AI Product Needs Evals*](https://hamelhusain.substack.com/p/evals)
主张：**领域专属评测集 + 错误分析驱动迭代**，比通用基准重要——
你的用户不问 MMLU，问的是你领域的问题。Tally 的 84 题就是这个
主张的实践。

本书全链践行的方法论是 **eval 驱动开发**：每个设计决策先有失败
样本，再写修复——D13 引用漂移先在 llm 模式现形、D19 向量消融先
跑出 1.00→0.83–0.93、D22 口径闸先有茅台散文句顶掉真值行。没有
失败样本的优化是盲调；失败样本入库（evals/*.json），优化才有靶子。

评测不止发生在 CI。**线上漂移**是部署后的问题：语料在长、问句
分布在变、模型服务商悄悄换版——离线真值集测不到线上分布。最低
配的监控三件：问句日志抽样回放进 eval、verdict 分布看趋势
（degraded 占比升高 = 生成层在退化）、waste_rate 看趋势（agent
环在变懒或变笨）。附录 G 生产清单会回到这里。

## 13.4 本项目：judge 的演进史——一学期踩完的坑

**v1：OR 子串。** `any(k in answer)`——关键词 `"3.6"` 能以子串命中
答案里的任何 `13.68`、`3.68`、页码日期。**评测在说谎**：分数
虚高，你据此做的所有决策都被污染。

**v2：左右都禁数字粘连。** 堵假命中——innolight 掉到 **0.963**，
门槛当场红。定位：关键词 `51.7`，答案 `51.71 亿元`——**数据集
约定是前缀截断**（`38,239` 对 `38,239,935,640`，`1,568,385,287`
对 `…287.19`），右边界一禁误杀过半真值题。

**v3（现状）：只守左边界。** 假命中实测全在**左侧**粘连（`3.6` 撞
`13.68`、`36,000` 撞 `136,000`）；右侧延续恰是截断约定：

```python
# tally/evalx.py: _kw_in
if re.search(r"\d", kw):
    return re.search(rf"(?<!\d){re.escape(kw)}", answer) is not None
return kw in answer
```

教学价值超过规则本身：**没有门槛的评测，你连自己的量尺坏了都
不知道**——v2 的误杀如果没有门槛，只会表现为「指标莫名掉了」，
大概率被当成系统回归去查检索层。量尺的 bug 和系统的 bug，
只有门槛能区分。

## 13.5 本项目：评测集设计四要素与七指标

`evals/*.json` 七个数据集、84 题（default 10 / innolight 31 /
maotai 9 / agent 8 / multihop 8 / quarters 8 / multiturn 10 轮）：

1. **真值纪律**：关键词是人工核对到分位的原文数字（与年报分季度
   表交叉验证），不是「大概对」——真值错一题，整条防线错位；
2. **陷阱题**（`expect_refused`）：期间外（2030）、域外（天气）、
   语义陷阱（「预计…多少」不是趋势）——**拒答正确率是一等指标**，
   一个不会说「不知道」的系统不值得信任；
3. **反向断言**（`forbid_keywords`）：第 7 章的口径负向断言——
   问扣非的答案不得出现归母的数；
4. **N/A 的诚实**：无陷阱题的数据集 refusal 记 None（打印 N/A）
   不记 0——「不适用」和「零分」是两回事（0 分会被未来 CI 门槛
   误判）。

七指标：retrieval@3 / answer_hit / refusal / citation_coverage /
chunk P/R@8 / steps（calls/dup/empty/waste_rate）。指标口径名实
相符：`faithfulness → citation_coverage`（它测引用对账，不测语义
忠实）。LLM-as-judge 只在 trend 叙述层用且**非对称信任**——只能
否决不能解锁（judge 的三类系统性偏差见第 7 章 7.8；裁判不比被
裁判者更可信，只给它刹车不给油门）。

## 13.6 知识点：评测 harness 的共同骨架

把 evalx 放回业界坐标——它是一个小号的**评测 harness**：

| harness | 领域 | 共同骨架的四件 |
|---|---|---|
| [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness)（EleutherAI）| 基础模型基准 | 任务集（数百个 task 注册表）/ 适配器（模型后端统一接口）/ 指标（per-task）/ 可复跑（版本钉死的配置）|
| [HELM](https://crfm.stanford.edu/helm/)（斯坦福）| 基础模型全维评测 | 场景（任务×分布）/ 适配器 / 指标（准确性/校准/鲁棒/公平…）/ 排行榜可复现 |
| [SWE-bench](https://arxiv.org/abs/2310.06770) | 真实仓库 issue 修复 | 任务集（真实 issue+PR）/ 适配器（agent 输出 → 测试）/ 指标（测试通过）/ 复跑（docker 锁环境）|
| **Tally evalx** | 领域 RAG 问答 | 真值集 84 题 / 图后端两种（heuristic/llm）/ 七指标 + gate_failures / CI 同口径复跑 |

四件套 = **任务集 + 适配器 + 指标 + 可复跑**。任何评测系统长出来
都是这四件——先有任务集（你的领域问题），再让被测系统通过适配器
接入（Tally 的适配器就是「图后端可切换」），指标必须名实相符，
最后一切为了可复跑（CI 同口径 = 评测自己的评测）。你的毕业设计
（第 14 章）交的就是这四件：20 题真值集 + 你的系统 + 三态出口
指标 + 可复跑脚本。

## 13.7 动手实验：门槛通电（实测）

亲手触发一次 CI 红灯。注意一个坑（作者亲踩）：第一题的
expect_keywords 是 **OR 语义的四个备选**（36,000 / 42,000 / 4.19亿
/ 3.6）——只改坏其中一个，其余三个照样命中，门槛纹丝不动。
**要触发必须报废整组关键词**：

```bash
bash experiments/ch13-gate-trip.sh
# 实测输出（2026-10-22）：
#   exit=1（预期 1）
#   ✗ eval 门槛未过（dataset=default）：
#     answer_hit=0.875 < 1.0
#     ✗ 欧科亿 2026 年半年度预计净利润多少  top1=欧科亿_2026H1E  kw=N doc=Y refused=N
#   还原后 exit=0 OK
```

改坏一道题 → 指标掉到 0.875 → 非零退出 + **指名道姓列出失败题**。
这个「单毁一个 OR 备选无效」的坑本身就是 13.4 judge 语义的现场
复习。

!!! example "毕业练习 ①：为你的语料写 20 题真值集"

    毕业设计（第 14 章）的第一块砖，现在就可以搬：给附录 F 画布里
    选定的语料写 20 题。配比：12 单跳（含 4 口径题）+ 4 陷阱
    （2 期间外 + 1 域外 + 1 语义）+ 2 对比 + 2 趋势。每题四字段：
    `q / expect_keywords（人工对到分位的原文数字）/ forbid
    （至少 4 题配）/ expect_refused（陷阱题）`。真值纪律：每个
    数字在原文里指得出页与行——你自己就是第 13.5 的「人工核对」
    那一环。产物 = 毕业设计四件套的任务集件。

## 13.8 小结

- 三种假绿：模式方差（heuristic 对照）/ 记忆虚高（eval 默认隔离）/
  门槛缺位（gate 通电）——评测工程就是让这三种绿消失；
- eval 恒 exit 0 的 CI 是装饰；门槛 = gate_failures 纯函数 + 非零
  退出，通电当天抓到真回归；
- 三代评测方法，领域真值集最可信也最贵；LLM-judge 只给刹车；
- judge 三版演进：OR 子串说谎 → 双侧禁误杀 → 只守左边界——量尺
  的 bug 和系统的 bug 只有门槛能区分；
- 评测 harness 四件套：任务集 + 适配器 + 指标 + 可复跑——evalx
  是它的小号实现，你的毕业设计交的也是这四件。

## 常见误区

**误区一：「有了 RAGAS 这类框架就不需要自建评测」。**框架指标
给你通用体温计，但你的用户问的是领域问题——扣非答归母在通用
faithfulness 下可能满分。领域真值集贵（人工核对）但它是唯一能
抓住领域错误的尺子；框架是补充，不是替代。

**误区二：「LLM-as-judge 更先进」。**judge 是另一个 LLM——它有
自己的分布、自己的盲区、自己的口径混淆。Tally 只在 trend 叙述层
用它，且**非对称信任**。关键词判定看着原始，但它确定性、可 diff、
可回归——评测层的可复现性比先进性重要。

**误区三：「评测集建完就完了」。**语料在长、问句分布在变。真值集
是活资产：每次事故入一题（Tally 的 D 编号事故大多伴着 eval 题），
每次语料扩容抽验旧题（指纹变了真值可能也变）。线上还要漂移监控
（13.3）——离线满分和线上正确是两件事。
