# 第 5 章 检索：双轨 FTS + RRF，以及「要不要 embedding」

> 状态：初稿 v0.1 · 所属：第一部 知识入库 · 前置：第 4 章
> ★ 本书最反共识的一章：词法饱和时，向量是净负贡献——用消融实验说话

## 5.1 失败先行：字轨整段短语的坑

v0.4 初版把字轨查询写成「空格整段短语」——`"预计净利润多少"` 作为
连续子串，在原文里**永远不存在**（被年份、标点隔开）。结果：答案块
在字轨零命中，RRF 融合后排序崩塌。教训后来写进了函数 docstring：

```python
# tally/fts.py: char_expr
def char_expr(query: str) -> str:
    """字级轨道：≥2 字词 token 做 trigram 短语 OR（子串命中，跨词边界）。
    不能用空格整段短语——「预计净利润多少」在原文里被年份隔开，
    整段短语永远不命中。"""
    segs = [char_text(t) for t in word_tokens(query)]
    segs = [s for s in segs if len(s) >= 2]
    return " OR ".join(_quote(s) for s in dict.fromkeys(segs))
```

**通用教训：换检索引擎时，查询语义的等价性要逐轨道验证，
不能只看接口签名。**

## 5.2 双轨设计：两条腿各补一个盲区

中文词法检索的两条失败路径，恰好各由一轨兜底：

| 失败路径 | 兜底的轨道 |
|---|---|
| 分词错误（专业术语被切碎） | **字轨**（trigram 子串命中，对分词免疫）|
| 词面鸿沟（问法 ≠ 写法） | **词轨 + 查询扩展**（营收→营业收入）|

词轨还做了一个小而关键的清洗——丢单字中文虚词（`word_expr`）：
「的/年/亿」这类 token idf 极低，进 MATCH 只会稀释排序。

融合不调权重，RRF 一律 k=60：

```python
# tally/fts.py: search（RRF 节选）
    for ranking in rankings:                    # 词轨 / 字轨 /（可选）向量
        for rank, row in enumerate(ranking, start=1):
            cid = row[0] if not isinstance(row, str) else row
            rrf[cid] = rrf.get(cid, 0.0) + 1.0 / (60 + rank)
```

排名互补是免费的鲁棒性——两轨都命中的块自然排前，单轨命中的
也不至于被埋掉。

## 5.3 重头戏：embedding 消融（D19）

教科书说 RAG 要上向量。Tally 完整实现了向量第三路（bge-small-zh
@ fastembed，512 维，同律 RRF），然后在 31 题人工核对真值集上做了
消融：

| 数据集 | 双轨 answer_hit | 向量三路 answer_hit |
|---|---|---|
| default 10 | **1.00** | 0.875 |
| agent 8 | **1.00** | 0.833 |
| innolight 31 | **1.00** | 0.926 |

三连 1.00 = 词法双轨在这个任务上**已饱和**——加第三路只可能持平或
变差。掉分机制值得细品：bge 的语义泛化把「同文档里语义相近但**口径
不同**」的块拉近，挤掉了本该精确命中的块——被害题恰好全是为口径
守卫修过的类型（年报营收、同比增长、归因句）。一句话：**在数字与
口径的精确匹配任务上，语义相近恰恰是风险而非收益。**

决策：**默认关闭，`TALLY_VEC=on` 显式 opt-in**。「用数据决定关掉
一个 feature」——这比「又接了一个向量库」的简历含金量高得多。

## 5.4 消融方法学（可以抄走的部分）

1. 固定对照组：heuristic 模式（零 LLM 方差）；
2. 人工核对到分位的真值关键词；
3. 一次只动一个变量（向量轨开/关）；
4. 指标不只看总分：被害题逐题分析（被害的都是哪类题？为什么？）；
5. 结论写成决策记录（D19），默认行为跟着结论走。
