## 5.1 知识：稀疏与稠密——两套检索的物理学

**BM25（稀疏/词法）**。打分三件套的直觉：

1. **IDF（逆文档频率）**：一个词在全部文档里越罕见，区分度越高
   ——出现在 0.1% 文档的词权重远高于出现在 80% 文档的词。财报里
   的精确数字（1,568,385,287）是 IDF 极高的「罕见词」——**精确
   数字检索天然是词法的领地**；
2. **TF 饱和**：词在文档里出现越多分越高，但边际递减（出现 10
   次不比 5 次重要多少）——防堆词；
3. **长度归一**：长文档天然命中更多词，按长度折算——短而准的
   文档不吃亏。

**稠密/语义检索**。训练范式的直觉（一句话级）：双塔结构——
query 与 doc 各自编码成向量，用「相关对距离近、不相关对距离远」
的对比损失训练。推理时 query 向量在 ANN 索引里找近邻。强项是
**同义改写与跨语言**（「营收」→「营业收入」词面零重叠，向量贴
着）；弱项是它把「语义相近」一律编码为「向量相近」——而
**「语义相近而语义价值不同」的词对**（净利润 ↔ 扣非净利润；
总资产 ↔ 净资产）在向量空间里几乎贴着。**同义改写的收益与口径
混淆的风险是同一枚硬币的两面**——你的任务吃哪面，决定选哪派。

**BEIR 的账**（[NeurIPS 2021](https://arxiv.org/abs/2104.08663)，
18 个异构数据集零样本评测）：**BM25 是稳健基线**——击败大多数
在 MS MARCO 上训练的稠密检索器，且恰在罕见词、精确匹配、域外
词汇主导的任务上（SciFact/BioASQ/ArguAna）。这不是「稠密不行」
——在分布内的语义改写任务上稠密强得多；是「**零样本/精确匹配
场景，词法是地板**」。

**ColBERT 的位置**（[arXiv:2004.12832](https://arxiv.org/abs/2004.12832)）：
迟到交互——不是整句压成一个向量（双塔），而是**每个 token 一个
向量**，查询时 token 级 MaxSim 求和。精度介于双塔与 cross-encoder
之间，代价是索引膨胀（每 token 一个向量）。知道它的存在，因为
「词法与语义的二分法」是简化——迟到交互一族在中间。

## 5.2 知识：RRF 融合与三个增强件

混合检索怎么融合两路？**RRF**（Cormack et al., SIGIR'09，[ACM](
https://dl.acm.org/doi/10.1145/1571941.1572114)）：

<div class="tg-formula" role="img" aria-label="RRF 融合公式">
  score(d)&nbsp;=&nbsp;Σ<sub>r&thinsp;∈&thinsp;R</sub>&nbsp;
  <span class="frac"><span>1</span><span>k + rank<sub>r</sub>(d)</span></span>
  ，&nbsp;&nbsp;k = 60
</div>

**手算**（k=60，三轨）：

| chunk | 词轨排名 | 字轨排名 | 向量排名 | RRF 得分 |
|---|---|---|---|---|
| A（真值块）| 1 | 3 | 9 | 1/61+1/63+1/69 = **0.0468** |
| B（页眉块）| 2 | 1 | — | 1/62+1/61 = **0.0325** |
| C（语义近块）| — | — | 1 | 1/61 = **0.0164** |

A 两轨靠前融合登顶；C 向量第一孤掌难鸣。RRF 聪明在**只用排名
不用分数**——BM25 分与 cosine 分根本不可比，排名是唯一公共货币；
实现三行（每路一个循环累加 1/(k+rank)）。k=60 对具体值不敏感
（第 1 名 1/61、第 10 名 1/70）——别把精力花在不敏感的参数上。
它是 ES/Weaviate/LangChain 混合检索的默认，原因就是「免费且稳」。

**三个增强件的判据**（都不默认开）：

| 增强 | 机制 | 何时适用 | 何时有害 |
|---|---|---|---|
| rerank（cross-encoder）| query+doc 拼接过 transformer，attention 全交互——精度高一个量级，每对一个前向，只能排 top 20–100 | 召回已好、要精排顶对 | **与稠密同偏见**：「语义近口径错」的块同样被抬名次——必消融 |
| HyDE（[arXiv:2212.10496](https://arxiv.org/abs/2212.10496)）| 先让 LLM 生成假设答案，用假设答案的向量去检索（答案↔答案比问题↔答案更近）| 词面零重叠的开放域 | 生成的假设带偏检索；数字任务假设答案就是幻觉 |
| multi-query | LLM 生成多视角查询并行检索、RRF 合并 | 召回覆盖不足 | 改写漂移 + 成本 ×N |

业界标准四层栈：**召回（便宜、多路）→ 融合（RRF）→ rerank
（贵、准）→ 生成**。Contextual Retrieval 的实测给 rerank 的位置
背书：检索失败率 5.7% → 3.7%（上下文嵌入）→ 2.9%（+BM25 混合）
→ **1.9%（+rerank）**——最后一刀是 rerank 砍的（第 3 章已引）。
但「加 rerank 必涨分」不成立——它与 embedding 同源同偏见，上
之前先消融。

**消融方法学五条**（决定「加不加一路」的唯一正道）：
①固定对照组（零 LLM 方差，否则实验自身会抖，结论不成立）；
②真值纪律（期望值人工核对到分位，多源交叉验证）；③单变量
（一次只动一路）；④被害题分析（掉分的是哪类题？为什么？——
把「掉分」变成「机制认知」）；⑤结论入档（决策记录 + 默认行为
跟着结论走——半年后有人想「顺手打开」时先撞见数字）。

## 5.3 案例研究：Tally 的双轨与 D19 消融

!!! abstract "案例研究：Tally（fts.py / embed.py）"

    **中文双轨词法**——两条失败路径各由一轨兜底：

    | 失败路径 | 例子 | 兜底的轨道 |
    |---|---|---|
    | 分词错误（术语被切碎）|「归属于母公司所有者权益」被切飞 | **字轨**（trigram 子串，对分词免疫）|
    | 词面鸿沟 |「营收」vs「营业收入」 | **词轨 + 查询扩展**（同义映射）|

    查询构造代码走读（两个实测坑都在注释里）：

    ```python
    # tally/fts.py: word_expr（词轨查询——清洗虚词）
    def word_expr(query: str) -> str:
        """丢单字中文 token：的/年/亿等虚词 idf≈0 却稀释 MATCH。"""
        toks = [t for t in dict.fromkeys(word_tokens(query))
                if not (len(t) == 1 and "一" <= t <= "鿿")]
        return " OR ".join(_quote(t) for t in toks)

    # tally/fts.py: char_expr（字轨查询——不能整段短语！D2 实测）
    def char_expr(query: str) -> str:
        """≥2 字词 token 做 trigram 短语 OR。「预计净利润多少」作为
        整段短语永远不命中——原文里被「2026年半年度」隔开了。"""
        segs = [s for s in (char_text(t) for t in word_tokens(query))
                if len(s) >= 2]
        return " OR ".join(_quote(s) for s in dict.fromkeys(segs))
    ```

    融合三行同律（向量缺位返回 None 静默降级双轨——可选功能不能
    变部署门槛）：`for ranking in rankings: for rank, cid in
    enumerate(ranking): rrf[cid] += 1/(60+rank)`。工程细节：两轨
    各取 top k×3 只拿轻列（chunk_id），融合后一次性取正文——避免
    两轨各拖 24 条长文本。**硬过滤下推**：公司/期间在 SQL 里先
    过滤再 MATCH——naive_rag 的张冠李戴在这层封死。

    **D19 消融**（本书最反共识的实测）——完整实现向量第三路
    （bge-small-zh，512 维，同律 RRF），31 题人工核对真值集上：

    | 数据集 | 双轨 answer_hit | 向量三路 answer_hit |
    |---|---|---|
    | default 10 | **1.00** | 0.875 |
    | agent 8 | **1.00** | 0.833 |
    | innolight 31 | **1.00** | 0.926 |

    读数三步（方法学五条的现场应用）：三连 1.00 = 双轨**饱和**
    （数学上加路只可能持平或变差）；被害题逐题归因——**恰好全是
    口径题**，bge 把「同文档语义近而口径不同」的块拉近挤掉精确
    命中（BEIR 结论的单语料复现，5.1 硬币的口径面）；决策 =
    **默认关、`TALLY_VEC=on` 显式 opt-in**，docstring 里留下三行
    数字——「用数据关掉一个 feature」。

## 5.5 小结

- BM25 三件套（IDF/TF 饱和/长度归一）解释了数字与精确匹配任务
  上词法的韧性；稠密强在同义改写、险在口径混淆——同一枚硬币；
- BEIR：零样本/精确匹配场景词法是地板；ColBERT 的迟到交互在
  中间；
- RRF 只用排名不用分数、三行实现——融合的默认答案；rerank 与
  稠密同偏见，必消融再上；四层栈（召回→融合→精排→生成）；
- 饱和点之上加路只会变差；消融方法学五条：固定对照/真值纪律/
  单变量/被害题分析/结论入档。

## 常见误区

**误区一：「向量检索总比词法好」。**强项同义改写、弱项精确匹配
（数字/编号/口径）——任务偏精确匹配时词法是地板不是过渡方案。

**误区二：「混合检索一定提升」。**前提是两路各有不可替代的命中
面；一路饱和时加另一路只引入噪声——饱和点之上没有免费午餐。

**误区三：「RRF 的 k 要精调」。**k=60 只是排名到权重的温和映射，
换 80 结果几乎不变。精力花在两路的查询构造上（整段短语坑就是
查询构造的锅）。

**误区四：「检索好了答案就对」。**检索保证证据在池，不保证生成
选对句（第 7 章口径）、答案对题、模型不算术幻觉——检索指标与
答案正确率的缝隙是第三部分的存在理由。
