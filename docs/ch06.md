## 6.1 知识：attribution 谱系与判定等级

「生成时带出处」是一个有正式理论的研究方向，不是工程装饰。

**AIS 框架**（Rashkin et al., [arXiv:2112.12870](
https://arxiv.org/abs/2112.12870)，Google）把归因定义为：**「一个
知情读者会同意：根据来源 s，陈述 z 成立」**——判定单元是
「陈述—来源」对。关键贡献是可操作等级：

| 等级 | 含义 | 判定 |
|---|---|---|
| **E**（Entailment）| 来源完全蕴含陈述 | 完全可归因 |
| **C**（Complement）| 来源支持陈述的可核验部分 | 可补全——陈述里有来源给不了的附加信息 |
| **N**（Not attributable）| 来源不支持 | 不可归因 |

这三级直接工程化：句级判定「这句答案有没有据」= 对每个数字句
问 E 还是 N。**粒度决定可验证性**——你要验证到句，引用就必须
到句（文档级引用无法支撑逐句判定，这是第一原则）。

**谱系全景**：

| 形态 | 代表 | 出处粒度 | 可验证性 |
|---|---|---|---|
| 文档级引用 | 早期 RAG、搜索摘要 | 「参考了这 3 篇」 | 弱（哪句来自哪篇？）|
| 句/段级内联 | Copilot 类产品 | 每事实句挂来源 | 强（句↔来源可对账）|
| 生成自带引文 | [Attributed QA](https://arxiv.org/abs/2212.08037)（Bohnet et al. 2022）| 答案 + 逐字支持引文 | 强（引文即证据，评测基准化）|
| 平台原生 | [Anthropic Citations API](https://platform.claude.com/docs/en/build-with-claude/citations)（2025-01）| 模型输出自带 grounding 块 | 依赖平台 |
| 引用评测 | [ALCE](https://arxiv.org/abs/2305.14627)（citation F1 等）| 评测层 | —— |

两条读谱原则：**生成自带 ≠ 可信**——平台原生引用解决成本（不用
自己拼格式），不解决治理（谁校验引用真指向证据）；需要「不依赖
任何模型自觉的第二道闸」的系统，校验必须自建（第 7 章）。**引用
的第一读者是验证器不是人**——用户体验是验证性的副产品。

## 6.2 知识：context engineering 三杠杆与 lost-in-the-middle

**送什么**：检索命中的块本身，还是带邻居的窗口？small-to-big 的
生成侧——检索单元小、生成上下文大（第 3 章）。表格行被切在相邻
块时，邻居窗口不是锦上添花而是**结构恢复**（单行读不懂列结构）。
窗口大小的确定方法是实测（见案例：union 整页窗净负）。

**什么顺序**：**lost in the middle**（Liu et al.,
[arXiv:2307.03172](https://arxiv.org/abs/2307.03172)，TACL 2024）
的实验证据：把关键信息放在长上下文的**开头或结尾**时模型表现
显著好于放在**中间**——曲线是 U 形。多个规模与模型复现。工程
含义：**最重要的证据放头尾，别均匀堆**；上下文分区顺序本身就是
检索质量的一部分。配套现象：上下文越长，对中间内容的「注意」
越弱——所以「多送」不只是浪费预算，可能 actively 有害。

**多少**：三个账都指向少——注意力稀释（无关块挤占）、打分带偏
（下一章的抽取式打分器会被无关数字句干扰）、预算挤占（上下文
与生成共享窗口）。「少即是准」是实证结论不是风格偏好。

业界把这三维统称 **context engineering**——与 prompt engineering
的区别：管理「进入窗口的一切」（检索/组装/排序/压缩）的工程，
不是措辞技巧。

**生成契约与它的边界**。给生成层的规矩（每句带引用/池里没有的
答「无依据」/数字原样引用不换算）是**减负**：降低验证层工作量。
不是安全边界：prompt 可以优化、可以失效、可以被更强的模型绕过
——把它当边界是第 7 章要拆的隐患。契约的措辞要点：**枚举合法
引用格式**（给正则可解析的样例）、**给反例**（「原文中没有
依据」怎么说）、数字**原样引用**（换算错在摄取层做，第 3 章）。

**格式漂移与归一化**。让模型手写引用，同一来源会写出三种变体
（`[A_2025FY 第8页]` / `[A_2025FY第8页]` / `[A_2025FY 第 8 页]`）
——逐字比对全部失配。通则（全书第三次出现）：**文本相等性判定，
永远先定义归一化**——剥空白再比，比对语义单位（doc+页）不变。
这条通则的三次收学费：第 2 章页眉空格、本章引用漂移、第 13 章
关键词边界。

## 6.3 案例研究：Tally 的引用契约与证据组装

!!! note "案例研究：Tally（graph.py / answer.py）"

    **句级内联引用契约**：`[公司_报告期 第N页]`——粒度到页，
    **页码来自摄取元数据**（chunk.page），不靠模型回忆（模型
    幻觉页码 = 引用指向不存在的位置，对账面直接损坏）。归一化
    治漂移（D13 实测：修前 cov=0.8 的合格答案被误判 degraded）：

    ```python
    # tally/answer.py: _cite_norm / citation_in（D13）
    def _cite_norm(s: str) -> str:
        """引用匹配的空白归一：小模型手写引用的空格会漂移……
        剥尽空白再比，引用语义（doc+页）不变。"""
        return re.sub(r"\s+", "", s)

    def citation_in(answer: str, citation: str) -> bool:
        return _cite_norm(citation) in _cite_norm(answer)
    ```

    **证据组装三件套**（context engineering 的确定性实现，每件
    一个实测教训）：

    1. **page_evidence（首命中页 ±2 窗）**——small-to-big 的页级版。
       为什么不是整页或 ±5：**union 窗实测净负**（无关块稀释
       注意力、带偏抽取式打分——6.2「少即是准」的内部证据）；
       ±2 是「拿到邻居又不淹没」的实测平衡；
    2. **stitch_adjacent（标签块+数值块拼接，D16）**——PDF 把
       「归属于上市公司股东的扣除非经常性损益的净利润（元）」和
       数值行拆成两块：标签块无数字被降权、数值块无标签词面不
       命中——**不拼回去，抽取式永远选不出完整证据**。拼接在
       检索后、抽取前做，两条路径（检索/agent）都挂；
    3. **front_key_table（表页前置）**——metric 意图把「主要会计
       数据」表页前置进 hits：真值行是纯数字块，词面打不过含
       公司名+期间的页眉块（实测被挤出 top-8）。前置 = 确定性
       精排——这张表是 metric 问题的最大概率证据源。

    **抽取式打分走读**（降级后的答案从哪来——打分器四权重，
    全码见附录 D）：

    ```python
    # tally/answer.py: extractive_answer（打分核心，节选）
    overlap = len(q & stoks)                  # ① 查询 token 重叠；零重叠出局
    score = overlap * (1.4 if has_num else 1.0) + (0.2 if h.chunk.num_notes else 0.0)
    if not has_num and any(w in state["query"] for w in ("多少", "几")):
        score *= 0.3                          # ② 数字问句下无数字句强降权
    ```

    四个权重每条都是一次实测翻车后加的：①防零重叠句靠 num_notes
    加分混入；②防表头句词面完美却无值；③防无数字句在数字问句下
    夺魁；④配对口径降权（第 7 章主角）。**抽取式不是「抄 top1」，
    是带领域知识的打分器**——「丑但真」却准的原因。

## 6.5 小结

- AIS 三级（E/C/N）把归因判定工程化；粒度决定可验证性——验证
  到句，引用就得到句；生成自带引用降本不治理；
- context engineering 三杠杆：送什么（small-to-big/结构恢复）、
  什么顺序（lost-in-the-middle，U 形曲线——重要证据放头尾）、
  多少（少即是准，三笔账）；
- 生成契约是减负不是边界；数字原样引用，换算归摄取层；
- 文本相等判定先归一化（第三次收学费）；抽取式是带领域知识的
  打分器，不是抄 top1。

## 常见误区

**误区一：「引用是给用户看的装饰」。**引用的第一读者是验证器。
文档级引用无法支撑逐句对账——粒度设计先问验证器要什么。

**误区二：「上下文越多越保险」。**U 形曲线 + 稀释 + 打分带偏 +
预算挤占，四笔账都指向少。窗口/前置/拼接都要实测。

**误区三：「prompt 里写了『必须引用』就安全了」。**减负 ≠ 边界。
安全边界是生成后的独立验证（第 7 章），两个角色不能同一层兼任。

**误区四：「让模型自己换算单位更贴心」。**换算即事实生产——
「约 4.19 亿」必须来自摄取层的确定性换算注释，不是模型心算。
