## 6.1 失败先行：一个空格毁掉的合格答案

小模型生成时会手写引用，格式会漂。同一个块，三种写法：

```
[中际旭创_2025FY 第8页]     ← 标准格式
[中际旭创_2025FY第8页]      ← 粘连（无空格）
[中际旭创_2025FY 第 8 页]   ← 多空格
```

verify 用精确子串匹配引用——后两种全判「引用不在场」，**有据答案
被误判 degraded**（llm 实测 cov=0.8 仍 degraded），对比结论句被
抽取式顶掉。修复（D13）：

```python
# tally/answer.py
def _cite_norm(s: str) -> str:
    """引用匹配的空白归一（D13）：小模型手写引用的空格会漂移……
    剥尽空白再比，引用语义（doc+页）不变。"""
    return re.sub(r"\s+", "", s)

def citation_in(answer: str, citation: str) -> bool:
    return _cite_norm(citation) in _cite_norm(answer)
```

**通用教训（第三次出现）**：文本相等性判定，永远先定义归一化。
第 2 章的页眉空格、本章的引用漂移、第 13 章的关键词边界——同一条
教训在三层各收一次学费。

## 6.2 知识点：attribution 谱系——引用粒度决定可验证性

「生成时带出处」不是一种功能，是一个有谱系的研究方向：

| 形态 | 代表 | 出处粒度 | 可验证性 |
|---|---|---|---|
| 文档级引用 | 早期 RAG 应用、搜索摘要 | 「参考了这 3 篇」 | 弱（哪句来自哪篇？）|
| 句/段级内联引用 | Tally、Bing/Copilot 类 | 每个事实句挂来源 | 强（句↔来源可对账）|
| 生成自带引文 | [Attributed QA](https://arxiv.org/abs/2212.08037)（Bohnet et al. 2022）| 答案+逐字支持引文 | 强（引文即证据）|
| 平台原生引用 | [Anthropic Citations API](https://platform.claude.com/docs/en/build-with-claude/citations)（2025-01）| 模型输出自带 grounding | 依赖平台 |
| 引用评测基准 | [ALCE](https://arxiv.org/abs/2305.14627)（citation F1 等）| 评测层 | —— |

学术标准是 AIS 框架（[arXiv:2112.12870](https://arxiv.org/abs/2112.12870)）：
归因判定单元是「陈述—来源」对，标准是「一个知情读者会同意：根据
来源 s，陈述 z 成立」。从这张表里读出本章的设计原则：

- **粒度决定可验证性**：文档级引用无法支撑逐句对账——你要验证
  「这句话有据吗」，粒度就必须到句。Tally 的选择：**句级内联引用
  `[公司_报告期 第N页]`**——粒度细到页，verify（第 7 章）才有可
  计算的对账面；页码来自摄取时的元数据（`chunk.page`），不靠模型
  回忆。
- **生成自带 ≠ 可信**：Citations API 是「生成时自带」，Tally 的
  verify 是「生成后自检」——封闭世界要的是**不依赖任何模型自觉的
  第二道闸**。平台能力可以降本，不能替代出口闸门。
- **检索到 ≠ 送进去**：送什么证据、按什么顺序送，同样是检索质量
  的一部分——业界把这层叫 context engineering。Tally 的三件套
  （6.4 节）是它的确定性实现。

## 6.3 本项目：grounded 生成的契约

generate 的 prompt 只有三条硬规矩：

1. 每个事实句**必须**带 `[公司_报告期 第N页]` 引用；
2. 证据池里没有的，答「原文中没有找到依据」——不许推理补全；
3. 数字原样引用，不许换算（换算由摄取层归一化注释负责，第 3 章）。

职责切分要清楚：模型负责**语言组织**（把证据句组织成通顺回答），
不负责**事实裁决**——那是 verify 的工作。生成层的自觉（prompt
约束）**从不被信任为安全边界**，它只是降低 verify 的工作量。实操
含义：prompt 可以优化、可以失效、可以被更强的模型绕过——闸门不能。



## 6.4 本项目：证据组装三件套

送进生成的证据池怎么组（`tally/graph.py`）——三件套全是实测教训：

**① page_evidence（small-to-big）**：检索命中 chunk 所在页的 ±2
兄弟块一起进池。为什么：表格行常被切在相邻块（第 3 章），只给
单行模型读不懂列结构；页是 PDF 的天然语义单元。为什么是 ±2 不是
整页或 ±5：union-window 实测**净负**——上下文稀释（无关块挤占
注意力，抽取式打分被带偏）；±2 是「拿到邻居又不淹没」的实测平衡。
这个模式在 LlamaIndex 的教程里有个名字：sentence-window /
small-to-big——检索单元小、生成上下文大。

**② stitch_adjacent（D16）**：同页「标签块 + 数值块」拼接。PDF
抽取的经典残骸：

```
块A（标签）：归属于上市公司股东的扣除非经常性损益的净利润（元）
块B（数值）：1,568,385,287.19   990,216,569.13   58.39%
```

不拼回去：抽取式永远选不出完整证据（标签块无数字被 0.3× 降权、
数值块无标签词面不命中）——扣非题答非所问的元凶之一。拼接在
**检索后、抽取前**做，retrieve 和 agent 两条路径都挂。

**③ front_key_table**：metric 意图把「主要会计数据」表页**前置**
进 hits。教训：真值行（纯数字块）词面打不过页眉块（页眉含公司名+
期间，词面完美匹配）——实测被挤出 top-8。前置=检索排名的「法定
插队」：这张表是 metric 问题的最大概率证据源。

三件套的共同模式：**先跑真值集，让失败告诉你下一行代码写什么。**

## 6.5 本项目：抽取式打分走读——被降级后的答案从哪来

第 7 章会说「降级 = 换抽取式」——抽取式答案是怎么选句的？这是
answer.py 最值得精读的一段（打分函数，逐项拆解）：

```python
# tally/answer.py: extractive_answer（打分核心，节选）
overlap = len(q & stoks)                    # ① 查询 token 与句/块 token 重叠
if overlap == 0:
    continue      # 零重叠句只靠 num_notes 加分混进答案（实测净资产句）
has_num = bool(re.search(r"\d[\d,]*\.?\d", s)) or bool(h.chunk.num_notes)
score = overlap * (1.4 if has_num else 1.0) + (0.2 if h.chunk.num_notes else 0.0)
# ② 数字句优先 ×1.4：财报问答大多数时候在问数字。真数字才算——
#    条目序号（「2.终止经营净利润」）也是 \d，要求 ≥2 位或小数/千分位
if not has_num and any(w in state["query"] for w in ("多少", "几")):
    score *= 0.3
# ③ 数字问句下无数字句强降权：表头行（「…净利润（元）」）词面完美
#    匹配扩展词却无值，会压过真值行（扩展词引入后实测）
if (("扣非" in q_raw or "扣除非" in q_raw)
        and "净利润" in s and "扣除" not in s and "扣非" not in s):
    score *= 0.3
# ④ 配对口径降权（第 7 章 7.5 节主角，此处先见一面）
```

四个权重的共同性格：**每一条都是一次实测翻车后加的**——①防
「零重叠句靠注释加分混入」，②防「表头句词面完美却无值」，③防
「无数字句在数字问句下夺魁」，④防「归母句冒名扣非」。④（口径）
在第 7 章展开成六对家族；这里先记住形态：**抽取式不是「抄 top1」，
是一个带领域知识的打分器**——这正是它「丑但真」却仍然准的原因。

## 6.7 小结

- 引用粒度决定可验证性：句级内联 + 页码元数据，verify 才有对账面；
- attribution 谱系（AIS/ALCE/Attributed QA/平台原生）——生成自带
  引用可以降本，不能替代出口闸门；
- 格式漂移用归一化治（D13）——文本相等判定三定律的第二次应用；
- 证据组装三件套（页窗/拼块/前置）= context engineering 的确定性
  实现，每件一个实测教训；
- 生成层自觉不被信任为边界：prompt 是减负，闸门是安全。

## 常见误区

**误区一：「引用是装饰，给用户看的」。**引用首先是**机器可验证
的对账面**——verify 靠它把答案句锚定到证据池。粒度设计的第一
读者是验证器，不是人：文档级引用无法支撑逐句对账，句级+页码
才能。用户体验是验证性的副产品。

**误区二：「上下文越多越好」。**union-window 实测净负——无关块
稀释注意力、带偏抽取式打分。「送什么」和「按什么顺序送」是检索
质量的一部分，±2 页窗、表页前置、拼接标签块，三件套都是「少即是
准」的证据。
