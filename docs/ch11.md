# 第 11 章 Planner 与 Memory：只删不造 / 三层记忆

> 状态：初稿 v0.1 · 所属：第三部 Agent 化 · 前置：第 10 章

## 11.1 失败先行：规划器的两种输出事故

多跳问题（「对比 A、B、C 三家 2025 与 2026 的营收和净利」）先让
LLM 出子目标清单，实测它会很自然地输出两类东西：

1. **白名单外的动作**——`browse` 网页、`calculate` 裸算式；
2. **语料里不存在的公司**——幻觉实体照拆不误。

校验器的哲学由此定调：**只删不造**（`_validate_plan`）——白名单外
的动作丢弃、期间规约到枚举、去重、封顶 MAX_SUBGOALS=5、单公司回填。
LLM 提供的是「拆解的灵感」，清单的合法性由代码裁决；校验失败整体
回退 agent 环（现路径，不冒险）。

## 11.2 检查点与「未覆盖」红线

每个子目标执行后过检查点（`_ckpt_ok`：财报级数字在场 ∧ 指标词命中），
不过有界重试 ×1，再不过**显式弃**——弃掉的进 `plan_gaps`，verify
出口追加声明：

```python
# tally/graph.py: verify_citations（节选）
gaps = [g for g in (state.get("plan_gaps") or []) if g]
if gaps:
    out["answer"] = (f"{out.get('answer', '').rstrip()}\n（未覆盖："
                     + "；".join(gaps) + "——检索不足，以上为已覆盖部分）")
```

**部分答案不硬凑**——宁可明说「C 公司的净利没找到」，不把别家的
数顶上去。这是 verify 精神（不编）在多跳场景的延伸：不编事实，
也不编完整性。

## 11.3 Memory 三层：每层回答一个「凭什么信」

| 层 | 是什么 | 凭什么信 |
|---|---|---|
| L0 会话 | 轮摘要继承（公司/期间/年份/指标词） | **永不继承自由文本**——只继承结构化理解字段，切断叙述传播边 |
| L1 台账 | verified_facts 表（公司+期间+指标+口径 键） | **写闸严于读闸**；读不豁免 |
| L2 资产 | alias 词典等检索导航知识 | 人工维护 + eval 全绿才晋升；非答案事实 |

L1 的两道闸值得精读：

```python
# tally/graph.py: _memory_write（写闸节选）
tr = "→".join(state.get("trace") or [])
if any(bad in tr for bad in ("caliber-mismatch", "fallback(",
                             "no-evidence", "derived-mismatch")):
    return []          # 口径闸触发过的一律不写——D22 闸保「数字在场」，
                       # 写闸要的是「行也对」
```

**写闸** = verify:pass ∧ 口径闸未触发——只有最干净的结构化事实进
长期记忆。**读不豁免**更关键：memory_probe 命中拼出的答案照样内联
过 verify（缓存证据不缓存结论）——投毒测试为证：往台账写一条假
事实（`test_poisoned_fact_read_not_exempt`），读路径的 verify 把它
拦下了。记忆是加速器，不是后门。

失效机制：语料指纹漂移 → probe 时校验 → 自动 supersede。语料变了，
旧事实不作数——记忆的生命周期跟着证据走。

## 11.4 eₖ·gₖ 视角（先埋个钩子）

三层设计共享同一个直觉：**长链的失败不该按 pⁿ 复利**。L0 不继承
自由文本 = 剪断「叙述错误」的传播边；L1 结构化键 + 读不豁免 = 错误
事实要么进不来（写闸）、要么出不去（verify）；结构化传递的本质
是「字段复制，不文本重释」。第 13 章把这写成公理。
