## 11.1 知识：工具调用谱系与 MCP

**ReAct**（[arXiv:2210.03629](https://arxiv.org/abs/2210.03629)，
Yao et al. 2022）：thought → action → observation 循环——思考给
行动定向，观察给思考供料。原论文的对照实验给过关键结论：Reason
与 Act 交织（ReAct）优于纯 Reason（CoT）——行动提供的真实观察
纠正推理的幻想。至今仍是 agent 循环的基型。

**Toolformer**（[arXiv.org/abs/2302.04761](
https://arxiv.org/abs/2302.04761)）：训练路线——模型自学在哪些
位置插 API 调用（自监督：插入调用后若降低下一 token 损失就保留）。
学术价值大，工程上被 API 原生能力取代。

**Function calling**（2023 起各家 API 原生）：结构化工具调用成为
平台能力——开发者战场从「让模型学会调用」移到「调用之后怎么防
它闯祸」（本章主题）。协议要点（第 8 章）：`tool_calls` 带
id+type、arguments 是 JSON 字符串、tool 消息回指 id——内部宽松、
边界归一化。

**MCP（Model Context Protocol）**（[modelcontextprotocol.io](
https://modelcontextprotocol.io)，Anthropic 2024-11 开放、2025 起
OpenAI/各家采纳）：工具互操作的开放标准，官方类比「AI 应用的
USB-C 口」。架构三角：

```text
Host（宿主应用：Claude/ChatGPT/IDE）
  └── MCP Client（宿主内置的协议客户端，1:1 连接）
        └── MCP Server（外部系统适配器：日历/数据库/Figma…）
              暴露三类原语：tools（可执行动作）/ resources（可读
              数据）/ prompts（可复用提示模板）
```

解决的是**生态碎片**：工具写一次、任何 host 都能挂（此前每家
API 的工具定义格式互不兼容）。对工程的三重含义：①白名单从
「自家注册表」升级为「**哪些 MCP server 你敢挂**」——每个 server
都是新的注入面与权限面（它返回的内容进了你的上下文）；②工具
描述成为跨生态契约——描述质量（三原则）比自家注册表时代更
重要；③封闭世界系统对接 MCP 要过一道筛选——resource 可读，
tool 是否放行按第 1 章信任分级裁决。

**工具设计三原则**（[Anthropic define-tools](
https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools)，
官方原话「描述详尽度是第一因素，远超其他」）：

1. **描述详尽**（每工具 3–4 句起）：讲清做什么、什么时候用、
   **什么时候别用**——描述是模型的使用说明书；
2. **强类型参数（poka-yoke 防呆）**：枚举与格式约束让模型「想错
   都难」（period 用枚举不用裸字符串——裸串「2025年上半年」要靠
   先验救）；
3. **错误以 error 对象回流，不抛异常**：模型可见、可改道——保守
   失败但不剥夺改道权（抛异常 = 循环猝死）。

## 11.2 知识：循环工程——账、三件套与两条路线

**compounding errors 的账**（[Building Effective Agents](
https://www.anthropic.com/engineering/building-effective-agents)）：
自主链上单步 95% 可靠，20 步成功率 0.95²⁰ ≈ 64%——**三分之一的
任务失败，且失败率随步数指数上升**。这是 agent 自主的第一代价，
也是「从 workflow 起步、按评估放权」的根本理由。治理它的是循环
三件套：

1. **预算**：步数硬上限 + 每步 token 上限。预算是真实成本（每次
   调用都是钱），循环的每个缺陷直接换算成钱——复读 6 步 = 6×
   检索 + 6× LLM；
2. **终止条件**（三态都要在 trace 可见）：模型自停（最理想）/
   护栏判停（**重复检测**：同一调用原样再现；**无新信息**：整批
   返回与已见重复——模型没有新问题要问了）/ 预算停（最差但可控）；
3. **步级观测**：每步记 {thought, action, observation, gate}
   四元组——没有它，「模型在循环里表现如何」只能靠感觉争论；
   有了它，浪费率 = (重复+空返回)/总调用 是可盯的数字。这是
   业界 LLM observability（trace/span）的最小实现：**先让失败
   可见，才谈得上治理**。

**小模型 agent 的两条可靠性路线**：业界主流**把保证移进解码器**
（Ollama structured outputs 的 GBNF、vLLM 的 xgrammar/guidance
——语法约束解码，非法 JSON 生不成）；本书路线**把保证留在
运行时**（解析失败退规则 + 先验覆盖参数 + 有界步数）。互补不
互斥，各管一段：**解码器保证语法，先验保证语义，闸门保证事实**
——解码器管得住「period 不是合法枚举」，管不住「search 了一个
语料里不存在的期间」（语义）与「答案数字不在证据里」（事实）。

**提示注入的风险地图**（分类见 [OWASP LLM Top 10](
https://genai.owasp.org/llm-top-10/)；「间接注入」= 检索内容/
工具返回里藏指令）。正确方法不是一句「安全/不安全」，是逐组件
标注「注入能影响什么 / 死在哪道闸」：

| 注入面 | 看见外部内容吗 | 注入能影响什么 | 依赖什么拦 |
|---|---|---|---|
| 查询理解 | 否（只见 query）| 不可达 | —— |
| 证据打分/检索评估 | 是 | 打分被带偏 | 失败退规则、重试有界 |
| 生成 | 是（证据池）| **叙述措辞**（选词/方向词）| **数字必须对账证据**——注入造不出「在场的数字」|
| **记忆写入** | 是 | **假事实沉淀**（一次注入、轮轮读它）| 写入门槛 + 失效机制（第 12 章）|

通用结论：**注入能碰到语言，碰不到有独立校验的事实**——每条
事实通路（生成出口/派生重算/记忆写入）都有独立于模型的验证时，
注入的上限是「说怪话」不是「说假数」。深防御在记忆写入层（一次
注入永久污染的唯一断路器）。

## 11.3 案例研究：Tally 的执行环与护栏四件套

!!! abstract "案例研究：Tally（graph.py / llm.py）"

    **工具白名单三个**（search / metrics_table / derive），注册表
    外返回空观测 `"[]"`——模型看得见「此路不存在」，走不出去。
    derive 工具是「**禁止模型心算**」的落点：Q2=H1−Q1 原币精度
    计算（亿值四舍五入差分到百万级误差——先算后换算），操作数
    不可解析返回 error 对象（三原则第 3 条），结果登记出口重算
    ±0.01（第 7 章）。

    **护栏四件套**（对 11.2 三件套的实例化，代码走读）：

    ```python
    # tally/graph.py: agent_research（节选——注释即事故档案）
    seen: dict[str, str] = {}   # 幂等缓存：小模型会把同一调用原样
                                # 重复 6 步烧满（实测）
    if key in seen:             # 重复调用：回缓存 + 换角度提示——
        msgs.append({"role": "tool",
                     "content": seen[key] +
                     "（重复检索：结果同上。请换检索角度或停止调用工具。）"})
        step.update(gate="dup"); continue     # 把失败变成下一步引导
    ...
    if not fresh and pool:      # 整批全是重复 = 没有新问题要问
        stopped = "重复收手"                  # 早于预算停——止损
        break
    # 另两件：MAX_AGENT_STEPS = 6 硬上限；
    #         理解先验覆盖工具参数（战略不归战术改写）
    ```

    四件套没有一条限制模型的**决策空间**（它仍决定查什么、何时
    停）——限制的是**无效动作**（重复/超步/幻觉参数）。护栏是
    保险绳不是镣铐。

    **步级观测**（四元组 + 耗时进 trace，`-v` 可读、eval 聚合）：

    ```python
    step = {"i": n_steps, "thought": thought[:80],          # 在想什么
            "action": f"{tc['name']}{json.dumps(tc['arguments'])[:64]}",
            "obs": n_obs, "obs_doc": first_doc,              # 看到什么
            "gate": "new" if n_obs else "empty", "ms": dt}   # 闸门判定
    ```

    **远端实测**（glm-5.3，agent 集 8 题，v0.7.1）：22 次调用
    **dup=0**（强档位不复读——护栏还在，只是没活干）、waste_rate
    0.227（全来自 empty：metrics_table 对预告类文档返回空）、
    两道 compare 被 0.45 阈值拦成 degraded 抽取式仍全对——闸门在
    真实远端生成路径的实弹证明。**Anthropic 通道 tools 未接 →
    显式 NotImplementedError → 固定管线兜底**（显式失败优于
    半成品，第 8 章）。

    **注入面地图的案例行**：Tally 生成看见证据池（叙述可被带偏，
    数字过覆盖率闸）；L1 写闸（第 12 章投毒测试）是深防御主通道。

## 11.5 小结

- 谱系：ReAct 基型（Act 的真实观察纠正 Reason 的幻想）→ function
  calling 平台化 → MCP 解决生态碎片（host/client/server 三角 +
  tools/resources/prompts 三原语）——白名单升级为 server 信任
  清单；
- 三原则：描述详尽（含何时不该用）、强类型防呆、error 回流不
  抛异常——四件套是三原则的运行时版；
- compounding errors 是第一代价（0.95²⁰≈64%）；循环三件套：
  预算/终止三态/步级观测——浪费率让失败可见；
- 两条可靠性路线各管一段：解码器保证语法、先验保证语义、闸门
  保证事实；
- 注入面地图：能碰语言碰不到有独立校验的事实；深防御在记忆
  写入层。

## 常见误区

**误区一：「Agent = 让模型自由循环」。**每种死法（复读/幻觉参数/
不收手）都是预算问题。工程化 agent = 自由 + 护栏 + 观测，缺一
不可；只给自由的循环是碎钞机。

**误区二：「护栏抑制智能」。**护栏限制无效动作不限制决策空间
——强档位实测根本不触发护栏。保险绳不是镣铐。

**误区三：「接了 MCP 生态就安全了」。**协议解决互操作不解决
信任——每个挂进来的 server 都是新的注入面与权限面。

**误区四：「上了结构化输出就不用护栏了」。**解码器管语法
（合法枚举），管不住语义（查不存在的期间）与事实（数字不在
证据里）——三层各管一段。
