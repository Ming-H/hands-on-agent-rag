## 11.1 知识：工具调用谱系与设计三原则

Agent 工具调用的谱系：

- **ReAct**（[arXiv:2210.03629](https://arxiv.org/abs/2210.03629)）：
  thought → action → observation 循环——思考给行动定向，观察给
  思考供料。至今仍是 agent 循环的基型。
- **Toolformer**（[arXiv:2302.04761](https://arxiv.org/abs/2302.04761)）：
  训练模型自学在哪些位置插 API 调用（训练路线）。
- **Function calling**（2023 起各家 API 原生）：结构化工具调用成为
  平台能力——战场从「让模型学会调用」移到「调用之后怎么防它
  闯祸」（本章主题）。
- **MCP**（Model Context Protocol，[modelcontextprotocol.io](
  https://modelcontextprotocol.io)，Anthropic 2024 开放、2025 起
  多厂商采纳）：工具互操作的开放标准——服务器统一暴露工具/
  资源/提示，客户端（host）即插即用。它解决的是**生态碎片**：
  工具写一次、各家 agent 都能挂；工程含义是白名单从「自家注册表」
  变成「哪些 MCP server 你敢挂」。

**工具设计三原则**（[Anthropic define-tools](
https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools)，
官方原话「描述详尽度是第一因素」）：

1. **描述要详尽**（每个工具 3–4 句起，含「什么时候**别**用」）——
   描述是小模型的使用说明书；
2. **强类型参数（poka-yoke 防呆）**：枚举与格式约束让模型「想错
   都难」；
3. **错误以 error 对象回流，不抛异常**：模型可见、可改道——保守
   失败但不剥夺改道权。

**第一代价：compounding errors**（[Building Effective Agents](
https://www.anthropic.com/engineering/building-effective-agents)）：
agent 自主链上单步 95% 可靠的任务 20 步只剩 ~36% 成功率（0.95²⁰）。
对策两条：从 workflow 起步按评估增量放权（第 9 章判定线）；给
循环配**预算、终止条件、步级观测**三件套——无界自主是状态机
反模式。

**失败模式与注入面**。agent 的经典攻击面是**间接提示注入**：
检索内容/工具返回里藏指令（「忽略之前的指令…」）。风险分类
见 OWASP LLM Top 10（[genai.owasp.org](https://genai.owasp.org/llm-top-10/)）。
正确的分析方法不是一句「安全/不安全」，是**画注入面地图**：系统
里每个看见外部内容的组件，标注「注入能影响它什么 / 死在哪道闸」。
通用版地图：

| 注入面 | 看见外部内容吗 | 注入能影响什么 | 依赖什么拦 |
|---|---|---|---|
| 查询理解 | 否（只见 query）| 不可达 | —— |
| 证据打分/检索评估 | 是 | 打分被带偏 | 失败退规则、重试有界 |
| 生成 | 是（证据池）| **叙述措辞** | 数字必须对账证据（注入造不出「在场的数字」）|
| **记忆写入** | 是 | **假事实沉淀**（一次注入、轮轮读它）| 写入门槛 + 失效机制（第 12 章）|

结论的一般形式：**注入能碰到语言，碰不到有独立校验的事实**——
每条事实通路（生成出口、派生重算、记忆写入）都有独立于模型的
验证时，注入的上限是「说怪话」，不是「说假数」。深防御在记忆层。

## 11.2 知识：循环工程——预算、终止、观测

工程化的 agent 循环三件套：

1. **预算**：步数硬上限 + 每步 token/调用预算。预算是真实成本
   （每次调用都是钱），循环的每个缺陷都直接换算成钱；
2. **终止条件**：模型自停（最理想）/ 护栏判停（重复检测、无新
   信息即停）/ 预算停（最差但可控）。三种终止都要在 trace 里
   可见；
3. **步级观测**：每步记录 {thought, action, observation, gate}
   四元组——没有它，「模型在循环里表现如何」只能靠感觉争论；
   有了它，浪费率（重复/空返回占比）是可以盯的数字。这是业界
   LLM observability（trace/span）的最小实现：**先让失败可见，
   才谈得上治理**。

**小模型 agent 的两条路线**（可靠性从哪来）：业界主流**把保证移
进解码器**（Ollama structured outputs 的 GBNF、vLLM 的 xgrammar/
guidance——非法 JSON 根本生不成）；另一路**把保证留在运行时**
（解析失败退规则 + 先验覆盖 + 有界步数）。互补不互斥：**解码器
保证语法，先验保证语义，闸门保证事实**——三层各管一段。解码器
管得住「参数不是合法枚举」，管不住「search 了一个语料里不存在的
期间」——后者是语义问题。

## 11.3 案例研究：Tally 的执行环与护栏四件套

!!! note "案例研究：Tally（graph.py / llm.py）"

    **工具白名单三个**（search / metrics_table / derive），白名单外
    返回空观测 `"[]"`——模型看得见「此路不存在」，走不出去。
    derive 是「禁止模型心算」的落点：Q2=H1−Q1 原币精度计算，操作
    数不可解析时返回 error 对象（三原则第 3 条），结果登记出口
    重算 ±0.01。

    **护栏四件套**（对 11.2 三件套的实例化）：①幂等缓存——重复
    调用回缓存 +「换角度」提示（把失败变成引导）；②整批重复即
    收手（早于预算停）；③MAX_AGENT_STEPS=6；④理解先验覆盖工具
    参数（战略决定不归战术改写）。实测死法对照：无护栏时小模型
    同一调用原样重复 6 步烧满预算。

    **步级观测**：四元组 + 耗时进 trace；eval 聚合 waste_rate =
    (dup+empty)/calls。远端实测（glm-5.3）：22 次调用 dup=0、
    waste_rate 0.227（全来自 empty）——强档位不复读，护栏还在，
    只是没活干。

    **消息归一化**（第 8 章 8.3 已走读）：内部宽松格式 ↔ 严格协议
    的转换消化在 llm 层，上层循环零改动——v0.7.1 靠它接通远端
    function calling；Anthropic 通道 tools 未接显式失败 → 固定
    管线兜底。

    **注入面地图的案例行**：Tally 的生成看见证据池（叙述可被带偏，
    但数字必须过覆盖率闸）；L1 写闸（第 12 章）是「一次注入、
    永久污染」的唯一断路器——投毒测试钉死。

## 11.5 小结

- 谱系从 ReAct 到 MCP：循环是基型，function calling 是平台能力，
  MCP 解决生态碎片——白名单变成「哪些 server 你敢挂」；
- 工具三原则：描述详尽（含何时不该用）、强类型防呆、错误回流
  不抛异常；
- compounding errors 是第一代价；循环三件套（预算/终止/观测）
  缺一不可——waste_rate 让浪费可见；
- 注入面地图：注入能碰到语言、碰不到有独立校验的事实；深防御
  在记忆写入层；
- 可靠性三层：解码器保证语法、先验保证语义、闸门保证事实。

## 常见误区

**误区一：「Agent = 让模型自由循环」。**自由循环的每种死法（复读/
幻觉参数/不收手）都是预算问题。工程化 agent 的定义是自由 + 护栏
+ 观测，缺一不可；只给自由的循环是碎钞机。

**误区二：「护栏抑制智能」。**护栏限制的是无效动作（重复、超步、
幻觉参数），不是决策空间——强档位实测根本不触发护栏。护栏是
保险绳，不是镣铐。

**误区三：「接了 MCP/工具生态就安全了」。**协议解决互操作，不
解决信任——挂进来的每个 server 都是新的注入面与权限面，白名单
治理从「工具注册表」升级为「server 信任清单」。
