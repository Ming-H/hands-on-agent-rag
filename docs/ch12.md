## 12.1 为什么需要记忆：三个根本限制

LLM 天生「没有记性」，三个限制决定了记忆是必答题而非加分题：

1. **上下文窗口固定**。窗口再大也是有限的——多轮会话每轮都在
   消耗它，工具返回动辄几千 token，很快见底。「把全部历史塞进
   prompt」在长会话里必然崩；
2. **跨会话失忆**。新会话从零开始——用户上周告诉系统的事（偏好、
   约定、上次的结论）全部丢失。每次都让用户重述，是「聪明系统
   蠢体验」；
3. **成本与延迟**。就算塞得下也不该塞：Mem0 的实测（LOCOMO
   基准，[arXiv:2504.19413](https://arxiv.org/abs/2504.19413)）：
   与「全历史塞 prompt」相比，结构化记忆在**准确率更高的同时，
   p95 延迟低 91%、token 成本省 90%+**——记忆不只是「记得住」，
    是把无限的历史压缩成有限的、相关的、便宜的上下文。

由此得到全书使用的分界：

| | 短期记忆（会话内）| 长期记忆（跨会话）|
|---|---|---|
| 存的是什么 | 消息历史本身 | 从历史沉淀的事实/偏好/技能 |
| 核心问题 | 窗口管理（删/剪/总结）| 写什么、怎么组织、怎么失效 |
| 典型载体 | 消息列表 + checkpointer | 向量库/键值库/知识图谱/文件 |
| 失败形态 | 溢出、丢上下文 | **污染**（记错一条，轮轮读它）|

## 12.2 短期记忆：窗口管理三种方式

会话内记忆 = 消息列表。窗口装不下时的三种处置，业界框架
（LangGraph 等）已把它们做成标准原语：

**① 删除（truncate）**：只保留最近 N 条。最便宜，但对话开头
的约束条件（「只看 2025 年的数据」）会被删掉——第 20 轮的答案
突然不再遵守第 1 轮的约定，用户莫名其妙。

**② 修剪（trim）**：按 token 预算保留尾部，且**从 human 消息
开头**——保证保留的都是完整问答轮，不出现悬空的工具返回。

**③ 总结（summarize）**：把被裁掉的历史压成一段摘要，随消息
一起进 prompt——信息有损但方向保真。工程上的标准形态是
「阈值触发的条件总结」：回答完先汇集，超过阈值才总结。用
LangGraph 的写法（伪代码保留骨架）：

```python
def passthrough(state) -> dict:          # 汇集空节点：两条分支都到这
    return {}

def count_messages(state) -> Literal[END, "to_summarize"]:
    return "to_summarize" if len(state["messages"]) > 5 else END

def summarize_conversation(state):
    trimmed = trim_messages(state["messages"], strategy="last",
                            start_on="human", end_on=("human", "ai"))
    keep_ids = {m.id for m in trimmed}
    to_summarize = [m for m in state["messages"]
                    if m.id not in keep_ids and m.type != "tool"]
    summary = llm.invoke([SUMMARY_PROMUP(to_summarize)])   # 压缩旧消息
    return {"summary": summary.content,
            "messages": [RemoveMessage(id=m.id) for m in old]}  # 删旧

graph.add_edge("generate_answer", "check_messages")        # 答完先汇集
graph.add_conditional_edges("check_messages", count_messages,
                            {"to_summarize": "summarize", END: END})
```

三个值得抄的细节：**空节点汇集**（两个分支汇到一个 passthrough
再做条件判断——条件边的映射是静态的，动态判断要有落点）；总结
时**剔除 tool 消息**（工具返回长且信息已进答案，压缩它纯属浪费
token）；**保留尾部完整轮**（`start_on="human"` 防止悬空返回）。

**会话持久化（checkpointer）**：短期记忆通常还要「重启不丢」——
每步状态落盘（SQLite/Postgres saver），按 thread_id 恢复会话。
LangGraph 的 `compile(checkpointer=...)` 一行接入；自己造系统时，
等价物是「每轮把 state 快照进 KV 存储，恢复时读回」。

## 12.3 长期记忆：五个代表系统的机制

跨会话记忆的分歧比短期大得多——五个代表系统，五种机制主张：

### ① generative agents：记忆流 + 三因子检索 + 反思（鼻祖）

斯坦福「AI 小镇」（[arXiv:2304.03442](
https://arxiv.org/abs/2304.03442)）把记忆建模为**观察流**：每条
观察是一个带时间戳的文本项，检索得分 = **recency（时近，指数
衰减）× importance（重要度，LLM 打 1–10 分）× relevance（与当前
情境的嵌入相似度）** 三因子乘积。两个原创机制沿用至今：**反思**
（定期把低层观察蒸馏成高层结论——「我注意到我常讨论物理」入库
成为新记忆）；**检索即打分**（不建复杂索引，分数即排序）。它存
自由文本——开放世界假设，也是后续所有系统要超越的起点。

### ② MemGPT：OS 式分页，模型自己管内存

MemGPT（[arXiv:2310.08560](https://arxiv.org/abs/2310.08560)，
→Letta）把上下文管理类比操作系统：**主上下文 = 寄存器/内存**
（system prompt + 少量工作消息），**外部上下文 = 磁盘**（全部
历史）；模型通过**自编辑函数**（self-editing）在两者间换页——
主动调用「把这段存进recall存储」「把那条检索回来」。主张：
LLM 能自己管理自己的内存层级。代价：管理动作本身占窗口且可能
出错；后续 DMR 基准上被 Zep 超越（94.8% vs 93.4%，见④）。

### ③ Mem0：两阶段「抽取-合并」管线（生产级代表）

Mem0（[arXiv:2504.19413](https://arxiv.org/abs/2504.19413)）把
长期记忆做成显式管线：**抽取阶段**（从对话轮提取候选事实）→
**合并阶段**（与已有记忆比对，LLM 在四个算子里裁决：
**ADD / UPDATE / DELETE / NOOP**）→ 存储（向量库；可选图存储
表达实体关系）。注意它与 generative agents 的根本分歧：记忆
不是「存下来等检索」，是**主动维护的知识库**——新信息可以更新、
作废旧信息（UPDATE/DELETE），不是只增不减。LOCOMO 基准实测：
比 OpenAI 的记忆方案相对提升 **26%**（LLM-as-judge），四类问题
（单跳/时序/多跳/开放域）全面领先；工程收益同样关键——p95
延迟比全历史方案低 **91%**、token 省 **90%+**。

### ④ Zep/Graphiti：时序知识图谱（时序主张）

Zep（[arXiv:2501.13956](https://arxiv.org/abs/2501.13956)）的
核心引擎 Graphiti 是**时间感知的知识图谱**：从对话与业务数据
同步抽取实体/关系/社区，但每条边带**生效时间与失效时间**
（valid_at / invalid_at）——「张三 2024 年在 A 部门」不会被
「2026 年调到 B 部门」覆盖，而是两条边并存，查询按时点取值。
这直接命中长期记忆最隐蔽的坑：**事实是会过期的，过期不是删除**。
实测：DMR 基准 94.8% 超越 MemGPT（93.4%）；更难的 LongMemEval
（跨会话综合、时序推理）准确率最高 **+18.5%**、延迟 **−90%**。

### ⑤ Anthropic memory tool：官方化一极（模型自管）

2025-08 起 Claude 提供原生 `memory` 工具（[文档](
https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)）：
模型自己调用 view/create/str_replace/insert/delete 读写**客户端
文件目录**（如 `./memory/`），跨会话由宿主应用挂载同一目录实现。
主张与 MemGPT 同族（模型自管），但形态是文件系统 + 权限边界
（目录可读写范围受控）。与自建写闸的对照：**「记什么」的判断权
在模型手里**——通用助手域这很高效；高错误代价域这是风险（见
12.4 公理二）。

### 评测基准一览（选型前先认基准）

| 基准 | 测什么 | 备注 |
|---|---|---|
| LOCOMO | 长对话多类型问答（单跳/时序/多跳/开放域）| Mem0 论文主战场，LLM-as-judge 为主指标 |
| LongMemEval | 跨会话信息综合、时序推理 | 更难、更贴企业场景；Zep 主推 |
| DMR（Deep Memory Retrieval）| 记忆检索准确率 | MemGPT 系自建基准，Zep 借用并超越 |

看数字时记两条：各家爱挑对自己有利的基准（谁家论文谁家赢的
现象在记忆领域尤其明显）；LLM-as-judge 指标自带裁判方差（第 13
章）——数字看趋势与量级，别当精确排名。

## 12.4 长期记忆的设计五问与三条公理

无论选哪个系统，落地都要回答五个问题：

1. **写什么**（写入策略）：全存（对话原文入库）是下策——污染面
   最大；存抽取事实（Mem0 式）是中策；**只存验证过的事实**是
   高错误代价域的上策（写闸，见案例）；
2. **怎么组织**（结构选择）：自由文本（检索靠嵌入）/ 结构化键值
   （寻址靠键）/ 知识图谱（查询靠关系+时序）。结构越强，治理
   手段越多，维护成本越高；
3. **怎么检索**：嵌入相似 / 键寻址 / 图遍历 / 三因子打分——
   检索方式要与组织方式配套；
4. **怎么写入**（写闸）：谁批准写入？追加还是合并（Mem0 四算子）？
   **append-only + supersede**（永不物理删除，旧版本留审计轨迹）
   是高代价域的标准答案；
5. **怎么失效**：有效期跟谁走？——跟**证据源**走（语料变了旧
   记忆作废）比跟时间走（TTL）更符合事实系统的语义；Zep 的
   valid_at/invalid_at 是同一思想的图谱版。

三条设计公理（全书反复引用）：

- **公理一：事实不可压缩，叙述才可压缩**——压缩一个数字等于
  捏造一个数字。12.2 的总结压缩的是叙述（合法）；把对话摘要当
  事实源是违反公理（非法）；
- **公理二：记忆是错误放大器**——写错一条，后续每轮都在读它。
  记忆的公信力 = **写入门槛 × 可审计**，不是「记性好」。通用
  助手写错偏好代价小；事实域写错数字是事故——写闸门槛按错误
  代价分级；
- **公理三：内容形态决定可信形态**——自由文本只能靠模型自觉，
  结构化键值可以靠代码校验。选了形态就选了治理手段。

配套专题：

**作用域与身份（记忆的权限面）**。LangChain 公司 harness 的实践
（第 1 章）：记忆分 **global / user 两层**，且与身份代行（OBO）
绑定——「这个用户喜欢简洁」是 user 层，「公司报销制度」是 global
层；写错作用域等于权限泄漏（A 的隐私进了全员共享记忆）。多用户
系统里，记忆的第一问除了「记什么」还有「**记到谁名下**」。

**Reflexion 为什么慎用**。把失败反馈转成语言自我反思存进情景
记忆（[arXiv:2303.11366](https://arxiv.org/abs/2303.11366)）：
通用域是增益；高代价域两个风险——反思是自由文本（非事实非
程序，污染形态纪律）；跨试次自我改进让「上次行为」影响「下次
输出」，若上次的错误与闸门相关，反思会**放大相关性错误**而
不是消除（第 14 章相关性警告）。

**记忆系统的评测隔离**。评测反复跑同批题，记忆把上轮答案记住
——检索指标虚高（测的是命中不是检索）。评测默认隔离记忆、
对照实验显式开闸，是记忆评测的铁纪律（第 13 章假绿之二）。

## 12.5 案例研究：Tally 的三层记忆

!!! note "案例研究：Tally（memory.py / graph.py，v0.7）"

    Tally 的三层是 12.3 谱系在**封闭世界约束**下的投影——每层
    回答一个「凭什么信」：

    | 层 | 映射类型学 | 是什么 | 凭什么信 |
    |---|---|---|---|
    | L0 会话 | episodic（短期）| 近 3 轮全量 + 更早压缩为**结构化轮摘要** | **永不继承自由文本**——只继承理解字段（公司/期间/年份）与指标词 |
    | L1 台账 | semantic | `verified_facts` 表，(公司,期间,指标,口径) 四元键 | 写闸严于读闸 + 读不豁免 |
    | L2 资产 | procedural | alias 词典等检索导航知识（≤2KB）| 人工维护 + eval 全绿才晋升 |

    **L0 的继承纪律**（公理一落地）：多轮对话里上一轮的**叙述**
    （可能带错误措辞）绝不流入下一轮——只继承结构化字段。裸追问
    （「呢/它」）带任何数据信号时，从继承字段救援意图而不是让
    自由文本污染理解。

    **L1 写闸**（`graph.py: _memory_write`，代码逐行）：

    ```python
    # tally/graph.py: _memory_write（写闸节选）
    tr = "→".join(state.get("trace") or [])
    if any(bad in tr for bad in ("caliber-mismatch", "fallback(",
                                 "no-evidence", "derived-mismatch")):
        return []      # 口径闸触发过的一律不写：数字闸保「在场」，
                       # 写闸要的是「行也对」
    ```

    写入条件 = verify:pass ∧ 口径闸未触发 ∧ 非台账命中。合并用
    **五算子**（与 Mem0 四算子同构，多一个语义化命名）：
    `noop / insert / conflict / restated / reingest`——比较
    value_std（数值标准化）裁决，**append-only supersede**（旧
    版本不物理删除，`vf_live` 部分索引只索引活行，死行留审计）。

    **L1 读不豁免**（`memory_probe` 命中后仍走全闸）——缓存证据，
    不缓存结论。投毒测试钉死这条性质：

    ```python
    # tests/test_v07.py: test_poisoned_fact_read_not_exempt（思想）
    # 绕过写闸直接 SQL 注入假事实 9,999,999,999.99
    # → 读路径命中它 → 出口 verify 对账证据池
    # → 假事实无真证据支撑 → 答案 degraded/拒答，假数出不了门
    ```

    **失效跟语料指纹走**：probe 时校验指纹，语料漂移自动
    supersede reingest——证据源变了旧账不作数（12.4 第 5 问的
    Tally 答案）。业绩预告类文档（E 后缀期间）是区间值非单值，
    解析不出单值不落账——保守失败，正确行为。

    **实测（反直觉的一课）**：eval 放开记忆后台账命中题的
    answer_hit **不变**——命中的是同一个已过闸事实，读不豁免、
    照样过 verify。**指标不变正是读不豁免的设计结果**；记忆的
    可见差异在 trace（`memory:hit`）、coverage 分布与延迟，不在
    对错。

    与业界默认的分歧：不给模型记忆写权（对照 Anthropic memory
    tool 的模型自管）——理由是公理二：财报域写错一个数字，
    后续每一轮都在读它。

!!! example "迁移盒：客服助手的记忆该记什么"

    - **语料差异**：客服域的「事实」是工单结论、用户偏好、承诺

      小（低门槛可写、嵌入检索即可，Mem0 式管线够用）；承诺记错
      代价大（必须过闸：工单号在场、原文在场才可写，Tally 式

      变的是 L1 的键（用户+日期+事项+状态）与分级门槛。**记忆
      设计第一问永远是：这条记错了，代价是什么？**（画布第 12 格）

## 12.7 小结

- 记忆是必答题：窗口固定、跨会话失忆、成本三重限制；结构化
  记忆比全历史塞 prompt 又准又便宜（p95 −91%、token −90%）；
- 短期记忆 = 窗口管理三方式（删除/修剪/总结）+ checkpointer
  持久化；总结的标准形态是阈值触发的条件总结（空节点汇集 +
  剔除工具消息 + 保留完整轮）；
- 长期记忆五系统五主张：三因子记忆流、OS 分页自管、抽取-合并
  管线（四算子）、时序知识图谱（过期不是删除）、官方 memory
  tool（模型自管）；基准看量级不看排名；
- 设计五问（写什么/组织/检索/写入/失效）+ 三公理（事实不可
  压缩/错误放大器/形态决定治理）+ 作用域身份；
- 案例 Tally：三层各答一个凭什么信，写闸五算子 + 读不豁免 +
  指纹失效——封闭世界的记忆版。

## 常见误区

**误区一：「记忆 = 把对话存进向量库」。**对话向量库检索出的
「相关历史」是自由文本——带上文的错误措辞与过期上下文注入新
问题，是新增一条传播边（违反公理一），且没有失效机制（第 5 问
不答）。

**误区二：「上下文窗口够大就不需要记忆了」。**窗口大只解决
「装得下」，不解决跨会话（换窗口即失忆）、成本（Mem0 的 90%
token 账）与时效（过期事实该作废而不是还躺在 prompt 里）。

**误区三：「记忆越多越好」。**每条记忆都是潜在污染源。写闸 +
读闸 + 失效三件套之下，记忆只会加速不会污染——加速器要有
断电开关。

**误区四：「记忆命中就不用再验证了」。**缓存结论是写闸的漏洞
放大器：写闸通过≠永远为真。读不豁免让记忆只省检索成本，不省
验证成本。
