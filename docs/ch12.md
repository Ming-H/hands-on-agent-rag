## 12.1 失败先行：装饰性 CI 的解剖

这个项目自己踩过的坑（2026-10 复盘）：CI 里跑了三个真值集 eval，
看起来很严格——直到有人问「指标跌到 0.3，CI 会红吗？」答案是不会：
`cmd_eval` 只打印，**永远 exit 0**。CI 从「只防崩溃」到「防退化」
之间，差一个非零退出码。

```python
# tally/cli.py: cmd_eval（修复后节选）
mins = dict(min_retrieval=args.min_retrieval, min_hit=args.min_hit,
            min_refusal=args.min_refusal)
if any(v is not None for v in mins.values()):
    fails = gate_failures(summary, **mins)
    if fails:
        print(f"✗ eval 门槛未过（dataset={args.dataset}）：\n  " + "\n  ".join(fails),
              file=sys.stderr)
        sys.exit(1)
```

`.github/workflows/ci.yml` 四处 eval 全部挂上 `--min-retrieval 1.0
--min-hit 1.0`。这个门槛通电当天就抓到一次真实回归（下节的 0.963）。

## 12.2 judge 的演进史：一学期踩完的坑

**v1：OR 子串。** `any(k in answer for k in expect_keywords)`——
关键词 `"3.6"` 能以子串命中答案里的任何 `13.68`、`3.68`、页码日期。
评测在说谎。

**v2：左右都禁数字粘连。** 想堵假命中，把关键词前后是数字/逗号/
小数点的都禁了——innolight 掉到 **0.963**，门槛当场红了。定位：
关键词 `51.7`，答案 `51.71 亿元`——**数据集的关键词约定是前缀截断**
（`38,239` 对 `38,239,935,640`），右边界一禁误杀过半真值题。

**v3（现状）：只守左边界。** 假命中实测全在左侧粘连（`3.6` 撞
`13.68`、`36,000` 撞 `136,000`）；右侧延续恰是截断约定：

```python
# tally/evalx.py: _kw_in
if re.search(r"\d", kw):
    return re.search(rf"(?<!\d){re.escape(kw)}", answer) is not None
return kw in answer
```

这条演进的教学价值超过规则本身：**没有门槛的评测，你连自己的
量尺坏了都不知道。**

## 12.3 评测集设计的四个要素

`evals/*.json` 七个数据集、84 题，值得抄的设计：

1. **真值纪律**：关键词是人工核对到分位的原文数字（与年报分季度表
   交叉验证），不是「大概对的数」；
2. **陷阱题**（`expect_refused`）：期间外（2030）、域外（天气）、
   语义陷阱（「预计…多少」不是趋势）——**拒答正确率是一等指标**；
3. **反向断言**（`forbid_keywords`）：第 9 章的口径负向断言；
4. **N/A 的诚实**：无陷阱题的数据集 refusal 记 None（打印 N/A），
   不打 0.0——「不适用」和「零分」是两回事。

指标口径也要名实相符：`faithfulness` 改名 `citation_coverage`
（它测的是引用对账，不是语义忠实度——名字吹的牛会被面试官拆穿）。

## 12.4 动手实验：门槛通电

```bash
# 亲手触发一次 CI 红灯（然后还原）
python - <<'EOF'
from pathlib import Path
p = Path("evals/dataset.json"); s = p.read_text()
p.write_text(s.replace('"36,000"', '"36,00X"', 1))   # 改坏一个真值
EOF
python -m tally.cli eval --min-hit 1.0; echo "exit=$?"
# 预期：✗ eval 门槛未过 … exit=1
git checkout evals/dataset.json
```
