## 12.1 知识：记忆类型学——先分类，再选系统

讨论 agent 记忆前先分类。认知科学/工程界通用的四分：

| 类型 | 是什么 | agent 里的对应物 | 生命周期 |
|---|---|---|---|
| working（工作记忆）| 当前上下文窗口内的一切 | prompt + 检索结果 | 单次调用 |
| episodic（情景）| 具体交互的历史 | 会话摘要、过往轨迹 | 会话/跨会话 |
| semantic（语义）| 事实与知识 | 事实库、知识图谱 | 长期，需失效机制 |
| procedural（程序）| 「怎么做」的技能 | 指令模板、工具偏好、工作流 | 长期，人工或评测晋升 |

这个分类是设计工具：**先问「这条记忆是哪类」，再问「哪站系统
的机制适合它」**。谱系五站：

| 站 | 系统 | 核心思想 |
|---|---|---|
| ① | generative agents（[arXiv:2304.03442](https://arxiv.org/abs/2304.03442)）| 记忆流按 recency × importance × relevance 检索 + 反思蒸馏 |
| ② | [MemGPT](https://arxiv.org/abs/2310.08560)（→Letta）| OS 式分页，LLM 自管理上下文层级 |
| ③ | [Mem0](https://mem0.ai) / [Zep](https://www.getzep.com) | 抽取-合并的事实记忆 / 时序知识图谱 |
| ④ | LangGraph memory | semantic/episodic/procedural 三分 store |
| ⑤ | [Anthropic memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)（2025-08）| 模型自己调 memory 工具读写客户端目录 |

⑤代表了「记忆官方化」的一极：**「记什么」交给模型判断**。生产
侧的补充视角来自 LangChain 的公司 harness 实践：记忆分
**global / user 两层作用域**，且与身份代行绑定——哪些事实是
「这个用户的」，哪些是「公司级的」，写错作用域等于权限泄漏。

**Reflexion**（[arXiv:2303.11366](https://arxiv.org/abs/2303.11366)）
是值得点名「慎用」的一站：把失败反馈转成语言自我反思存进情景
记忆、下轮更好。两个风险：反思是自由文本（非事实非程序，污染
两类记忆的形态纪律）；跨试次自我改进让「上次行为」影响「下次
输出」——如果上次的错误与闸门有相关性，反思会把相关错误放大
而不是消除。通用域它是增益，高错误代价域慎收。

## 12.2 知识：三条设计公理与三策略

**公理一：事实不可压缩，叙述才可压缩。**把对话摘要当事实源，
等于用一个有损压缩器生产事实——压缩一个数字等于捏造一个数字。
可压缩的是叙述（轮摘要、经历描述），不可压缩的是事实（结构化
键值、带出处的数字）。

**公理二：记忆是错误放大器。**写错一条，后续每一轮都在读它、
每一次对账都失败——记忆的公信力 = **写入门槛 × 可审计**，不是
「记性好」。错误代价决定门槛：通用助手写错一条偏好代价小，
事实域写错一个数字是事故。

**公理三：内容形态决定可信形态。**自由文本的记忆只能靠模型
自觉；结构化键值的记忆可以靠代码校验。选了内容形态，就选了
能用的治理手段。

三策略（任何记忆系统的三个必答题）：

1. **写闸**：什么才有资格写入？——高错误代价域的答案：已验证的
   结构化事实（出处在场、校验通过），append-only + 版本取代
   （永不物理删除，保留审计轨迹），且**写闸严于读闸**；
2. **读闸**：读到的就能信吗？——**读不豁免**：命中的记忆拼出的
   答案照样过出口验证（缓存证据，不缓存结论）。没有读闸，写闸
   只是拖延污染；
3. **失效**：记忆的有效期跟着谁走？——高错误代价域的答案：跟着
   证据源（语料/上游变了，旧记忆作废或降级待重验）。没有失效
   机制的记忆是只涨不落的湖。

配套的评测纪律：**评测默认隔离记忆**——同一批题反复跑，记忆把
上轮答案记住了，检索指标测的是记忆命中不是检索能力（一种典型
假绿，第 13 章）。对照实验必须显式开闸。

## 12.3 案例研究：Tally 的 L0/L1/L2

!!! note "案例研究：Tally（memory.py / graph.py）"

    三层映射到 12.1 类型学：**L0 会话**（episodic——近 3 轮全量、
    更早压缩为结构化轮摘要；**永不继承自由文本**，只继承理解字段
    与指标词——公理一的落地，剪断叙述传播边）；**L1 台账**
    （semantic——`verified_facts` 表按 (公司,期间,指标,口径) 四元
    键寻址，五算子合并 noop/insert/conflict/restated/reingest，
    append-only supersede）；**L2 资产**（procedural——alias 词典
    等检索导航知识，人工维护 + eval 全绿才晋升，≤2KB 纪律）。

    **写闸**代码一行看清严于读闸：trace 里出现过 caliber-mismatch/
    fallback/no-evidence/derived-mismatch 的**一律不写**——数字
    闸保「在场」，写闸要「行也对」。**读不豁免**有测试钉死：
    往台账 SQL 注入一条假事实（9,999,999,999.99）→ 读路径命中 →
    出口对账拦下 → 假事实出不了门（投毒测试）。**失效**跟语料
    指纹：probe 时校验，指纹漂移自动 supersede reingest。

    **实测反直觉**（作者亲踩后写对）：eval 放开记忆后，台账命中
    的题 answer_hit **不变**——命中的是同一个已过闸事实，读不
    豁免、照样过 verify。**指标不变正是读不豁免的设计结果**；
    记忆的可见差异在 trace（memory:hit）与延迟，不在对错。

!!! example "迁移盒：客服助手的记忆该记什么"

    - **语料差异**：客服域的「事实」是工单结论、用户偏好、承诺
      记录（「说好补偿 50 元券」）——三类错误代价完全不同。
    - **哪个决策因此改变**：公理二按代价分级写闸——偏好记错代价
      小（低门槛可写、可模糊检索）；承诺记错代价大（必须过闸：
      工单号在场、原文在场才可写）。作用域分层（user/global）：
      偏好是 user 层，服务承诺是 global 层。
    - **Tally 哪个机制对应**：三层骨架与「写闸严于读闸」原样；
      变的是 L1 的键（用户+日期+事项+状态）与分级门槛。记忆设计
      第一问永远是：**这条记错了，代价是什么？**（画布第 12 格）

## 12.5 小结

- 类型学四分（working/episodic/semantic/procedural）先于系统选型；
  谱系五站各取一瓢；「记什么交给模型」是官方化一极，高代价域
  慎用；
- 三公理：事实不可压缩；记忆是错误放大器（公信力=写入门槛×
  可审计）；内容形态决定可信形态；
- 三策略：写闸严于读闸、读不豁免（缓存证据不缓存结论）、失效
  跟证据源走；
- 作用域与身份（user/global + 代行）是记忆的权限面，写错作用域
  等于泄漏；
- 评测默认隔离记忆，对照实验显式开闸。

## 常见误区

**误区一：「记忆 = 把对话存进向量库」。**对话向量库检索出的
「相关历史」是自由文本——带着上文的错误措辞与过期上下文注入
新问题，是新增一条传播边（违反公理一）。

**误区二：「记忆越多越好」。**每条记忆都是潜在污染源。写闸 +
读闸 + 失效三件套之下，记忆只会加速不会污染——加速器要有
断电开关。

**误区三：「记忆命中就不用再验证了」。**那正是「缓存结论」——
写闸通过≠永远为真（语料会变）。读不豁免让记忆只省检索成本，
不省验证成本。
