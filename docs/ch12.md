## 12.1 失败先行：记忆是错误放大器

给 RAG 加记忆，最常见的翻车不是「记不住」，是**记错了以后每一轮
都在读它**：

| 死法 | 过程 | 代价形态 |
|---|---|---|
| 对话向量库传播 | 上轮的错误措辞被检索进新问题 | 叙述错误跨轮复利 |
| 脏写入门槛 | 一次降级答案的数字进了长期记忆 | 每次命中都错，且错得有引用 |
| 旧账不失效 | 语料更新后旧事实还在被命中 | 答案对不上当前原文 |

结论先立：**记忆的公信力 = 写入门槛 × 可审计**，不是「记性好」。
通用助手域写错一条偏好（「用户喜欢简洁」）代价小；事实域写错一个
数字，后续每一轮都在读它、每一次对账都失败——同样的记忆架构，
错误代价差一个数量级。Tally 的六条设计公理（DESIGN-v0.7 §7.1）
里最锋利的一条就是：**记忆是错误放大器**。

## 12.2 知识点：记忆谱系五讲

2023–2025 的记忆系统演进，五站看全：

| 站 | 系统 | 核心思想 | Tally 取什么 / 不取什么 |
|---|---|---|---|
| ① | generative agents（斯坦福小镇，[arXiv:2304.03442](https://arxiv.org/abs/2304.03442)）| memory stream 按 recency × importance × relevance 检索，reflection 蒸馏 | L0 轮摘要的近亲；分野在内容形态——小镇存自由文本，L0 只继承结构化字段 |
| ② | [MemGPT](https://arxiv.org/abs/2310.08560)（→ Letta）| OS 式内存分页，LLM 自管理上下文 | 分层思想（热/冷）；不取「模型自己管自己」 |
| ③ | [Mem0](https://mem0.ai) / [Zep](https://www.getzep.com) | 抽取-合并的事实记忆 / 时序知识图谱 | 事实级合并算子；时效意识（指纹失效）|
| ④ | LangGraph memory（2024–25）| semantic / episodic / procedural 三分 + BaseStore | L1/L0/L2 几乎同名同置；分野在写闸——通用 store 谁都能写 |
| ⑤ | Anthropic memory tool（2025-08，[文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)）| 模型自己调 memory 工具读写客户端目录 | 官方化代表；Tally 把「记什么」交给确定性写闸而非模型判断 |

**Reflexion（[arXiv:2303.11366](https://arxiv.org/abs/2303.11366)）
——Tally 明确不收的一段**：把失败反馈转成语言自我反思、存进情景
记忆、下轮更好（verbal RL）。不收的理由：①反思是自由文本——既非
事实也非导航知识，违反内容纪律；②跨试次自我改进 = 让上次行为影响
下次输出，这是**相关性风险**——闸门防的恰恰是系统性相关错误
（第 14 章相关性警告）。「不学上次为什么错」在通用域是损失，在
封闭世界是安全设计。

五站连起来读，每个系统对「记什么」给出不同答案，而 Tally 的答案
由一条公理决定：**事实不可压缩，叙述才可压缩**——压缩一个数字
等于捏造一个数字。**内容形态决定可信形态**：自由文本的记忆只能
靠模型自觉，结构化键值的记忆可以靠代码校验。

## 12.3 本项目：L0/L1/L2——每层回答一个「凭什么信」

| 层 | 是什么 | 凭什么信 |
|---|---|---|
| L0 会话 | 轮摘要继承（公司/期间/年份/指标词） | **永不继承自由文本**——只继承结构化理解字段，切断叙述传播边 |
| L1 台账 | verified_facts 表（公司+期间+指标+口径 四元键） | **写闸严于读闸；读不豁免** |
| L2 资产 | alias 词典等检索导航知识 | 人工维护 + eval 全绿才晋升；非答案事实 |



L1 的写闸值得逐行读：

```python
# tally/graph.py: _memory_write（写闸节选）
tr = "→".join(state.get("trace") or [])
if any(bad in tr for bad in ("caliber-mismatch", "fallback(",
                             "no-evidence", "derived-mismatch")):
    return []          # 口径闸触发过的一律不写——D22 闸保「数字在场」，
                       # 写闸要的是「行也对」
```

**写闸** = verify:pass ∧ 口径闸未触发 ∧ 非台账命中——只有最干净的
结构化事实进长期记忆（五算子：noop/insert/conflict/restated/
reingest，append-only supersede，value_std 比对；**永不物理删除**，
死行留存审计轨迹）。

**读不豁免**更关键——memory_probe 命中拼出的答案**照样内联过
verify**（缓存证据不缓存结论）：

```python
# tests/test_v07.py: test_poisoned_fact_read_not_exempt（思想）
# 往台账写一条假事实（跳过写闸直接 SQL 注入）
# → 读路径命中它 → verify 对账证据池 → 假事实没有真证据支撑
# → 答案 degraded/拒答，假事实出不了门
```

**记忆是加速器，不是后门**——这条性质由投毒测试钉死。失效机制：
语料指纹漂移 → probe 时校验 → 自动 supersede reingest——语料变了，
旧事实不作数，记忆的生命周期跟着证据走。

L0 的「永不继承自由文本」也值得咀嚼：多轮对话里上一轮的**叙述**
（可能带着错误措辞）绝不流入下一轮——只继承 understanding 字段
与指标词（结构化、可校验）。叙述的传播边被剪断（第 14 章公理的
杠杆三：结构化传递 = 字段复制，不文本重释）。

## 12.4 本项目：eval 默认隔离——防记忆虚高

评测记忆系统时最容易得到的**假绿**：eval 反复跑同一批题，L1 台账
把上一轮的答案记住了——retrieval 指标全满，测的是记忆命中不是检索
能力。Tally 的对策：**evalx 默认强制隔离台账**（`TALLY_EVAL_MEMORY`
显式 `on` 才放开）。做记忆对照实验时必须知道这个开关，否则对照组
根本没分开（作者亲踩后才写对——12.5 实验②的实测）。

## 12.5 动手实验（实测修正版）

```bash
bash experiments/ch12-memory-toggle.sh
# 输出实录（2026-10-22）：
#   == ① 常态 ask：L1 台账在工作 ==
#   memory:hit
#   == ② eval 默认隔离 vs 放开（TALLY_EVAL_MEMORY=on）==
#   answer_hit 两次都是 1.0（不变），citation_coverage 0.941→0.736
#   == ③ 记忆总闸关 ==
#   （无 memory 标记——台账已关）
#   == ④ 投毒复现（幕二）==
#   假事实写入台账 → 读命中 → verify 拦 → 出不了门
```

**②的反直觉结果是本章最重要的一课**：放开记忆后台账命中
**answer_hit 不变**——命中的是同一个已过闸事实，读不豁免、照样过
verify——**指标不变正是「读不豁免」的设计结果**。记忆的可见差异
在 trace（`memory:hit`）、coverage 分布与延迟，不在答案对错。

!!! example "迁移盒：客服助手的记忆该记什么"

    - **语料差异**：客服域的「事实」不是财报数字，是工单结论、
      用户偏好、承诺记录（「上周说好补偿 50 元券」）。
    - **哪个决策因此改变**：错误代价分级变了——偏好记错代价小
      （可以低门槛写、embedding 检索），承诺记错代价大（必须
      过闸：引用工单号、原文在场才可写）。L0/L1/L2 骨架不变，
      **写闸按错误代价重新分级**。
    - **Tally 哪个机制对应**：三层结构与「写闸严于读闸」原则原样；
      变的是什么进 L1——「承诺类」进台账（四元键换成 用户+日期+
      事项+状态），「偏好类」降级进 L2 导航资产。**记忆设计的第一
      问永远是：这条记错了，代价是什么？**

## 12.6 小结

- 谱系五讲 + 一段不收（Reflexion）：Tally 的分野在写闸与内容形态；
- 两条公理：事实不可压缩；记忆是错误放大器——公信力 = 写入门槛
  × 可审计；
- 三层各答一个凭什么信：L0 不继承自由文本、L1 写闸严于读闸 +
  读不豁免、L2 人工维护；
- 投毒测试是记忆安全性的形态证明；指纹失效让记忆生命周期跟着
  证据走；
- eval 默认隔离台账：防检索指标虚高——对照实验要开
  `TALLY_EVAL_MEMORY`。

## 常见误区

**误区一：「记忆 = 把对话存进向量库」。**对话向量库检索出的
「相关历史」是**自由文本**——它带着上文的错误措辞、过期的上下文、
无关的枝节，注入新问题是新增一条传播边。Tally 的 L1 只存
**结构化、已过闸**的事实（四元键寻址），L0 只继承 understanding
字段——记忆的内容形态决定了它的可信形态。

**误区二：「记忆越多越好」。**每一条记忆都是潜在的污染源。
Tally 的取舍：写闸严于读闸（不干净的不进来）、读不豁免（进来
的照样过 verify）、指纹失效（语料变了旧账作废）。三条规则下，
记忆只会加速、不会污染——加速器要有断电开关。
