# 前言：为什么写这本书

## 一句话

市面上教「怎么把 RAG 跑起来」的教程已经太多；这本书教的是
**「怎么让 RAG 不敢编造」**——以一个真实开源项目
（[Tally](https://github.com/Ming-H/tally)）为唯一载体，从 PDF 语料
一路走到 Agent 四支柱与评测体系。

## 本书的来历

Tally 不是为教学准备的玩具：它是一个人在 2026 年 10 月里、踩着
26 个实测决策（D1–D26）、3 次事故复盘和 40 道人工核对真值题长出来的
财报问答系统。本书做的事是给这个「结果」补一条「过程」的缓坡——
每章先让你看一次失败，再讲为什么这样修。**失败先行**不是教学技巧，
是这个项目真实的成长方式。

## 怎么读

| 你是谁 | 路径 |
|---|---|
| 按部就班 | ch1→ch13 顺序读，每章实验跟着做 |
| 做过 RAG、查漏补缺 | 第二部（ch6–9 求证闸门）直奔主题，回头补第三部 |
| 面试冲刺 | ch1 / ch5 / ch8 / ch13 四张牌 + 附录 D 决策索引 |

体例说明：

- **五段式**：失败先行 → 业界视角 → 决策与备选 → 代码精讲 → 动手实验；
- **D 编号**（D1–D26）：Tally 设计文档的决策记录编号，正文引用处
  可溯源到 `docs/DESIGN-*.md` 原文；
- **破坏性实验**：每个设计决策都让你亲手拆一次、看指标变坏、装回去；
- 代码只贴关键片段（`文件名 + 函数名` 锚定），完整代码以 Tally
  仓库为准，**锁定 v0.7+ tag**——代码会演进，本书引用以函数名为锚。

## 诚实边界

- 本书全部实测数字来自 Tally v0.7（2026-10）；标 ★ 的实验在作者机
  验证过，其余按脚本可复现（`experiments/`）；
- Tally 有它管不住的问题（ch13 边界账本）——本书不装完美；
- 远端 API 通道的 ReAct 工具环尚未接通（ch10 详述）——这是留给
  读者的 v1.1 挑战，不是被藏起来的缺陷。

祝你拆得开心。

—— Ming-H，2026-10
