## 3.2 业界视角：切分方法全景

!!! note "背景速览"

    切分（chunking）是 RAG 里被讨论最多的低层决策，业界谱系：

    | 方法 | 代表实现 | 思路 | 软肋 |
    |---|---|---|---|
    | 固定长度 | 朴素 token 切分 | 简单、可并行 | 拦腰斩断语义单元 |
    | 递归分隔 | [LangChain RecursiveCharacterTextSplitter](https://python.langchain.com/docs/how_to/recursive_text_splitter/) | 段落→句子→字符逐级回退 | 仍不识表格结构 |
    | 句子/语义窗口 | [LlamaIndex SentenceSplitter](https://docs.llamaindex.ai)、语义分块（Kamradt） | 按句/按嵌入相似度断点 | 表格行≠句子 |
    | 版面感知 | [Unstructured chunk_by_title](https://unstructured.io) | 按标题/布局聚块 | 依赖上游版面分析 |
    | 命题级 | Dense X Retrieval | 一句一命题 | 块数爆炸、丢上下文 |
    | 迟到切分 | Late Chunking（[arXiv:2409.04701](https://arxiv.org/abs/2409.04701)） | 先嵌入整文再切 | 需长上下文嵌入模型 |

    经验参数：主流实践落在 256–1024 token、overlap 10–20%——但这些
    数字全部来自**叙事文本**的直觉。**财报是表格型文档**：42% 的
    内容住在表格里，而表格行的语义单位是「行」（标签+数值+同比），
    不是 512 个字符。选切分方法的第一问永远是：**这个语料的语义
    单元是什么？**

## 3.3 为什么：毁证据的三种死法

```
营业收入 520,053,589.94  345,593,109.95  50.48%
```

固定 512 字符边界切这行的三种死法：指标名与数值分家（销毁证据）；
同行三数分进两块（本期与同比分离）；切在千分位逗号后（`520,` 和
`053,589.94` 各自不可读）。Tally 全库实测：**42.1% 的块是完整表格
块**——毁掉它们，检索层再好也答不对。

## 3.4 决策：逐行分类聚簇（6 行启发式）

三个备选的取舍：①固定长度（毁表格）；②语义模型切分（贵、慢、
不可控——切分是离线高频操作）；③逐行分类聚簇（本文）。核心是
**表格行判定**（数字密集 + 无句末标点 + 短行），连续表格行聚成
**原子块永不跨切**；配套 `keep_block` 过滤纯列头块（「项目 2026年
半年度」——无数字的列头是检索噪声）；正文按段落边界切 ~420 字。

还有一个容易被忽略的细节：**数字归一化注释**：

```python
_NUM_RE = re.compile(r"([1-9]\d{0,2}(?:,\d{3})+(?:\.\d+)?)\s*(亿元|万元|元)")
# 41,914.72 万元 → ≈4.19亿（纯程序换算，零幻觉；每块至多 6 条防噪）
```

用户问「多少亿」、原文写「41,914.72 万元」——词面零重叠。注释在
下游打分加权（answer.py 的 1.4×/0.2 权重）接上亿级问法。它是**程序
换算的字符串**，不是 embedding——各司其职。

## 3.5 已知边界：这门课不装完美

超长表格（>840 字）切块后**后块丢表头**——列头在第一块，后几块是
裸数字行，命中后模型读不懂「第三列是什么」。这个坑 Tally 知道、
没修、写进了边界账本（第 13 章）。教学点：**工程教程最值钱的
部分是「知道哪里没修好」**。

## 3.6 动手实验（还原后）

```bash
  FROM chunks WHERE doc_id='海伦哲_2026Q1' AND is_table=1 LIMIT 5"
# chunk_id 连号（p3#4、p3#5…）= 同一表格的连续行聚簇

```
