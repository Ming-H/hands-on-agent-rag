## 3.2 为什么：财报 42% 的事实住在表格里

通用 RAG 教程的标准动作是「固定 512 字符切分」。对财报这是灾难：

```
营业收入 520,053,589.94  345,593,109.95  50.48%
```

这一行被 512 边界拦腰斩断的三种死法：指标名与数值分家（销毁证据）；
同行三个数字被分进两个 chunk（同比与本期分离）；切在千分位逗号后
（`520,` 和 `053,589.94`，两个 chunk 各自不可读）。Tally 全库实测：
**42.1% 的块是完整表格块**——毁掉它们，检索层再好也答不对。

## 3.3 决策：逐行分类聚簇（6 行启发式）

三个备选的取舍：①固定长度切分（通用但毁表格）；②语义模型切分
（贵、慢、不可控——切分是离线高频操作）；③逐行分类聚簇（本文）。

```python
# tally/ingest.py（示意节选）
def _is_table_line(s: str) -> bool:
    # 数字密集、无句末标点、短行 → 表格行；连续表格行聚成原子块，永不跨切
    ...
# keep_block：纯列头块（「项目 2026年半年度 2025年半年度」）过滤——
# 无数字的列头对检索是噪声，还会挤掉真值块
```

配套两条：正文按段落边界切 ~420 字；逐页处理让页边界天然保护跨页
大表。判定规则总共 6 行，零模型零成本——**能用规则解决的事，
不要动用模型**。

还有一个容易忽略的细节：**数字归一化注释**（`normalize_numbers`）。

```python
_NUM_RE = re.compile(r"([1-9]\d{0,2}(?:,\d{3})+(?:\.\d+)?)\s*(亿元|万元|元)")
# 41,914.72 万元 → ≈4.19亿（纯程序换算，零幻觉；每块至多 6 条防噪）
```

用户问「多少亿」，原文写「41,914.72 万元」——词面零重叠。归一化
注释让检索打分和抽取式答案都能接上「亿」的问法。注意它是**换算的
注释字符串**，不是 embedding，也不进 FTS 索引——它在下游打分里
加权（answer.py 的 1.4×/0.2 权重），各司其职。

## 3.4 已知边界：这门课不装完美

超长表格（>840 字）切块后，**后块丢表头**——列头在第一块，后几块
是无列名的裸数字行，检索命中后模型无法解读「第三列是什么」。这个
坑 Tally 知道、没修、写进了边界账本（第 13 章再会）。教学点：
**工程教程最值钱的部分是「知道哪里没修好」**。
