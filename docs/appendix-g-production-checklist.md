# 附录 G 从原型到生产：检查清单

> 本书止于「能证明、能迁移」的原型（CLI + eval + CI）。把这样一
> 个原型送上生产，是另一门课的全部内容——本清单只**点名**不展开，
> 每条给你「不做的后果」，让你知道自己欠了什么账。三节：服务化 /
> 监控 / 成本。

## G.1 服务化

- [ ] **API 化**：CLI 包一层 HTTP 服务（FastAPI/Flask）——不做的
      后果：没有用户，只有你自己的终端；
- [ ] **并发模型**：SQLite 单写者（ch04）——读多写少可只读副本分
      连接；写并发要排队（单写队列）或换库。不做的后果：`database
      is locked` 在第二个并发请求到达时出现；
- [ ] **摄取与查询分离**：ingest 走离线 worker（`--watch` 或定时），
      ask 走在线服务——共享一个库文件时锁竞争是必答题；
- [ ] **超时与降级链**：每个 LLM 调用带超时（ch08 的 60s+1 次重试
      是底线）；服务层入口超时后**返回三态里的 refused 而非 500**——
      失败形态也是接口（ch14）；
- [ ] **密钥与配置**：.env 不出机器；生产用密钥管理服务轮换——
      ch08 的密钥纪律是个人版，不是生产版；
- [ ] **幂等与重入**：部署脚本、索引迁移全部可重入（ch02/ch04 的
      幂等纪律直接平移）。

## G.2 监控

- [ ] **verdict 分布看趋势**：pass/degraded/refused 占比的日曲线——
      degraded 升高 = 生成层或检索层在退化（ch13 §13.3 的线上漂移
      三件之一）；
- [ ] **waste_rate 看趋势**：agent 环在变懒（dup 升）或变笨（empty
      升）——它是 eₖ 的线上代理（ch11/ch14）；
- [ ] **问句日志抽样回放**：每周抽真实问句进 eval 真值集——分布
      漂移的唯一可靠探测器（离线满分 ≠ 线上正确）；
- [ ] **延迟分位**：p50/p95/p99 分节点报（understand/检索/生成/
      verify 各一段）——ch08 的尾延迟实测在服务化后放大；
- [ ] **事故入账**：每次线上错答进边界账本 + 补一道 eval 题——
      ch13 的事故→D 记录→永久测试链条在线上继续跑。

## G.3 成本

- [ ] **调用账本**：每问的 LLM 调用次数（heuristic 0 次 / llm 单跳
      1–2 次 / agent 环 5–10 次）× 单价——没有账本的系统不知道
      自己多贵；
- [ ] **分级路由省钱**：便宜问题走便宜路径——规则能路由的不进
      agent 环（ch09 的判定线就是成本线）；
- [ ] **缓存分层**：幂等缓存（ch11）之外加结果缓存（同问同答）——
      注意失效条件要跟语料指纹（ch12）走，否则缓存变成记忆投毒面；
- [ ] **嵌入/索引成本**：全库嵌入是离线一次性成本 + 增量成本——
      ch05 的向量轨默认关，一半理由就是这笔账；
- [ ] **预算熔断**：单问/单日预算上限，超限降级 heuristic——
      「烧钱失控」也是一种拒绝服务。

## 一句收束

这份清单上每一条都是一门独立的课。本书教的是**闸门与评测的方法论**
——它们才是这份清单上所有条目的共同底座：没有三态出口，服务化
只是把错误更快地发给更多人；没有 eval，监控只是在看数字变化。
